# 口径补丁 v1.3（最终收敛）

> 2026-11-14 ｜ 优先级：**高于 02 / 02b / 02c**  
> 触发：加班工时与加班费被混为一谈、阈值参与计算造成激励漏洞、快照缺算法版本

## S1 加班：工时与费彻底分层（替换 02b P9、02 的 12.1 双条件写法）

### 错误写法

`employment_nature=自有全职 AND payroll_category=FT` 作为「要不要算加班」的开关。
后果：派遣/外包人员的**加班工时也被清零** → ① 劳务对账失去计费依据 ② 人服侧（法定雇主）算薪出错。

### 正确写法：两层

| 字段 | 规则 |
|---|---|
| `ot_hours`（事实层） | **全部现场作业人员一律照记**，不分身份 |
| `ot_pay_amount`（金额层） | 仅「自有全职 + FT」计算；派遣/外包/自有非全日制 = 0，**但工时不置 0** |

派遣/外包的 `ot_hours` 用途是**计费工时**（劳务结算依据），不进工资项。

**连带三处**：
1. 薪酬侧硬规则「PT/LTPT 加班工时取 0」改为「**费**取 0」，工时不置 0。
2. 加班工时报表**必须按用工性质分列**，否则门店会拿报表质疑工资单。
3. 自有非全日制是否付加班费做成参数 `pt_ot_pay_enabled`，默认 `false`（各地口径差异大，需法务确认）。

### 数据模型

`attendance_daily.ot_hours` **直接拆三列**：

```
ot_weekday_hours  / ot_restday_hours  / ot_statutory_hours
```

现在拆是三列，以后拆是一次跨三模块的数据迁移。

## S2 五快照（替换 02b 的四快照）

| # | 快照 | 时点 |
|---|---|---|
| 1 | 工时单价 | 考勤确认日 |
| 2 | 技能归属（技能→单价映射版本） | 考勤确认日 |
| 3 | 组织归属（四维 assignment 版本） | 考勤确认日 |
| 4 | 计费口径（分摊策略版本） | 考勤确认日 |
| 5 | **`calc_rule_version`（计算所用规则版本）** | 算薪执行时 |

第 5 项是新增：工时是"算出来的"中间结果，规则改版后重算会让历史工时漂移。前四项锁的是输入，这一项锁的是**算法**。

> **原则（替代枚举自查）**：凡是参与算钱的中间结果，必须能固化，不能靠回溯推导。

枚举式表述总有漏，原则不会。

## S3 无考勤组：改为签认，不阻断上线

原「未匹配人数 > 0 不予上线」→ 改为「**> 0 须 HR 逐人签认后方可上线**」。

理由：新开店常存在「人已入职、店未建组」的正常过渡态，一刀切会卡死业务；签认同样有效但留弹性。

上线巡检增加一条：**「有 assignment 但无考勤组」名单**（员工有店可去、无规则可排），与「未匹配人员清单」合并成一张巡检报表。

## T1 10% 阈值改为「仅展示」（替换 02c 的 V5）

### 原写法有问题

阈值若参与计算：B 店借 3 人周末支援，每笔占比 < 10% → 成本退回主店、系数权重归主店 → **B 店获得免费劳动力，人力成本率被低估，B 店系数虚高**。累计 25% 借入工时，成本率就低估 25%，而 B 店并不高效。

**这是激励漏洞，不是计算误差。餐饮周末借人是常态，一定会被用。**

### 更关键：阈值想防的问题不存在

「支援半天把系数拉歪」只在**简单平均**下发生：

| 算法 | 结果 | 判断 |
|---|---|---|
| 占比加权 | 1.2 × 0.85 + 0.8 × 0.15 = **1.14** | 偏离主店 0.06 = 占比 × 差距，正确 |
| 简单平均 | (1.2 + 0.8) / 2 = **1.0** | 这才是被拉歪的 |

拉歪的根源是用了简单平均，不是占比不够大。

### 定稿

`allocation_min_share = 0.1` **保留但只用于报表明细折叠展示，不参与任何算式**；成本分摊与系数加权**全额按工时占比**。

好处：同源严格成立、指标不失真、系数不拉歪，还少一处过滤逻辑。

若实现上必须在计算侧过滤，则必须两边同阈值 + 加「单店每月借入工时占比上限 30%」护栏。

## T2 营业额口径补储值规则（餐饮最易被投诉的口径）

**充值不计营业额，按消费确认。**

- 会员卡充值全额进「预收款 / 合同负债」
- 消费时才确认收入
- 赠送部分按实收比例分摊：充 100 送 20，消费 120 元时确认营业额 100 元，赠送 20 元不计

理由：否则充值当月营业额虚高、成本率虚低，充值淡季反向跳变 → **店长奖金随总部促销节奏波动，而店长根本无法控制**。

进指标字典的营业额定义。

## T3 `perf_unit ↔ cost_center` 完整性校验

- 每个 `perf_unit` 至少映射一个 `cost_center`
- **一个 `cost_center` 对应 N 个 `perf_unit` 时，必须配置下钻规则（面积 / 营业额 / 工时 三选一）**
- 未配置则**不允许输出单元级人力成本率**

> 宁可不出数，也不出假数。

否则一个成本中心 3 个档口、3 个档口成本率完全一样，店长一眼看穿。

## T4 锁数快照不可变，重锁生成新版本（替换 02c 的 V8）

`snapshot_version` 递增、旧快照保留、重锁需权限 + 填原因 + 通知已查看过该期数据的门店，工资条标注「基于 v2 快照」。

比"解锁后直接改数"安全得多，且能向门店解释。

## 汇总：v1.3 之后的完整口径链

```
事实层（不可变）：打卡、请假、加班申请、工时（含 ot 三列）
   ↓ 固化
快照层（五件）：单价 / 技能归属 / 组织归属 / 计费口径 / 规则版本
   ↓ 计算
工资记录（唯一，三元组约束）
   ↓ 派生
分摊行（成本口径，全额按占比，无阈值过滤）
   ↓ 勾稽
管理成本账合计 ≡ 实发账合计（恒等，差异只作解释）
```

**任何一环回溯重算，都必须基于当时快照，不得读当前主档。**
