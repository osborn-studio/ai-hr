# 天意HR演示账号与岗位权限

完整虚构帐套可显式初始化62个员工账号和8个功能账号，共70个日常演示账号。既有`tyhr_admin`作为本机技术初始化账号保留，不重置其口令。

|登录账号|用途|范围|
|---|---|---|
|admin|系统配置管理员|帐套、组织基础、系统参数、账号与授权配置；不执行业务算薪、绩效或人员批量导入|
|demo|全部权限演示|查看、配置和操作所有测试功能|
|boss|老板|集团经营、人事、薪酬绩效只读，不能修改业务及授权|
|hr_manager|HR主管|集团HR运营、招聘、组织人事、考勤、薪酬绩效、培训|
|recruiter|招聘专员|招聘需求、候选及录用流程；不算薪或维护系统授权|
|payroll|薪酬专员|工资规则、试算、核验及确认；人员资料只读|
|trainer|培训专员|课程、场次、报名、学时及考试；不修改工资或雇佣|
|hr_staff|普通HR|日常人员、雇佣和人事事务；不算薪或配置系统|
|ty000001等|员工账号|店长按本店范围管理；店员与档口人员使用本人资料、工资、假期及学习自助|

账号与岗位是不同对象。HR功能账号独立测试职能权限，不增加62名测试人员。员工登录名由永久人员编号生成，以初始化回执为准，遇到已有同名账号会采用集团前缀，不接管原账号。

各店厨房人员可用非主任职同时覆盖厨房档口与炉灶工作区，明确标记兼岗。此操作不修改原主任职或已确认工资绩效。

## 本地初始化

先建立完整TY-TEST虚构工作区，再在明确的持久库上运行：

```bash
node tools/init-test-accounts.mjs --confirm-synthetic --work-areas
```

`--work-areas`显式追加尚缺的20条档口兼岗。初始化只作用于TY-TEST，重复执行保留已有口令、角色及用户修改。原工作区与客户源文件不受此工具影响。

初始口令随机生成，数据库仅保存散列。完整账号表写到本地`TYHR_RUNTIME_DIR/test-accounts.json`，文件权限600；日志仅打印计数与文件路径。重跑会合并仍可用的本地口令记录，不重置用户已经设置的密码。

## 登录与权限

新版工作台支持登录名或数字ID。使用JSON请求提交账号口令，避免新版页面把口令放进地址；原查询参数仅为原测试与旧客户端兼容保留。

角色资源许可、集团/公司范围和明确的员工绑定共同决定权限。菜单跟随真实许可，服务端另做岗位与数据范围检查。员工本人工资只返回已确认批次，不读取来源快照、草稿或他人的行；工资、培训、考试和假期自助均由会话识别本人。

完整口令文档只在本地交付，GitHub不保存口令、会话或运行数据库。部署到其他环境时重新初始化账号凭据。
