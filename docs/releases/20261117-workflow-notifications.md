# 审批消息与回执（增量233）

管理员可为公司和业务用途配置待审批、抄送及申请人结果通知。规则由另一名有当前业务权限的HR独立核准并明确授权以其账号后台投递。系统使用既有225消息队列发送，员工登录后回到确切原单，沿原有审批和显式业务生效流程办理。

## 状态和权限

- 原生审批任务、抄送和结束结果在原事务登记事件。多个抄送节点按同一审批单和收件人合并；申请人结果另存为一类事件。规则核准不会静默补发历史事件。
- 配置经办人和发送授权HR分别留存。225任务经办人是核准授权的真实HR；每次网络前后重核当前完整操作授权、实际发送字段、原单投影、接收人及唯一已核人员映射。不同部分授权不能拼成更大的消息权限。
- 通知仅含固定泛文案和确切事项链接，不发送工资、病历或其他表单内容。字段受限的接收人可按现有原单投影收到泛提醒，无须扩大字段授权。
- 待配置草稿可尚未绑定内部应用运行规则。它不能核准或投递；内部应用核准后须建立规则新版本。已核版本停用后不会重新启用被替代旧版。
- 接收者必须是登录本人及同一当前永久人员，原单仍按当前权限投影。通知引用不代表权限。停用发送规则不使历史原单入口失效；原单撤权后仍拒绝查看。
- 平台受理、送达依据、平台已读、站内阅读、原生审批和业务生效分别保存。平台回执不自动审批、不执行HR业务、不标记站内已读。
- 网络后撤权仍保留225实际受理响应，任务进入待核；不能将其当成未发送而重新投递。只有网络前明确未发送的阻断任务可沿225独立核对恢复。

## 已核公开协议

| 平台 | 已实现的消息结果读取 | 边界 |
| --- | --- | --- |
| 飞书 | [查询消息已读用户](https://open.feishu.cn/document/server-docs/im-v1/message/read_users)，[消息已读事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/message_read) | 只查询应用自己的已知消息，遵循7天窗口；验签、租户、应用、消息及读者对应后核入。名单无接收人时保持未报告，不推断未读。 |
| 钉钉 | [官方企业会话发送结果接口](https://developer.alibaba.com/doc2/apiDetail.htm?apiId=37024)，`topapi/message/corpconversation/getsendresult` | 以明确AgentID、原TaskID查询；按公开表单协议解析已读、未读、失败和无效人员列表。适配器保守限制一天内查询；该限制是本系统限制。没有平台阅读时间时只记录本地观察时间。 |
| 企业微信 | 既有225通用文本发送受理 | 未实现未经核实的通用文本已读回读协议，界面不提供假的已读查询。 |

目前不把钉钉、飞书或企微原生审批引擎的结果自动采用为HR批准或业务生效。员工经密码或受控企业SSO返回原生任务，登录后核对并明确办理。

## 接口和页面

查询：`integration.notifications.workspace`（规则、投递、回执分页与当前授权搜索）；`integration.notifications.target`（仅公开事项引用，不接收前端公司或人员扩权参数）。

命令：`integration.notifications.rule.save`、`rule.approve`、`rule.disable`、`delivery.retry`、`receipt.refresh`。写命令使用既有事务、稳定操作号和版本核验。

页面：集成设置中的“审批消息与回执”；PC和手机使用同一受控事项入口。待办链接为 `/#my/tasks/notice/<32位引用>`，抄送与结果为 `/#my/alerts/notice/<32位引用>`。登录保留确切入口，转交、批准、驳回和执行仍使用既有原生命令。

部署必须明确配置 `TYHR_NOTIFICATION_ALLOWED_ORIGINS`（英文逗号分隔的完整origin）。仅接受允许列表内HTTPS源或明确回环HTTP测试源；不从Host头推导。未配置公开源时有据阻断配置和发送。

## 演示与验证

标准演示工具 `seedWorkflowNotificationsDemo(db,{confirmSynthetic:true,origin})` 只用于已有完整标记的TY-TEST帐套，保留62人和77账号。它创建门店待办、抄送、批准和驳回结果，以及三平台待配置草稿，不造凭据、不联网、不造受理或已读。应在明确的允许公开源环境下执行，可重复回放。

增量47项PGlite和47项独立真实PostgreSQL验证通过；真实认证HTTP和编译后React的PC/393px手机16项通过，未捕获JS异常为0。既有225兼容回归71项、公开协议32项和目录HTTP2项通过。标准演示独立克隆首播和重放14项通过。233接线时的全新空PostgreSQL完整工厂也通过连续迁移及SHA核对，保留62人、77账号、20店，并检查233新阶段、初始密码不入场景文件、拒绝覆盖非空库。标准云端native-only入口下，已验证真实HTTP签名回调只更新平台阅读，以及旧工资书签转入原生核算首页、不传递旧数字ID。

协议测试使用本地HTTP服务和测试材料；未连接真实企业，未发送真实消息，不能据此声称某客户企业已接通。平台受理/已读测试证据仅保留在隔离验证库和本地测试记录中，不写入标准演示帐套。
