## 电子签与原生合同

集成设置和合同台账接入e签宝SaaS API V3。连接、个人和机构及经办人映射分别独立核准。外发意图冻结当前合同版本、主体、PDF原件与签章位置。后台上传后仅建立外部草稿；开启人工签署是独立明确操作。已完成的外部流程仍须回读原件、存证哈希及服务商验签报告，再由HR核定，最后显式办理原生合同签署登记。

结果不明的创建及开启不自动重发；已知流程仅安全回读。网络前后重新核对配置、原件、授权及来源版本。字段限制同时覆盖列表、检索、计数、下载和回执。当前已核定电子签后材料只能登记对应正文、版本、主体和日期的合同；改稿后必须重新收集材料。待签原件不能替代纸签扫描件。普通纸质签署保留独立HR核验流程。

`TYHR_ESIGN_ALLOW_LIVE`默认关闭，不办理真实外部任务。真实应用、实名主体与机构规则须另行配置验收；本地核准不代表服务商连通。当前采用主动核验，不开放未经实现的服务商回调；服务商验签报告与本地独立PDF证书链验证明确区分。合同签署、结构条款生效和工资来源采用分别办理。

协议依据：[官方V3开发说明](https://open.esign.cn/doc/opendoc/dev-guide3/el34xh)、[文件上传](https://open.esign.cn/doc/opendoc/pdf-sign3/rlh256)、[创建流程](https://open.esign.cn/doc/opendoc/pdf-sign3/su5g42)、[开启流程](https://open.esign.cn/doc/opendoc/pdf-sign3/pu4xsx)、[下载文件](https://open.esign.cn/doc/opendoc/pdf-sign3/kczf8g)、[验签报告](https://open.esign.cn/doc/opendoc/pdf-sign3/yekrnc)。

## 一致的人事权限与门户

基础目录的POST和GET入口统一到同一投影。配置管理员只取得当前有权的人员ID、姓名、永久编号，用于账号配置；不附带雇佣、任职和外部身份历史。其他人员按当前人事完整授权逐公司、部门、本人及字段投影，计数在范围过滤之后产生，不拼接字段授权，也不返回旧身份快捷字段。

个人门户“全部授权”不再隐式缩小到操作账号的当前门店。本人仍有权阅读的原门店申请和通知可以继续查看；明确选择门店时仍按所选范围过滤。通知候选目录单独提供外包人员，接收资格与审批资格分开，最终通知仍按原单当前阅读权限核验。

企业登录设置增加只读前置检查，按当前可见且有权的连接显示启用、凭据、内部应用、人员及具体账号对照状态。没有为了演示生成假的已核平台身份。通知状态在PC和手机使用中文说明，站内记录与平台受理、送达、已读分别显示。

## 供应商成本与权限

已确认的供应商对账成本按归属月和独立成本承担公司进入老板人力成本表，可穿透当前授权的对账版本与明细；代发资金排除，与工资成本匹配时防止重复计入。尚待核定或金额不可见的来源明确标示，不作为零成本。

供应商联动测试在 PGlite 和真实 PostgreSQL 各通过 124 项；工资字段投影各通过 5 项，禁止拼接不同授权的字段。实际老板账号 PC/手机只读验证通过 7 项，包含双币种合计、受保护来源穿透、无业务写入及无页面错误。
