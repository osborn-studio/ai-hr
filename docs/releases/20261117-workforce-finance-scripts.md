# 供应商用工、工资资金与公式扩展

2026年11月17日。增量迁移226–228，沿用冻结001–225。这里只记录实际实现和验证；测试不代表真实银行支付、政府受理或外部平台实连。

## 供应商用工

入口为「用工与服务」下的供应商与用工、服务量与对账、供应商资金、工资代发核对、用工沟通。每个入口分短页签，列表由服务端按授权分页。PC可维护资料；手机可复核、查看业务原件、处理本人沟通。

供应商资格、加密收款版本、服务合同、订单、人员实际关系、服务量及工作地分摊分别核定。原生考勤来源取当前已核雇主月根，明确计量截止；工作地分摊不增加第二份服务量。已核法律雇主采用有效期内的结构条款，不回填原有未知登记。

对账、供应商确认、应付、期初、预付、发票、银行事实、付款及逐人结果分别留痕。已外发未知继续占用，待退款单独登记；供应商收款不会冒充员工到账。14类重要业务可绑定统一审批，来源变化、撤权及本人别名自核均受阻。

- 领域116项PGlite与116项独立PostgreSQL通过。
- 实际正式registry、Node HTTP、隔离PG及React PC/393px手机12项通过，覆盖供应商新增、分页、资格核定、原件上传下载、对账穿透及员工共享沟通。
- 新演示30场景，复用6位服务人员；首次生成和原号重放通过，原帐套不变。

## 工资资金与申报

入口为「薪酬管理 → 工资付款与申报」，包含工资资金、收款资料、付款申请、到账核对、期初与对账、申报与供款、文件与登记。已确认工资是资金目标来源；报销和净工资分别核，全部渠道共享父资金根，未知期初不补零。

七类资金业务接真实审批与显式领域执行。输出文件使用独立核准的声明式列布局、机构登记和人员标识，保存加密原字节。重新下载返回同一份原件；输出文件、提交凭据、受理凭据、实际供款及员工到账各自保留状态。当前没有预置或认证具名银行/政府正式上传格式。

已增加香港行业MPF适配和已核住房公积金整元口径；计算仍要求明确政策版本、适用事实及来源，不能用演示政策代替现行法定核定。

- 资金原127项及父公司/品牌帐筛选、检索新增3项，共130项双库通过；整元及原薪税回归60项双库通过；行业供款23项双库通过。
- 实际正式registry、认证HTTP、隔离PG及React PC/手机12项通过，包含不同账号独立核准、原件相同字节重下载、部分到账与余款占用。
- 资金演示13场景、7类真实审批；独立PG9项验证通过。演示不调用银行或政府。

## 公式代码与触发器

入口为「薪酬管理 → 公式代码与触发器」，分代码版本、沙箱预演、参数草稿、触发器、触发任务及AI需求提案。代码只接受已声明类型的当前工资参数与已核考勤，输出普通参数草稿；经过另一自然人独立核准后，仍沿正常工资预演、复核、采用和确认。

执行器采用精确锁定的QuickJS WASM包，物理内存固定64MiB、代码/输入/输出和运行时间设上限，并由Node工作线程硬限时；未启用配置时拒绝执行。没有文件、网络或主机业务回调。触发任务重查原操作者当前权限，来源变化和撤权阻断；AI接口只保存需求，未配置模型不会声称已生成或执行代码。

- 领域54项双库、真实引擎12项、前端模型5项通过。
- 实际正式registry、隔离PG、认证HTTP、真实WASM及React PC/手机11项通过。
- 两地7个演示场景及9项克隆验证通过，工资采用及已确认工资没有被后台新增。
