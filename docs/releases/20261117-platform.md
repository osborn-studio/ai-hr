# 平台、假期生命周期与人员配套数据检查点

2026-11-17。React与同一Node进程、真实PostgreSQL继续使用第一组部署架构；新增213–215迁移已在专用虚构演示副本受控前滚，已应用字节冻结。原演示库与旧工作台保留。

## 已实现

- 操作人员、一次性初始凭据、角色和成员、同一授权内功能动作/公司部门人员/字段/明确有效时点、只读模拟、即时撤回与停用会话；配置岗位不因此取得业务数据。
- 新授权与原业务资源投影不交叉扩大。尚未改造为完整授权的旧接口对已接管账号明确阻断；不会把粗粒度旧查询当作字段授权已生效。授权生效日期按业务时区，避免UTC零点偏移。
- 表单字段设计、可拖动节点/连线、条件、或签会签、抄送、转交和代理、双人发布与不可变版本、实例/当前任务/轨迹、本人撤回。PC设计与手机办理分开，默认服务端分页。
- 普通表单只形成审批登记；请假表单实际接入原生额度，提交预占、批准待执行、执行转为已批占用、驳回/撤回释放。申请人、真实批准人和实际执行人分别保留；已变更来源不能用旧审批覆盖。
- 高级假期延期、结转、周期发生候选、预支及清偿核对、加班已核分钟分配、补偿和未休现金资格/义务；精确有理数累计与来源守恒。来源仍须有资格、日历、实际关系和已核依据，不默认未知地方规则。
- 宿舍、证照和简单物品21张原生表：真实入住换退和房床排他、维修；费用分摊及跨渠道同一余额/未知对账；证照独立核验续期、跨店认可和借还；用途/采购入库/核准实领/原单退回和库存守恒。尚待配套React页面和丰富演示。
- 独立集成配置、AES-GCM凭据、三平台能力/未实连状态、外部快照及组织人员人工对照；不按同名新造雇佣，不把配置校验当作外部连接或发送成功。
