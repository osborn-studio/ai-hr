# 集成运行与来源核验检查点

225把连接配置、人员及组织对照、原始打卡、消息任务和签名回调接入同一个Node服务。外部来源先进入可复核收件箱，核定后才能成为新考勤草稿的证据；已封存考勤及工资不被回调改写。

## 连接与同步

钉钉、飞书、企微采用各自适配器和验签协议。按已核准的部门范围读取直属人员，飞书和企微可读取已核范围的子组织；姓名更新由独立人员核准。对照记录关联现有永久人员及真实任职，通讯录出现一条记录不会直接创建新雇佣。

消息任务只发送通用业务提醒和回系统办理的入口。通知受当前接收人、源业务和字段授权约束；远端受理、员工已读及本地审批生效分别记录。超时写任务保留未知状态，不通过更换操作号再发。

设备入口支持TYHR签名网关和可独立复核的Excel来源，配置页明确具体协议。未配置的第三方凭据显示未配置，不生成假的已发送回执。钉钉部门树、第三方代开发认证、外部原生待办创建、任意设备型号的私有协议及外部打卡写回继续单独适配。

## 回调与执行

公共回调精确匹配连接路径，保留原始字节，限制1MiB；验签、去重和加密来源在单个事务提交后才返回供应商ACK。失败使用通用拒绝码，不返回签名参数或秘密。已验证云审批事件仍需本地支持的业务结构和当前授权复核，不自动批准本地业务。

同一Node进程中的worker用短事务领取租约和提交结果，网络请求位于事务外。关闭应用等待在途工作完成。Broker部署的签名回调及worker须在相应事务执行服务端运行；无该后端时不确认收件。

## 个人场景与导入

新增五个个人场景：退宿草稿、换房审批、领用已批待交接、领用实际出库，以及员工调店审批。领用前缺库存时通过采购入库、独立核准和验收操作补足。身份、既有任职、原卡及工资的摘要保持不变，原号重跑不新增业务。

新增九个集成场景，包括三平台未配置、内地及香港原卡文件预检、独立核定、归属待复核和原卡核准。文件进入来源收件箱，不直接确认考勤或采用薪酬。整组数据仅使用既有62人及77账号。
