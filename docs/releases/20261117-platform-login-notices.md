# 企业平台登录、审批通知与分角色门户

2026年11月17日。230连续迁移接在229后，001–228保持原字节。登录配置与本人映射分别核准，不新增员工、操作账号或角色。

## 平台登录

集成设置新增“企业平台登录”，提供入口配置、具体操作账号对照、独立核准与停用。配置只接受服务端`TYHR_SSO_ALLOWED_ORIGINS`白名单中的完整源地址；正式使用HTTPS，本机HTTP例外须逐项明确开启。空白名单不开放登录入口。

- 企业微信支持内部应用PC网页登录与客户端网页授权；当前成员身份与本企业归属必须验证。
- 飞书支持OAuth v3与S256 PKCE；客户端内使用同一授权跳转流程，不宣称SDK静默免登。
- 钉钉支持网页登录OAuth，校验本企业身份并将unionId解析为当前企业userid；本次不启用SDK免登码模式。

只从已独立核准的组织人员对照定位永久人员，再绑定明确选定的活跃操作账号。不按姓名、手机或邮箱自动匹配，也不在同一人多个账号中自动选择权限最高者。源连接与目标操作账号范围都要满足完整授权。

公共OAuth编排在领域服务之外拥有短事务：先消费state，事务外读取官方身份，再开新事务重查当前映射和人员权限。5分钟state、浏览器HttpOnly绑定、60秒一次性回跳票据和同源兑换分别验证。回跳URL不放本地会话或平台token；上游token只在本次交换内存中使用。凭据轮换、人员或账号失效、配置停用、映射变更会阻止新登录并使相关既有平台会话失效。

## 通知与工作台

通知接收者单独按当前阅读权限核验，不要求拥有审批权限，不因代理审批重定向抄送；同一原单经过多个通知节点，在个人通知列表只形成一项。新流程可配置向申请人发送批准、驳回和撤回结果。阅读、审批通过和实际业务办理分别记录。撤权后不再通过历史通知取得原单字段。

“我的待办”默认只列当前可办理事项，“办理记录”另列没有当前动作的历史任务。已批准而等待有权经办执行的事项仍属于待办理。PC和手机可直接查看确切审批原单与授权轨迹。

工作台按系统配置、集团及公司HR、薪酬、招聘、培训、店长、店员、档口和外包角色显示不同焦点，最多六个常用入口。所有快捷入口仍从当前有权且已实现的菜单中选择；顶部身份使用实际操作人员类型。异步切换视图和工作范围先清空旧投影并显示读取状态，避免旧数据被新页面列名误读。

## 验证范围

- `test/external-sso.test.mjs`：70项PGlite和70项隔离PostgreSQL，覆盖三平台真实协议HTTP、身份归属、PKCE、防重放、撤权并发、完整字段和数据权限。
- `test/sso-browser-pg.test.mjs`：21项正式注册表、会话、HTTP、实际React PC及手机验收，含登录与管理配置、人员对照、检索和分页。仅接受随机命名空测试库。
- `test/workflow-notifications.test.mjs`：14项双数据库，覆盖只读接收、申请人结果、代理隔离、通知去重、当前权限重检和原通知参数兼容。
- `frontend/test/workspace-experience.test.mjs`：角色快捷入口撤权、不可用入口、配置门户和无授权输入验证。

以上平台响应由本地受控HTTP协议夹具提供，没有调用真实企业身份平台或发送短信、邮件及签署邀请。真实企业应用仍须配置凭据、官方权限和回调域名并做实连验收。

协议依据：[企微PC内部应用登录](https://developer.work.weixin.qq.com/document/path/98174)、[企微网页授权](https://developer.work.weixin.qq.com/document/path/91022)、[飞书OAuth v3](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token-v3)、[飞书当前用户信息](https://open.feishu.cn/document/server-docs/authentication-management/login-state-management/get)、[钉钉网页登录](https://open.dingtalk.com/document/orgapp/tutorial-obtaining-user-personal-information)。

## 实际页面与演示场景收口

`test/workflow-notifications-browser-pg.test.mjs` 在随机命名的隔离 PostgreSQL 副本上，使用正式注册表、HTTP、会话和构建后的 React 页面完成24项检查。PC及393像素手机页面覆盖申请人批准、驳回、撤回结果，真实已读命令与原单穿透，只读接收人无审批动作，审批委托不改变抄送，撤权后原单403及旧卡片消失。

同次检查验证“待我办理”和“办理记录”按服务端当前动作分开，具有完整授权的集团统一事项不会因选中公司而被提前过滤；员工及配置管理员首页最多六个快捷入口。实际延迟请求期间，外包服务总量、月度对账、对账明细及品牌范围切换显示读取状态，不将上一视图记录套入新列。请求继续后使用真实服务返回的金额、工时与三条新范围记录。浏览器无 JavaScript 错误，手机页面没有整体横向溢出。

`tools/seed-workflow-notification-demo.mjs` 提供五个可重放场景：已批准结果、已驳回结果、本人撤回结果、仍在审批的申请、集团HR原单抄送。已批准单经过两个通知节点及结束通知仍只呈现一张当前卡片。抄送使用原有完整可读的集团HR账号，不扩大老板权限；独立只读夹具另行证明接收通知不要求审批权。首次及重放保留相同场景引用，不新增账号，不改变口令、既有权限或工资记录。通知记录和核准结果不替代实际业务执行。

本次检查未写入保留中的V5、V6或V7演示环境，没有调用真实外部身份平台或发送对外消息。上述测试截图仅作为开发验收证据，正式宣传素材另从冻结演示环境采集。
