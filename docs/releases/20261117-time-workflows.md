# 排班、补卡与原请假单统一审批

2026年11月17日。229为连续增量；001–228迁移保持原字节。实际演示数据库的升级与代码验证分别执行。

## 业务结果

- 调班、互换、借调与支援引用216原申请；需要对方确认时，先由真实对方本人同意，再送指定流程。原单据页可以直接提交审批和查看确切审批原单。
- 审批通过保留原申请待办理。当前有权经办显式实际办理后，调整写入排班草稿，原正式班表保留，发布仍另行复核。
- 补卡引用原班段与真实工作关系。审批与实际办理分开；实际办理生成核勤草稿，原卡不改写，考勤确认和工资采用仍分别办理。
- 原请假单只送审一次，不另造请假或重复预占。批准后分配原权益，实际已休仍另行核定。审批原单在PC和手机直接查看，申请人与审批人进入对应门户。

## 来源、权限与防重

审批绑定覆盖原公司、工作地、接收门店和相应申请类别；不同有效绑定不能任选较弱流程。原申请人、受益员工及同一人的其他账号不能自行核准。

原计划、班段、本人同意、工作关系、当前考勤头和相关原卡形成冻结指纹。原卡迟传、来源更版、关系有效期变化或最新月汇总不适合按日更正时，办理保持受阻并留下真实日志，不覆盖原事实。审批通过后撤权仍会阻止实际办理。字段受限或某行流程配置冲突不会使整张列表失效，也不会向该用户补发审批编号。

229的不可变执行凭证记录原经办、提交人、批准人和实际办理人；数据库约束核验确切来源与真实审批节点。旧的直接决定接口在已绑定或在办事项上不能绕流程。客户端JSON不能代替服务器私密执行凭证。
