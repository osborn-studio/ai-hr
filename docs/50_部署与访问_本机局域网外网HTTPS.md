# 50. 怎么把系统跑起来，以及怎么让外面的人访问

> 这份文档只回答三件事：**本机怎么起**、**局域网/外网怎么开**、**为什么不能想当然**。
> 具体业务口径不在这里（见 `docs/00` 与各专题）。演示时的注意事项在 §6，那是**会当场出丑**的部分。

---

## 0. 端口：8899（为什么不 8788）

本机端口很挤，ERP / CRM 与各种开发服务占了 3000、3001、3307、3396–3397、4220–4310、
5000、5433、7000、8440、18488、52502 等一大片。早期演示用的是 **8788**，
后来发现它落在这些服务常被临时征用的区间附近，于是统一改到 **8899**（实测空闲）。

- `tools/` 下三个脚本（`migrate-status` / `migrate-apply` / `backup*`）都读同一个
  `PORT` 环境变量，默认 8899 —— **换端口只改环境变量，不要改代码**。
- 早期文档（`docs/48`、`docs/49`）里出现的 8788 是当时的历史记录，不是现在的配置。

## 1. 一条命令起服务

```bash
cd ai-hr/code
PGLITE_DATA_DIR=/tmp/xxym-v5 PORT=8899 node app/server.mjs
```

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 演示固定用 **8899**（本机 ERP/CRM 占了 3000/3307/4220–4310/5433 等，8899 实测空闲）。`tools/` 下的对账/前滚/备份脚本都读同一个 `PORT`，换端口只改环境变量 |
| `HOST` | `127.0.0.1` | **只监听本机回环**。局域网要换成 `0.0.0.0`（见 §3） |
| `PGLITE_DATA_DIR` | `./.data` | 数据库目录。演示库是 `/tmp/xxym-v5` |
| `SEED_SKIP=1` | — | 跳过灌种子（**已有库必须带它**，否则空库才灌） |
| `TRUST_PROXY=1` | — | 在反向代理后面时置 1，否则取不到真实来源 IP（登录限流按来源计） |

★ **别把 `node … &` 挂在后台**。父 shell 退出会把进程一起带走，日志里明明打了
`listening on 127.0.0.1:8899`，端口却已经没了 —— 这个坑今晚踩过，见 `docs/49`。

## 2. 数据目录是**单写者**的（这是本仓最容易误判的一条）

PGlite 是"数据库跑在进程里"，没有服务端做并发控制。因此：

- **一个目录同一时刻只能有一个进程打开**。两个进程同时打开不是排队，是**互相覆盖**。
- 想对账/校验/前滚，**先停服务**；不想停就对**副本**做（`cp -R` 后对副本操作）。
- 备份 = 停服务 + `cp -R`。运行中直接 `cp` 得到的是一份可能撕裂的库。

```bash
# 对账（只读，服务在跑时会对"它正开着的那个目录"拒绝）
PGLITE_DATA_DIR=/tmp/xxym-v5 node tools/migrate-status.mjs

# 前滚（必须先停服务；必须显式写号；会先自动备份）
kill <pid>
PGLITE_DATA_DIR=/tmp/xxym-v5 node tools/migrate-apply.mjs --only 183
```

**为什么没有"自动追平"**：这个库从来没有 `schema_migration` 账本，"缺哪几条"只能靠指纹推，
猜错就把旧库永久钉成最新 —— **错误的账本比没有账本更危险**（`docs/48 §13.6`）。
启动时只会**警告**，并把上面两条命令打出来。

## 3. 局域网访问（同事在自己电脑上打开）

```bash
HOST=0.0.0.0 PORT=8899 PGLITE_DATA_DIR=/tmp/xxym-v5 node app/server.mjs
```

然后别人访问 `http://<这台机的局域网IP>:8899`。取 IP：

```bash
ipconfig getifaddr en0
```

三个必须知道的边界：

1. **没有 TLS**：局域网里是明文 HTTP，口令与会话 token 都能被抓包看到。只在内网演示用。
2. **登录会按来源限流**（30 次失败锁定）。十个人同时试错口令，会把整个出口 IP 锁掉 —— 这按设计如此。
3. **并发会排队**：PGlite 单进程，五个并发请求最后一个等前四个跑完（详见 §6）。

---

## 4. 外网 HTTPS：保留配置位，不在本仓内置

本仓是**单机演示版**，不带证书、不带反向代理。要对外，把它当成一个普通的 HTTP 上游：

```
外网 ──HTTPS──> 反向代理（Caddy / Nginx / Cloudflare Tunnel） ──HTTP──> 127.0.0.1:8899
```

Caddy 的最小配置（自动申请证书）：

```caddyfile
demo.example.com {
    reverse_proxy 127.0.0.1:8899
}
```

此时**服务仍监听 `127.0.0.1`**（不要为了外网把 `HOST` 改成 `0.0.0.0`），
并且**必须**设 `TRUST_PROXY=1`，否则限流把所有请求都算在代理那一个 IP 上。

四条硬要求（少一条就会出问题）：

| 要求 | 为什么 |
|---|---|
| 反代要转发 `Authorization` 头 | 会话 token 在这个头里。有些网关会静默丢掉它 —— 本仓为此**同时认** `X-AIHR-Token`（`server.mjs` 的取值处），但别指望它能救回所有网关 |
| 反代超时 ≥ 60s | 组织页正常 0.4s，但首次冷启动/并发排队会到秒级；20s 超时会被读成"服务挂了" |
| 只暴露一个入口 | 不要把 PGlite 目录、`/tmp` 静态目录另开端口 |
| 演示期间别换证书/别重启反代 | 会话是进程内内存态，重启后所有人要重新登录 |

## 5. 开机自启（launchd，需要本人在**自己的终端**跑）

沙箱里 `launchctl` 是被挡住的，所以这一步只能由操作者执行。
脚本与 plist 模板在仓库里（`deploy/macos/`），`~/Library/Application Support/aihr-demo/install.sh`
只是转发过去的一份壳 —— **同一件事不要放两份拷贝**，它们迟早变成两种说法。

```bash
cd ~/ai-hr && sh deploy/macos/install.sh --dry-run   # 先看它要做什么（不碰 launchctl、不 kill、不复制）
cd ~/ai-hr && sh deploy/macos/install.sh             # 再真装
```

`--dry-run` 会检查：node 可执行、代码目录与 `node_modules`、数据目录可写、磁盘余量、
8899 上的占用、要搬哪个库，并把 plist 的四处替换结果（node / code / data / HOST / logs）逐行打出来。

脚本会：自检 node → 停掉 8899 上的临时实例（**必须先停**，PGlite 单写者）→
把数据目录**复制到持久目录**（`~/Library/Application Support/aihr-demo/data`，`/tmp` 会被系统重启清空）
→ **打开副本数一遍**（表数 + person/payslip 行数，打不开就中止）→ 生成 plist → 装 → 跑四项验收。

四条注意：

- **它会 kill 掉 8899 上的那个实例**。演示期间跑它 = 服务中断几十秒，别在演示前 5 分钟装。
- **装之前先定稿数据目录**。服务跑的是"安装那一刻复制过去的快照"，之后再换库它不会自动跟。
- **装完不要再手工起一个 8899**：EADDRINUSE + 两个进程抢同一个 PGlite 目录。
- `HOST` 默认 `0.0.0.0`（局域网可达）；只给本机就 `HOST=127.0.0.1 sh deploy/macos/install.sh`。
  node 路径由 `~/.workbuddy/binaries/node/versions/current` 现算，WorkBuddy 升级 node 后**重跑一次**即可。

上线前的完整检查项见 `docs/52`（备份恢复、迁移对账、监控、权限基线）。

## 5.5 登录被限流（429）：演示当天最容易把自己锁死的一条

```
429 E_LOGIN_THROTTLED / E_LOGIN_LOCKED
同一来源 30 次失败后锁定约 15 分钟（阈值见制度项 RATE_LOGIN_FAIL_PER_15M）
```

三个必须知道的事实：

1. **按来源 IP 计数，成功不清零**。设计如此：清零的话，攻击者拿自己的账号登一次就能继续试别人。
   代价是**在同一台机器上演示的人共享一个来源** —— 一个人连错 30 次，所有人一起被锁。
2. **`index.html` 每次加载都会自动 `login(1)`**（演示便利：默认以集团 HR 进）。
   所以**每刷新一次页面就多一次尝试**；如果 user 1 当时登不上，刷新就是**把锁续上**。
   这就是为什么"越急越登不上"。
3. **不要做成自动重试**。重试只会延长锁定窗口 —— 这条是实测出来的，不是推理。

**现场处置顺序**（从便宜到贵）：

| 做法 | 代价 | 说明 |
|---|---|---|
| 等 15 分钟 | 0 | 窗口是滑动的但只数窗口内失败；停止尝试后自然解锁 |
| 换账号：`/?u=2&pwd=demo1234` | 0 | 绕开那个登不上的账号；`?u=` 支持任意帐套账号 |
| 调高阈值（制度项 `RATE_LOGIN_FAIL_PER_15M`） | 需改数据 | 演示机可临时调到 200；**改完要记住改回来** |
| 清掉近期失败记录 | 需停服务 | `DELETE FROM login_attempt WHERE source='127.0.0.1' AND at > now()-interval '15 minutes'`；PGlite 单写者，**必须先停服务** |

★ 这一条**只在演示机上才该放宽**。上线形态下 30/15min 是对的，别把它当"太严"改掉。

## 6. 演示须知（会当场出丑的三件事）

1. **组织页一次一个人点**。PGlite 单进程，五个人同时点，最后一个要等前面四个跑完
   （60 店单次 0.4s，五个并发叠到 2s 量级，再叠浏览器 6 连接上限会摸到 10s）。
2. **别在演示中途重启服务**。起来那几秒页面全白。
3. **别现场授予"只看本档口"的能力位**。演示库每个档口只配了 1 个岗 1 个人，
   授了位花名册会从"整店 11 人"变成 **1 人** —— 那不是越权也不是 bug，是数据配不齐，
   但现场很难解释。
   ★ 说准确一点（别顺口说成"默认关"）：**182 建的 `station_chef` 角色自带这个位**，
   而这批演示账号里**没有一个是那个角色** —— 所以今天谁登录都不受影响。
   要演示它，得新建一个带 `station_chef` 的账号（或用前厅/洗碗这类 **2 人档口**，
   见 `docs/48 §17.5`）。
