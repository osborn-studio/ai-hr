## 七、术语表（必须严格区分，否则评审必然打架）

| 术语 | 定义 | 不要混淆 |
|---|---|---|
| **多账套** | 核算集合拆分：同一员工被分到不同账套各算一次，多法人分别出账报税 | vs 多口径账 |
| **多口径账** | 同一笔实发工资派生实发口径与管理成本口径两份结果，同源派生、必须可勾稽 | 竞品无此概念 |
| **借调计价差** | `按任务价计费 − 按机械分摊`，Σ=0，只作解释与校验 | **不是毛利**，不产生利润 |
| **毛利** | 客户收费 − 工资 − 社保 − 返费，**不恒为 0**，是利润 | vs 借调计价差 |
| **用工类型** | FT / PT / LTPT，决定**怎么算钱** | vs 用工性质 |
| **用工性质** | 自有全职 / 自有非全日制 / 派遣 / 外包 / 第三方兼职，决定**谁发钱、算不算人效** | 派遣的人可能是月薪制全职 |
| **借调** | 劳动关系不变，1 条工资记录，A 发薪 | vs 调动 |
| **调动** | 劳动关系变更，2 条记录，期间不重叠 | 跨法人调动 ≠ 借调 |
| **绩效单元** | 可独立核算绩效的最小经营单元（门店/档口/共享厨房） | vs 成本中心（可多对多映射） |

## 八、三条系统级原则（写进 PRD 技术原则章）

1. **主档只回答"现在归谁"，时序表回答"当时在哪"。** 凡涉及过去某一天的计算，禁止读主档当前值。
2. **凡是参与算钱的中间结果，必须能固化，不能靠回溯推导。**（五快照的依据）
3. **能在约束层消灭的异常，不要留给下游清洗脚本。**（数据建模原则）

## 十、优先级调整（负责人 2026-11-14 指示，覆盖前面的分级）

### 10.1 重心重排

| 档位 | 模块 | 投入 |
|---|---|---|
| **第一优先级（做深做透）** | 人事组织、入转调离、排班（含 AI 排班）、假期 | 60% |
| **第二优先级（对标成熟产品做到能用）** | 算薪 | 25% |
| **第三优先级（够用即可，采用成熟范式不深度定制）** | 绩效、考试 | 10% |
| 其余 | 招聘、报表、MCP | 5% |

**绩效**：采用「目标 + 指标 + 评分 + 校准 + 等级分布」成熟范式即可，**不做** OKR 深度、不做 360 环评、不做人才盘点。门店记分卡保留（它是算薪系数来源），但界面从简。

**考试**：采用「课程 + 题库 + 组卷 + 考试 + 成绩 + 证书」成熟范式，**不做**学习社区、直播、积分商城、AI 命题。

### 10.2 AI 排班升为 P0，分三级实现

用户明确要求"最好加一个 AI 排班"。拆成三级，P0 交付第一级，让用户立刻感知到"系统帮我排好了"：

| 级别 | 能力 | 是否 P0 | 说明 |
|---|---|---|---|
| **L1 规则排班** | 轮班模板 + 一键生成整月 + 冲突自动消解 + 缺人推荐补位 | ✅ **P0** | 不需要算法，规则引擎即可。店长感知最强 |
| **L2 建议排班** | 历史同期模式 + 客流/营业额预测 + 工时预算约束 → 给出建议班表，店长采纳或微调 | P1 | 需要 3 个月历史数据才有效 |
| **L3 优化排班** | 多目标优化（成本、满意度、合规、客流匹配） | P2 | 运筹求解，本地版算力可接受 |

**L1 必须包含的四件事**（这才叫"智能化"，不是"能填表"）：
1. **一键生成**：选店 + 选周期 + 选轮班规则 → 30 秒出整月班表
2. **自动消解冲突**：生成时即校验工时上限、连续工作天数、最小间隔、健康证，冲突处标红并给替代方案
3. **缺人自动补位**：某班次人数不足 → 按「工时余量 → 技能匹配 → 通勤距离 → 成本」排序推荐，一键拉人
4. **变更自动传播**：改一个人的班 → 自动检测连带影响（谁的工时超了、谁的健康证过期），并通知到人

**AI 的边界**：AI 只产出「草稿 + 建议」，**发布权永远在店长**。不允许 AI 自动发布排班。

### 10.3 假期对齐国家现行口径（P0）

假期体系必须按现行法规内置，且按地区参数化：

| 假期类型 | 国家口径 | 系统实现 |
|---|---|---|
| 法定节假日 | 11 天/年（元旦1、春节3、清明1、劳动1、端午1、中秋1、国庆3） | 内置节假日库，按年度维护，支持调休上班日 |
| 带薪年休假 | 累计工龄满 1 年不满 10 年 5 天；满 10 年不满 20 年 10 天；满 20 年 15 天 | 按工龄自动生成额度，支持按在职月份折算 |
| 病假 | 医疗期按工龄与本单位工作年限确定（3–24 个月） | 医疗期累计计算 + 病假工资比例参数化 |
| 产假 | 98 天 + 地方奖励假（各省不同） | 按参保城市参数化 |
| 陪产假 | 各地不同（7–30 天） | 按参保城市参数化 |
| 育儿假 | 各地不同（子女 3 周岁前，每年 5–15 天） | 按参保城市参数化 |
| 婚假 / 丧假 / 工伤假 | 国家规定 + 地方补充 | 参数化 |
| 加班调休 | 休息日加班优先安排补休，不能补休的付 2 倍 | 调休余额台账，与加班工时联动 |

**关键要求**：
- 节假日库与地方假期参数**按年度版本化**，历史月份按当时版本重放（版本化原则）
- 地方差异做成「城市参数包」，支持离线导入（内网版无云端下发）
- 法定节假日上班：月薪制**照付 + 另付 3 倍**；时薪制按 3 倍工时计——这个双逻辑不能简化成一种

### 10.4 算薪：按成熟商业产品的能力标准对标

对标口径（不点名具体产品）：多薪资方案、多账套、算薪规则可配、社保公积金多城市、个税累计预扣、工资条与确认、成本归集。这些在 P0-29 至 P0-36 已覆盖，**不需要新增模块**，只需确保能力深度对齐成熟产品。
