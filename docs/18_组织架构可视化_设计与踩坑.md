# 18 · 组织架构可视化：设计与踩坑

> 对应代码：`code/app/index.html`（`viewOrg` / `orgTreeLayout` / `orgTreeSvg` / `orgRadialSvg` / `orgPosCard`）
> 对应断言：`code/test/ui.test.mjs` 的 UI9、UI9b、UI10、UI11、UI12

## 1. 一句话

部门页与岗位页**共用同一份数据**，顶部一个滑动分段器切换；部门给三种看法（树形图 / 关系网 / 清单），
岗位给两种（卡片 / 网络）。图形全是自算坐标的原生 SVG —— 不引外部图库，内网、离线、CSP 收紧都不会突然白屏。

## 2. 为什么"建完部门就是这个帐套自己的架构"

不需要额外逻辑，需要的是**不缓存**：

- 一帐套一库（迁移 069/070），`org_unit` 就在这个帐套自己的库里，别的帐套的库根本连不到它；
- 每个请求按 token 前缀路由到对应库（`app/registry.mjs`），`/api/org/tree` 永远只读当前库；
- 前端**不存**上一次的树：`ORGST.rows` 每次进页面被覆盖，没有 `TREE_CACHE`。

所以 DM 帐套建了 16 个部门，只有 DM 看得到；新开一个集团帐套，进去就是一棵只有一个根的空树，
从「＋ 新增部门」开始长。

## 3. 交互结构

```
组织
├─ [ 部门架构 | 岗位架构 ]        ← 滑动分段器（滑块跟选项走）
│   ├─ 部门：树形图 / 关系网 / 清单
│   └─ 岗位：岗位卡片 / 岗位网络
└─ 右上角：在册 / 定编 / 缺编 / 期间 + ＋新增部门
```

两处"滑动"是两件不同的事，别混：

| 控件 | 切换的是 | 存在哪 |
|---|---|---|
| 顶部 `#orgSeg` | 页面：部门 ↔ 岗位 | URL hash（`#org/tree`、`#org/pos`） |
| 工具条 `#orgOri` | 布局：竖排 ↔ 横排 | `localStorage`（`aihr.org.ori`），URL `?ori=h` 可覆盖 |

朝向是**看图的习惯**，不是数据：同一个帐套换个人看，偏好也该各人自己的，所以不进库、不跟帐套走。
`?ori=h` 是为了让"这一屏长什么样"可复现（截图、培训、贴链接）。

## 4. 布局算法（这是"难不难看"的全部）

### 4.1 树形图：主轴/次轴互换

竖排和横排**不是两套代码**，只是主轴与次轴互换：

| | 主轴（层级推进） | 次轴（兄弟排列） | 卡片 |
|---|---|---|---|
| 竖排 | y = depth × (NH+GY) | x 递增 | 164×66 |
| 横排 | x = depth × (NW+GX) | y 递增 | 216×76 |

父节点坐标 = 其子节点在次轴上的**中点**，于是"父居中于子群"自动成立，不需要事后调整。

竖排卡片更窄，是因为同级可能十几个部门 —— 窄卡才能少滚一点。

### 4.2 连线：正交折线，不用贝塞尔斜线

同一层十几个部门时，斜线会从整张图上斜穿过去，看起来像"这两个部门有关系"，
**而实际上那只是布局坐标**。所以走直角母线：

```
父右中点 ──┬────────────  (层间通道)
           ├── 子1
           └── 子2
```

拐角用 `Q` 做半径 9 的圆角，避免生硬。

### 4.3 关系网：环半径由"标签总宽"决定

定长半径是这类图最常见的失败原因：16 个部门的标签会叠成一团，
而那**不是数据密，是布局没有把标签算进去**。

```
r[d] = max( r[d-1] + 156,                    // 不能压住内环
            Σ(本层标签宽) / 2π × 1.10,        // 沿圆周排得下
            168 )                            // 下限，否则第一环太挤
```

角度分配也一样：先按"每个标签自己那一份弧长"**保底**，剩下的角度再按
`1 + √(在编人数 + 子树人数)` 加权。纯按权重分时，0 人的小部门只分到 3°，标签直接压在邻居身上。

画布按内容包围盒裁（`viewBox` + 外层 `<g transform>` 平移），不留一大圈空白。

节点面积随人数增长用**开方映射**，不是线性 —— 线性的 1 人部门会变成一个看不见的点。

### 4.4 岗位页：卡片按部门分组

- 一张卡 = 一个岗位：名称 + 主管/外包徽章 + 在岗头像（叠压）+ 在岗人数与人名；
- **空岗是虚线卡**："有编制没人"和"这个岗位不存在"是两件事，不能长一样；
- 部门头部的进度条 = 该部门"岗位有人率"，回答"这个部门是不是整建制空着"。

## 5. 踩坑（都是真跑才暴露）

### 5.1 CSP：`style-src 'nonce-x' 'unsafe-inline'` 等于没有 `unsafe-inline`

按 CSP3，`nonce` 与 `'unsafe-inline'` 同时出现时，**`'unsafe-inline'` 被忽略**。
结果所有 `style="..."` 属性被拦。症状非常隐蔽 —— 页面不是一片白，而是：

- 分段器的滑块不滑动（`--i` 是内联变量）；
- 岗位头像没有底色（`background` 是内联的）；
- 部门头部的进度条永远满格（`width` 是内联的，失效后 block 撑满）；
- 表格缩进失效。

看起来只是"有点素"，不会报错。改法是**只要 `'unsafe-inline'`，不要 nonce**：

```
style-src 'unsafe-inline'
```

CSS 注入的危害与脚本注入不是一个量级，这是一条写明的取舍。

### 5.2 `background:hsl(68 58% 52%)` 在 style 简写里被判无效

空格分隔的 `hsl()` 在独立属性里没问题，但作为 `background` 简写值时被拒 ——
圆变成白底白字，肉眼看是"头像没颜色"。
改用传统逗号语法 `hsl(68, 56%, 48%)` 就没有歧义。

### 5.3 竖排不要自动"适应"

16 个同级部门，自动 fit 到画布会缩到 45%，字全糊 ——
**等于用"看得全"换掉了"看得清"**。
所以竖排首次进来保持 1:1，横向滚动，要全貌自己点「适应」。

### 5.4 `--window-size=390` 的 headless，实际视口是 500

用 `--headless`（旧模式）时窗口有最小宽度，截出来的图右边被裁，
看上去像"页面横向溢出"。判断有没有溢出只能看 `document.documentElement.scrollWidth`，
不能靠截图。这一条差点让我去改一堆本来没问题的样式。

## 6. 断言

| 断言 | 守的是 |
|---|---|
| UI9 | 部门页默认渲染树形图（卡片节点 + 正交连线 + 编制口径写在图上） |
| UI9b | 清单视图仍保留 编制/在编/缺编/含下级 四列（图形不替代表格） |
| UI10 | 关系网渲染出节点与曲线（不是一张空画布） |
| UI11 | 岗位页渲染岗位卡片，空库时给空态文案而不是白屏 |
| UI12 | 工具条上的竖排/横排是同一个滑动件（滑块 + 两个选项都在） |

UI9 数的是 `class="onode"` 与 `class="link"` 的个数，UI10 数 `circle.core` 与 `class="link2"` ——
**数元素，不是数"页面不为空"**。空画布也能让"页面不为空"为真。
