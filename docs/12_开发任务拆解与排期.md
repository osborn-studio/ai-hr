# 开发任务拆解与排期（供工程排期输入）

> 版本 v1.0 ｜ 2026-11-14 ｜ 阅读对象：研发负责人、项目经理、技术骨干
>
> **这份文件回答三个问题**：先做什么、什么东西不能先做、每一步做完怎么算做完。
>
> **这份文件不回答三件事**：报价、对外交付日期、人力承诺。人周数是**排期输入**，不是承诺值——把它当承诺值用，第一个变化就会让它失效，然后所有人开始不信它。
>
> **编号纪律**：顶层编号严格继承 `04` §11.3 的 `T01–T05`，本文只做**子任务细化**（`T01.1`…）与新增 `T00`（开工前）和 `T06`（上线）。**不新开一套编号**——两套编号并存时，说"T03 做完了"会没有确定含义。

---

## 0. 这份拆解的三个前提

| 前提 | 说明 | 如果前提不成立 |
|---|---|---|
| 一套部署服务一个集团 | 不做多租户、不做 SaaS | 多租户会让"单实例"这个前提失效，90% 的任务要重估 |
| 6 人团队基准 | 后端 2、前端 1、DBA/运维 1、测试 1、产品/设计 1 | 人少不是线性变慢，是**并行度下降**，见 §5 |
| 设计与实现分离 | 本文的验收判据来自各册条款，不是"跑通即可" | 若判据不认账，§9 的索引就是空文 |

## 1. 模块清单

后端 15 个模块 + 1 个前端工程。**模块数不是为了好看**：每个模块都是一条编译期强制的边界（ArchUnit 守着），跨模块只能通过接口。

| 模块 | 职责 | 被依赖 | 首个可演示切片 |
|---|---|---|---|
| `hr-common` | 统一响应、异常、枚举、脱敏注解、traceId、雪花 ID | 全部 | 一个 `/health` 返回标准响应体 |
| `hr-security` | 认证、三轴权限、`ScopeResolver`、`AuditAspect`、`FieldMasker` | 全部业务域 | 建角色 → 配数据范围 → 查列表只看到范围内数据 |
| `hr-domain-org` | `org_unit` / `version` / `headcount` / `attendance_group` | person | 组织树增删改 + 历史版本回溯 |
| `hr-domain-person` | `person` / `employment` / `contract` / `certificate` / `change_order` | worktime / payroll / leave | 花名册 + 入职单据 + 一人多段任职 |
| `hr-domain-worktime` | `shift` / `schedule` / `punch` / `daily` / `daily_store` / `segment` / `exception` | payroll / report | 排一天班 → 打一次卡 → 出人日与班段 |
| `hr-domain-leave` | `leave_type` / `quota_ledger` / `balance` / `request` | worktime / payroll | 请假申请 → 余额扣减 → 排班可见冲突 |
| `hr-domain-payroll` | `scheme` / `item` / `period` / `record` / `allocation` / `batch` / `si` / `tax` | report / mcp | 一张工资条，逐项可展开到工时来源 |
| `hr-domain-perf` | 绩效 | report | 一套考核方案跑完一轮打分 |
| `hr-domain-recruit` | 招聘 | person | 需求 → 候选人 → offer → 入职 |
| `hr-domain-learn` | 培训与考试 | person | 一门课 + 一场考试 + 证书 |
| `hr-domain-flex` | 灵活用工与外包协同 | worktime / payroll | 供应商账号登录只看得见自己的人 |
| `hr-report` | 指标字典、预聚合、报表模板 | mcp | 门店人效看板 |
| `hr-integration` | `IntegrationPort` + 设备/银行/电子签/个税/财务适配器 | 各域 | 模拟一台设备推一条打卡 |
| `hr-mcp-gateway` | 工具注册、Scope 映射、字段脱敏、plan 存储、确认闸、限流、调用审计 | — | `tools/list` 能列出全部工具 |
| `hr-mcp-stdio-bridge` | stdio ⇄ HTTP 桥 | gateway | 本地 AI 客户端连得上 |
| `hr-job` | 算薪批、导入、汇总刷新、Quartz | — | 手工触发一次算薪批 |
| `hr-boot` | 启动、配置、Flyway 迁移、镜像 | — | `docker compose up` 起全套 |
| `web` | PC 端 + H5 | — | 登录 + 排班板渲染 |

**一条不该省的纪律**：`hr-domain-*` 之间不许互相 `import` 实现类，只许依赖对方的 `api` 包（`xxx-api` 子模块或 `@NamedInterface`）。这条靠 ArchUnit 测试守，**违反时构建失败，不是代码评审时提意见**。

## 2. 硬依赖：这些不能并行

九条，每条都写清"为什么不能"——因为"不能并行"若不写理由，就会被当成排期保守而被打折。

| # | 依赖 | 为什么不能并行 |
|---|---|---|
| 1 | `hr-common` → 全部 | 响应体与异常契约变了，全部接口签名要跟着改 |
| 2 | `hr-security` → 全部业务域 | **权限不是横切面，是入口。** 先做业务后加权限，等于每个查询都要重写一遍 `WHERE` |
| 3 | `hr-domain-org` → `hr-domain-person` | 四维归属里的组织/成本中心/考勤组，全部是组织树的引用 |
| 4 | `hr-domain-person` → `hr-domain-worktime` | 排班对象是人；人日表的复合外键挂在 `(employee_id, work_date)` |
| 5 | `hr-domain-worktime` → `hr-domain-payroll` | 工资的输入是工时；工时口径一变，工资重算逻辑全变 |
| 6 | `hr-domain-leave` → `hr-domain-worktime` | 请假要冲抵排班与考勤，方向不能反 |
| 7 | `hr-domain-payroll` → `hr-report` | 指标字典里"人工成本""人效"的口径由薪酬定义，报表不能自己算 |
| 8 | 全部业务域 → `hr-mcp-gateway` | MCP 是**投影**，不是源头。先做 gateway 等于先写一层调不通的壳 |
| 9 | Flyway 迁移 → 全部 | 表结构先行；**但迁移必须可重复执行**（见 T00.1） |

**可以并行的三组**（排期时要真的并行，否则关键路径会白长）：

- `perf` / `recruit` / `learn` 三者互不依赖，且都只依赖 `person`；
- `integration` 的**接口定义**可以和 `worktime` 并行（先定 `IntegrationPort`，适配器后补）；
- `report` 的骨架（指标字典表 + 一个最简看板）可以和 `payroll` 并行。

## 3. 里程碑与出口条件

出口条件分两栏：**能演示**（给客户看的）和**能验证**（给自己看的）。只有"能演示"的里程碑不算完成——本项目最贵的教训就是"演示能过、上线会错"。

| 里程碑 | 内容 | 能演示 | 能验证（硬出口） |
|---|---|---|---|
| **M0** | 骨架 + 平台域 | 登录、建角色、配范围 | 三轴权限求值序正确；**无范围授权返回 0 行**；审计可查不可删 |
| **M1** | 组织 + 人员 | 架构图、花名册、入职 | 四维归属落库正确；一人多段任职不串；健康证过期阻断排班 |
| **M2** | 排班 + 考勤 | 划线排班板、异常处理 | 5000 格写入 < 1.5s；三日期字段各就各位；封账后补录只生成调整单 |
| **M3** | 假期 + 薪酬 | 算薪、工资条、分摊 | **与客户上月工资表逐人对平**；成本分摊恒等式；一人一期间一条记录 |
| **M4** | MCP + 扩展域 | AI 调工具、供应商账号 | 工具清单可列举；**无 `approve_*`**；两阶段写生效；供应商数据隔离 |
| **M5** | 验收与上线 | — | **空库建一遍通过**；压测达标；离线重算对账差异可解释 |

## 4. 任务表

### T00 开工前（3 个任务，合计约 2.5 人周）

| ID | 任务 | 交付物 | 验收判据 | 人周 |
|---|---|---|---|---|
| **T00.1** | **空库建一遍**：从零执行全部迁移，再执行一次全部迁移；**同一脚本内附六条 PG 行为 fixture**，并**按变更源门控分两批**——随 PG 版本变的（`RENAME` 后视图指向、`LIMIT NULL` = `LIMIT ALL`）按 `server_version_num` 门控；随我们 DDL 变的（入口函数重载数、`chk_ads_span` 是否报 `already exists`）每次构建都跑 | 一份执行日志 + 一份"重复执行结果" + 六条 fixture 的实测输出 + **每条 fixture 的"红过一次"记录**（改错 expected → 确认红 → 改回） | 第一次成功；**第二次也成功且无变更**（幂等）；六条输出写进日志；每条至少红过一次；另加**常驻阴性对照 `SELECT 1=0` 必须显示失败**（它若显示通过，说明 runner 不报红，全部结果作废） | 0.5 |
| **T00.2** | 五个冒烟实验（见 §7） | 每个实验一份结论（含"失败时的回退顺序"） | 五项全过；未过项必须写进 ADR 附录，不允许"先写着看" | 1.5 |
| **T00.3** | 目录、分支、CI、镜像基线 | 可跑通的 CI（构建 + ArchUnit + 迁移校验） | CI 里**迁移校验**这一步必须存在（空库建 + 重复执行） | 0.5 |

> **T00.1 为什么排第一**：它把"没验证"这个唯一不产生任何痕迹的动作，变成有痕的成败。这套设计里已经出现过两次"表在任何环境都建不出来"的问题（同一约束定义两次），都是靠人读出来的，不是靠跑出来的。**跑一次的成本是半小时，漏一次的代价是上线当天。**

**读数说明**：

- 77.5 人周 ÷ 6 人 ≈ **13 个月**（含并行损耗）。若要求 9 个月，需要 8–9 人，**不是"压缩任务"能解决的**——`T03` 与 `T04` 都在关键路径上且不能压缩，它们是"验证"占大头，不是"编码"占大头。
- 前端的工作量没单列：各里程碑里"前端并行"已计入后端人周之外，前端 1 人从头到尾是瓶颈。**建议前端不少于 2 人**，否则排班板这个交互密集页面会拖住 M2。
- 人周数不含需求变更。这个项目变更概率最高的三处：权限维度、排班规则、薪资项结构——**三者都在关键路径上**。

## 6. 每模块的第一个切片：为什么必须有

"先做完再做界面"是本项目最贵的错误模式：做完才发现口径错了，返工的是数据模型，不是界面。

| 模块 | 第一个切片（1–3 天内可跑） | 它能提前暴露什么 |
|---|---|---|
| `worktime` | 排一天班 → 打一次卡 → 出人日 + 一个班段 | 三个日期字段定义是否有歧义 |
| `payroll` | 一个薪资项、一个人、一个期间，算出一个数并**展开到工时来源** | 快照链是否真的能回溯 |
| `security` | 一个角色、一个范围、一张列表 | 四维 OR/AND 是否理解反了 |
| `leave` | 请一天假 → 余额减一 → 排班冲突可见 | 假期与考勤的交界在哪张表 |
| `mcp-gateway` | `tools/list` + 一个只读工具 + 一次 plan | scope 映射是否漏了字段脱敏 |
| `org` | 建三级组织 → 挂一个人 → 查历史某日归属 | SCD2 的区间开闭 |

## 7. 开工前必须做的五个冒烟实验

每个实验都要写"失败后怎么退"，否则实验本身会变成一场讨论。

| # | 实验 | 为什么必须先做 | 失败后的回退顺序 |
|---|---|---|---|
| **S1'** | `work_date` 四机制共存（触发器 + `CHECK` + 复合外键 + 列级 `REVOKE`） | 四件东西可能互相打架，且只在特定路径下打架 | ① 去触发器改应用写入（留 `CHECK` + 复合外键）→ ② 只剩 `CHECK`。**复合外键在任何回退方案里都保留** |
| **S2** | 权限求值序：数据 → 字段 → 功能 | 顺序错了症状是"少看到数据"，不会被当成 bug | 固定为单入口函数，禁止各模块自己拼 `WHERE` |
| **S3** | 划线排班 5000 格批量写入 | 决定批量写入是"多行 INSERT"还是"COPY + 临时表 + MERGE" | 降为分片提交（500 格/批），但**逐格结果必须保留** |
| **S4** | 公式 DSL 沙箱逃逸 | 一旦逃逸，等于给客户开了任意代码执行 | 收窄到白名单函数 + 无反射；再不行改规则表（放弃公式） |
| **S5** | 算薪 1 万人分片并发 | 并发下的幂等与重算是最容易错的地方 | 降为单线程分批（慢但确定），性能另想办法 |

> 五个实验合计约 1.5 人周。**不做这五个，后面每个里程碑都会多花两周去查"为什么数不对"。**

## 10. 排期纪律：三件不做什么

1. **不为了演示跳过权限。** 演示环境若不带权限，M1 之后每个页面都要返工加 `WHERE`。这是本项目最确定的一条返工来源。
2. **不先做界面后做约束。** 界面能骗过人，约束不能。所有数据模型的硬约束（唯一、外键、勾稽、区间）必须在界面之前落地。
3. **不在 M3 之前接真钱。** 工资条、代发报文、个税申报，这三条路径上线前必须走过一次"与人工核算逐人对平"，否则接真钱的那一刻就是风险敞口。
