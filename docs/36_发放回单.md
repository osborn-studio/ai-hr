# 36 · 发放回单

> 封账说"这批数定了"，发放说"钱到员工账上了"。以前系统只有前者。

## 1. 一个到不了的状态

`ck_pr_status` 允许 `draft / sealed / paid`，但全库搜下来只有 `sealed` 有路径。
`paid` 是个**永远到不了的状态** —— 也就是说：

> 钱发出去了，系统不知道。

"这个月工资发了没有"只能靠人翻银行流水和微信记录。这不是少一个字段，
是少一个**事实**。

## 2. 两件事必须分开记

| 状态 | 含义 | 什么时候 |
|---|---|---|
| `sealed` | 这批数定了，不再改 | 会签完成后 |
| `paid` | 钱到员工账上了 | 银行回单之后，可能隔几天、可能退票重发 |

合成一个状态就再也答不出"封了但还没发"这种情况 —— 而这恰恰是月底最常见的那几天。

## 3. 三条硬判断

**① 只有封账后能登记发放。** 没封账就发钱，等于按一份还会变的数发。
反过来，封了账没发，系统明确显示"已封账 · 待登记发放"。

**② 回单总额与工资表实发合计不一致 → 直接拒。**

```sql
IF p_total IS NOT NULL AND abs(p_total - v_sum) > 0.01 THEN
  RAISE EXCEPTION 'E_PAY_TOTAL_MISMATCH: 回单总额 % 与工资表实发合计 % 不一致（差 %）…'
```

这是发薪里最贵的一种错：差的钱会落到某个人头上，而**没人会主动说自己多收了**。
容差 1 分（银行按分入账），超过就一定是有一边错了。

**③ 不能重复登记。** 钱只发一次，状态也应当只改一次。

配套约束 `ck_pr_paid`：`(status='paid') = (paid_at IS NOT NULL)` ——
与 `ck_pr_sealed` 同一条规矩，状态与时刻同生同灭。不能出现"发过但不知道何时"。

## 4. 刻意不存银行账号

账号留在网银与代发系统里。HR 库里留一份完整账号库，是**最容易被整库拖走的东西**，
而它对算薪没有任何作用。

所以导出的是给财务在网银里逐笔核对的清单：

```
工号,姓名,部门,应发,实发
E001,张三,A店,8000.00,6500.00
...
,,合计,,13500.00
```

末行带合计 —— 财务不用自己按计算器，而按计算器的地方正是容易差一分的地方。

## 5. 表结构

```sql
ALTER TABLE pay_run ADD paid_at, paid_by, pay_method, pay_ref;
-- pay_method ∈ bank / cash / manual
```

`pay_ref`（流水号/代发批次号）是对账的唯一锚点：从这一串能回到银行原始凭证。

## 6. 断言

| 组 | 条数 | 钉住什么 |
|---|---|---|
| `PAYR1-6`（库） | 6 | 没封账不能登记；方式只认三种；总额不符被拒且状态不变；登记成功记全四个字段；重复登记被拒；`paid` 无 `paid_at` 被约束拒 |
| `PAYR1-6`（接口） | 6 | 清单人数/合计、不含账号；方式校验；总额校验；登记成功；重复 409；CSV 可下载且带合计行 |
| `UI33` | 1 | 发放卡写明"封账≠发钱""不存银行账号""回单总额要与实发对上" |

`PAYR3`（库）特意多断言了一条：总额不符被拒之后**状态仍是 sealed**。
只断言"报错了"不够 —— 有一种更坏的实现是"先改状态再校验"，报错回滚了但人会以为没发。

## 7. 踩过的坑

**约束写反了一个符号。** 第一版：

```sql
CHECK ((status = 'paid') = (paid_at IS NULL))   -- 错
```

对 draft 行：`false = true` → false → 加约束的那一刻整张表都过不去。
`ck_pr_sealed` 的写法是 `(status='draft') = (sealed_at IS NULL)`，照抄时把方向抄反了。
正确是 `= (paid_at IS NOT NULL)`。

**顺手修的两处界面债**（同一屏）：

- 工资条表格第一列原来只有 `employee_id`（1、2、3）——"这行是谁"是 HR 看这张表的第一件事。
  改成姓名 + 工号，查不到人才退回 `员工 #id`。
- 已封账后"算一次薪"按钮还写着"重算"，点下去只会报错。改成"已封账（重算需先重开）"并置灰。

## 8. 还没做的（留债）

- **退票/重发**：银行退回几笔时，现在只能整批改回 `sealed`（而 `E_PAYRUN_REOPEN` 拦着）。
  真要做需要 `pay_run_payment` 明细表（每笔一条状态），不是加个字段能解决的。
- **员工签收**：工资条签收是另一件事（员工端），不在这条链路里。
