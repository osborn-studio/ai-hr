# 47 · 工资单批量打包（按门店一次出全套）

> 单份打印解决的是"一家店出一张纸"，而月底的真实动作是**一次出十家店**：
> 点十次、另存十个文件、再手工打包。中间点错一次，就是把这家店的薪资
> 发给了那家店的店长 —— 而这个错不会报错，只会被某位店长看见别家的工资。

## 1. 这次补的是一个出口，不是一个页面

`/api/payroll/payslip-pack?period=YYYY-MM&per=1|2`：

```
GET /api/payroll/payslip-pack?period=2026-11&per=1
→ 200 application/zip
  Content-Disposition: attachment; filename="payslips-2026-11.zip"; filename*=UTF-8''工资单_2026-11.zip
  X-Pack-Files: 10        ← 包里几张单（= 有工资条的门店数）
  X-Pack-People: 137      ← 包里一共几个人
```

```bash
curl -sS -H "authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8080/api/payroll/payslip-pack?period=2026-11" -o 工资单_2026-11.zip
```

包里**只有**门店文件，没有清单文件、没有 README、没有 `__MACOSX`：

```
2026-11_A店.html
2026-11_B店.html
2026-11_示例餐饮（上海）_C店.html     ← 只有该期间有多个法人批次时才加主体前缀
```

每个 HTML 都是服务端渲染的、能直接打印或存 PDF 的一份单（与单份打印同一模板）。

## 2. 为什么是服务端 zip，而不是"前端攒十个 blob"

三个理由，第一个是合规，后两个是工程：

**① 前端攒包就要把十家店的数据先发到浏览器。** 那和"把全公司模板发给店长"
没有区别，只是把泄露点从文件挪到了网络响应里。这也是单份打印当初拒绝
"前端按部门筛"的同一条理由（见 `services/payslip-print.mjs` 文件头 ①）。

**② 权限只在服务端一侧成立。** 行闸（`fn_scope_people`）与字段掩码
（`fn_field_action`）读的是 `pg_temp` 里的范围表，浏览器里没有这些东西。
一旦打包移到前端，权限就必须在导出前"已经生效"，而"生效"这件事在前端
只能靠"我请求的时候记得带参数"—— 那是最容易被下一个人改坏的地方。

**③ 不新增依赖。** 这个仓库的依赖只有 PGlite 与 pg（`xlsx.mjs` 开头那段自述）。
zip 的**写**侧比读还简单：`node:zlib` 已经给了 `deflateRawSync`，剩下的是把
三段结构按顺序摆好 —— 本地文件头 + 数据、中央目录、EOCD（见 `app/zip.mjs`）。
多引一个 `archiver`/`jszip` 就多一条供应链、多一份 CVE 订阅、多一次"它升级了我们不敢升"。

## 3. 与单份打印**同源**：一条业务 SQL 都不另写

`services/payslip-pack.mjs` 里没有 `SELECT ... FROM payslip`。它做的只有：

```
pay_run（该期间的批次目录，只有日期/主体/id）
  └─ 每批 → payslip-print.sheet(tx, { runId, orgId: null, scene: 'export' })
              ├─ 行闸：fn_scope_people(期末)
              ├─ 法人闸：requireOrg(payroll_legal_entity)
              ├─ 掩码：fn_field_action(payslip, net_amount, scene)
              └─ 分组：按 cost_org（门店）
  └─ 每组 → payslip-print.html()（同一个模板）
  └─ makeZip()
```

理由不是"代码复用"，是**权限口径只能有一处**。两份口径必然不同步，
而不同步的那一天，通常是在审计报告里发现的 —— `71ce396` 那次验收就是
一口气抓出 4 处：导出忘掩码、跨法人工资条、四个接口没行闸。
第三个出口（zip）如果自己拼一条 SELECT，就是第 5 处。

## 4. 权限三处，逐条说清怎么"同口径"

### 4.1 行闸：`fn_scope_people()`

```sql
AND p.employee_id IN (
      SELECT employee_id FROM fn_scope_people(
        (date_trunc('month', to_date($2,'YYYY-MM')) + interval '1 month - 1 day')::date))
```

- 用 170 立的**唯一表达式**，不手抄 `EXISTS tmp_scope_org` —— 手抄漏一次不报错，
  只会让某个角色的包里多几个人。
- 日期取**发薪期末**，与"门店归属"用同一个日期表达式：补打上月单时，
  印的是上月所在的店，人也不会因为"这个月调走了"而从这张单上消失。
- 没有范围时 `fn_scope_people` 返回 0 行（fail-closed），不是"全部"。

### 4.2 法人闸：`requireOrg(payroll_legal_entity)`

一期可能有多个法人批次。A 店 HR 请求这一期时，**不属于他法人的批次被跳过**，
不是整包 403、也不是静默降级成"他只看到自己那批"（那会导致"包里少了一家店"
而没人知道为什么）：

```
{ "skipped_runs": [ { "run_id": 7, "legal_entity_id": 2 } ] }
```

跳过逻辑**不重写权限判据**：它只吞 `E_OUT_OF_SCOPE`，判断仍然发生在 `sheet()` 里。

### 4.3 掩码：`fn_field_action`，场景 `export`

| 出口 | scene | 为什么 |
|---|---|---|
| 页面 `/api/payslip` | `list` | 屏幕上看 |
| 单份打印 `/api/payroll/print.html` | `list` | 也是一个页面（可再点"打印"） |
| 发放清单 CSV | `export` | 文件会被转发 |
| **打包 zip** | **`export`** | 同上，而且是"整包发出去" |

掩码为 `masked` 时，金额印成 **「—」**，不是 `0.00`：0 会被读成
"这个人这个月实发 0 元"，一张写着 0 元的工资单拿给员工签字是要出事的。
合计也随掩码一起走 —— 掩了明细却给出合计，等于把总数漏出去。

> 演示数据里给了 `payslip.net_amount` 的 `export` 档（集团HR `visible`、A店HR `masked`）。
> 这一档**不配就是 fail-closed `masked`**（003 的规矩）：新加一个出口不会因为
> "忘了配"而默认可见。生产环境按岗位另配。

### 4.4 验过的两条

| 断言 | 验的是什么 | 结果 |
|---|---|---|
| PK4 | A店HR 的包里只有 A 店一份，文件名、人名、金额里都不出现 B 店 | `文件=2026-03_A店.html`；B店实发 7000.00 出现在包内 = false |
| PK5 | 看不到实发的人，包里那份是「—」；看得到的人那份是真值 | 集团HR `6,500.00` / A店HR `—` |

## 5. 空门店为什么**不出**文件

判据是"这个店在这一期有没有工资条"，**不是**"组织树里有没有这个店"。

- 没有工资条的门店生成一份 0 人 0 元的空单，唯一后果是：店长收到一张写着
  "0 人"的纸，然后打电话问财务"我店里的人是不是漏发了"。
- 反过来，"有编制、有人、但这一期没算薪"的门店必须**不**出文件 ——
  它是"这一期没这个店的钱"，不是"这个店没人"。PK8 专门造了这样一个门店
  （98 店有人有归属、该期无工资条）：包里仍然只有 99 店那一份。

所以文件数 == 该期间有工资条的门店数，而这条数是**从 `sheet()` 的 groups 里数出来的**，
不是从组织树里数的。

## 6. 文件名：能一眼看出是哪个门店、哪个期间

```
{期间}_{门店名}.html              单法人
{期间}_{主体名}_{门店名}.html      该期间有多个批次（多法人）时
```

门店名里的 `\ / : * ? " < > |` 与控制字符一律换成 `_`，名字首尾的点与空格去掉，
超长截到 60 字，撞名加 `(2)` 序号。

为什么较真到一个字符：**zip 里 `/` 是路径分隔符**。留着它，那家店的文件会落进
一个子目录，解压后"包里少了一份"—— 不报错、不告警，只有店长来问才知道。
PK7 用一家叫 `A/B店:"测试"*?<>|\` 的门店把这件事钉住：

```
2026-04_A_B店__测试_______.html
```

## 7. zip 写侧的三个坑（写在代码里，也写在这里）

| # | 坑 | 错了会怎样 |
|---|---|---|
| ① | CRC32 必须算**原始数据**，不是压缩后的 | macOS `unzip` 不校验、Python `testzip()` 会报 —— 而财务的 Windows 资源管理器直接说"文件已损坏"。这个错会一路发到别人的电脑上才暴露 |
| ② | 中央目录里的偏移指**本地文件头起点**，不是数据起点 | 解出来是乱码/截断 |
| ③ | 文件名必须是 UTF-8 且置 `0x0800` 标志位 | 中文门店名在 Windows 上变乱码 —— 而"文件名要一眼看出是哪个门店"是这个功能的全部意义 |

已知限制（写在 `zip.mjs` 里，不写"将来支持"）：

- **不写 zip64**：>4GB 或 >65535 个文件直接抛 `E_ZIP_TOO_LARGE` / `E_ZIP_TOO_MANY`。
  工资单打包远到不了这个量级，而写了就是一段**永远不会被执行**的分支。
- **macOS 自带的 Info-ZIP 6.00 忽略 UTF-8 标志位**（不是本包的问题：
  `ditto -x -k`、Finder、Python `zipfile`、7-Zip、Windows 资源管理器都正常）。
  在那种老 unzip 上要加 `-O UTF-8`。

## 8. 三个错各有名字

| 情况 | 码 | HTTP | 该做什么 |
|---|---|---|---|
| 期间不是 `YYYY-MM` | `E_PACK_PERIOD` | 422 | 改参数 |
| 该期间没有发薪批次 | `E_PACK_NO_RUN` | 409 | 去算薪 |
| 有批次，但我的范围里一个门店都没有 | `E_PACK_EMPTY` | 409 | 看权限/门店归属，不是改参数 |

合成一个码的后果：看到 422 的人去改参数，看到 409 的人去算薪 —— 而第三种
真正要做的是查"这个人为什么一个门店都看不到"。三个码的说明里都写清了去向。

## 9. 断言（`code/test/pack.mjs`，9 条）

| ID | 钉住的性质 |
|---|---|
| FX | 夹具全部建成（建不成的夹具会让"包里少一家店"看起来像功能正常） |
| PK1 | 包内文件数 == 该期间有工资条的门店数，且每张单对应一个人 |
| PK2 | 文件名含期间与门店名、`.html` 结尾、互不重名、无非法字符 |
| PK3 | 解出来的 HTML 与单份接口同源（主体/期间/签收栏/合计），且**每个条目 CRC 正确** |
| PK4 | A店HR 的包里只有 A 店（行闸） |
| PK5 | 看不到实发的人，包里那份是「—」（掩码不因换入口失效） |
| PK6 | 三个错各有业务码，都不落 500 |
| PK7 | 非法字符门店名被清洗，且不产生子目录 |
| PK8 | 空门店不产生空文件 |

测试自带一个 zip 读侧（不是复用 `app/zip.mjs` 的 CRC 表，而是逐位算一遍）：
"我生成了几段字节"只能自己跟自己对答案，**能按中央目录解回来、CRC 对得上、
内容一致**才算过。

### 这一段抓到的真 bug

第一版 `pack()` 直接把 `sheet()` 的整个结果递给 `html()`，于是 **A 店那份文件里
印着 B 店的人**（同一个包、同一批权限，但"发到店"的前提就是每家店只看到自己的那张纸）。
它不报错、PK4 也绿（A店HR 的行闸本来就只出 A 店），
是 PK1 数"签收栏份数 = 人数"时对不上（4 ≠ 2）才露出来的。

修法就是给每个门店 `{ ...d, groups: [g], totals: {...} }` 一个单店视图。

## 10. 判据登记（`db/171_payroll_pack.sql`）

这个任务没有 DDL —— 它加的是一个读接口与一个 zip 写出器。但两条判据要登记，
否则覆盖率页读不到它们：

| check_code | 守什么 | guard |
|---|---|---|
| `SUITE.ZIP` | 包的形状：文件数、文件名、能解、与单份同源 | `payslip_pay_run_id_employee_id_key`（同一人同一批次只能一张工资条，所以"按门店分组"不会因重复行凭空多一家店） |
| `SUITE.API-ZIP` | 权限口径：行闸与掩码在包里同样生效 | `fn_scope_people`（与 `SUITE.SCOPE-P` 同一处，写法也相同） |
