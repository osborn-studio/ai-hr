## 1. 工资项是数据，不是代码

```
工资项（salary_item）
├─ code        唯一代码（大写字母/数字/下划线，2–24 位）
├─ name        显示名
├─ item_kind   fixed 固定 | variable 浮动 | formula 公式 | statistic 统计
├─ formula     公式（空 = 不是派生项）
└─ sort_order  求值顺序（后面的可以引用前面的结果）
```

界面：**工资项**页签。点行载入、改完保存，下次算薪生效。停用不删历史（明细已经写进历史工资条）。

## 2. 公式语言

### 2.1 语法

```
表达式 := 数字 | 变量 | 函数(参数, ...) | 表达式 运算符 表达式 | ( 表达式 )
运算符 := + - * /  >  <  >=  <=  =  <>  AND  OR  NOT
变量   := 任意已启用的工资项代码
        | MONTHLY          月薪标准
        | COMMISSION       本期提成合计
        | PRESENT_DAYS     本期出勤天数（封账人日；未封账退回打卡去重天数）
        | WORK_DAYS        本期应出勤天数（制度 PAY_DAYS_PER_MONTH，默认 21.75）
        | LEAVE_DAYS       本期请假天数（各假种已批准之和，与事假扣款同源）
        | WORK_HOURS / OT_HOURS  实际工时 / 加班工时
        | SI_BASE          社保基数
        | TAX_THRESHOLD    个税减除费用
```

### 2.2 函数库（界面从 `fn_formula_funcs()` 直接读，不另抄）

| 函数 | 签名 | 用途 |
|---|---|---|
| `if` | `if(条件, 真值, 假值)` | 条件分支，编译成 `CASE WHEN` |
| `round` | `round(x[, 小数位])` | 四舍五入 |
| `ceil` / `floor` | `ceil(x)` | 上/下取整 |
| `abs` / `sqrt` / `power` / `mod` | 标准数学 | — |
| `min` / `max` | `min(a, b)` | **编译成 LEAST/GREATEST**（PG 的 min 是聚合函数） |
| `greatest` / `least` | 多参 | — |
| `coalesce` | `coalesce(a, b)` | 取第一个非空 |
| `max0` / `min0` | `max0(x)` | 封底/封顶到 0 |
| `prorata` | `prorata(金额, 实际, 应出)` | 按出勤折算；应出为 0 时**不折算** |

### 2.3 真实例子

```sql
-- 全勤奖：出勤满 21 天才发，金额是岗位津贴的 10%
if(PRESENT_DAYS >= 21, POST_ALLOW * 0.1, 0)

-- 餐补按出勤折算
prorata(600, PRESENT_DAYS, WORK_DAYS)

-- 提成封顶 8000 且不倒扣
max0(min(COMMISSION, 8000))

-- 高薪档位补贴
if(MONTHLY >= 15000, 800, if(MONTHLY >= 10000, 500, 200))
```

## 3. 三条安全线（少了任何一条，这就是数据库的 eval）

| 线 | 做法 | 为什么 |
|---|---|---|
| 字符白名单 | 只允许 `数字 字母 _ + - * / ( ) . , < > = !` 与空格 | 引号/分号/反斜杠一放开就是任意 SQL |
| 注释符显式拒绝 | `--`、`/* */` 直接 `E_FORMULA_CHAR` | `-` 是合法运算符，`1--2` 会被 PG 当注释，公式**静默变 1** |
| 函数/变量白名单 | 函数必须在 `fn_formula_funcs`，变量必须已登记 | 否则 `pg_sleep(60)` 会被当成一个"函数"跑起来 |

求值不是 eval：先校验 → 再**编译**（if→CASE、prorata→乘除、min/max→LEAST/GREATEST、max0/min0→GREATEST/LEAST）→ 变量替换成数字 → 动态 SQL 求值。

## 4. 导入：Excel / CSV

两种表，语义不同，必须显式选：

**A. 工资项目与公式**

```csv
项目名称,代码,类型,公式,排序
基本工资,BASE,固定,,10
全勤奖,FULL_BONUS,公式,if(PRESENT_DAYS >= 21, POST_ALLOW*0.1, 0),50
```

**B. 每人金额**

```csv
工号,姓名,基本工资,岗位津贴,餐补,通讯补贴
E0006,杨继勇,5500,1500,600,400
```

B 表导入后要**再点一次"应用"**：把每人的合计写成月薪标准、按列拆成工资结构。
把"导进来"和"发多少钱"分成两步，中间留一次人看得见的确认。

### 4.1 解析层（零依赖）

- `.xlsx`：`app/xlsx.mjs` 自己解 zip（zlib.inflateRawSync）+ 认 `sheet1.xml`/`sharedStrings.xml`。
  不装 SheetJS：多一个大包 = 多一条供应链、多一份 CVE 订阅。
- `.csv/.tsv`：`app/sheet.mjs`，处理 BOM、CRLF、引号转义、千分位、括号负数、末尾空行。
- **非 UTF-8 直接报错**（`E_IMPORT_ENCODING`）：猜编码猜错，乱码的项目名会真的建进库。

### 4.2 一行一结论

```
批次 #5 · 共 2 行 · 通过 1 · 未通过 1
 行 2  通过      NIGHT_ALLOW / 夜班津贴
 行 3  未通过    E_FORMULA_EVAL: 公式「POST_ALLOW+」算不出来（syntax error）
```

- 整批有错就**不写一半**：那样会变成"有人有数、有人没数"，而看不出来；
- 但错误行要留下来并带原因 —— 静默跳过更糟，少一个人不会报错。

## 5. 一个必须绕开的坑：事务里不能靠 catch 继续

导入是"逐行校验"，但 PostgreSQL 里**一条语句失败，整个事务就 abort**，之后所有语句都返回
`current transaction is aborted`。所以"try/catch 一下继续下一行"是行不通的。

解法：把校验包进带 `EXCEPTION` 块的 plpgsql 函数（`fn_formula_try`），块内失败隐式回滚到
savepoint，事务继续可用，错误文本作为**返回值**交出来。

同理，`fn_formula_try` 要做三步才够：

1. 字符/变量/函数校验（`fn_formula_check`）
2. 编译（`fn_formula_rewrite`）—— 参数个数到这一步才看得出来
3. **试算**（全 1 变量跑一次 `fn_formula_eval`）—— 语法不完整、除零、结果不是数字，到这一步才发现

少第 3 步的后果：`POST_ALLOW+` 这种公式能通过导入，直到算薪那天整批人算不出来。

## 6. 未做 / 已知边界

- ~~出勤天数变量固定 0~~ —— 已由迁移 102/103 接入（`fn_att_person_period`）。
  口径：出勤取封账后的人日；没有封账数据时退回打卡去重天数（不是主口径）。
  **不允许从参数传天数**：天数一旦能传，就会有人传一个"看起来对"的数，
  而工资与考勤从此有两个口径。
- **公式项不参与月薪拆分**：它是加项。混进拆分会让同一笔钱被拆一次、再算一次。
- **没有公式的版本历史**：改公式是就地改，旧工资条不受影响（明细已固化），
  但"三月份用的公式长什么样"查不到。要做得加一张 `salary_item_version`。
- **没有循环引用检测**：A 引用 B、B 引用 A 会按 sort_order 各取一次（A 用 B 的旧值）。
  不报错，但结果不是用户想的。要做需要拓扑排序 + 显式拒绝。
- **导入不认合并单元格**：合并单元格只有左上角有值，其余为空 —— 会在"行内某列为空"处体现。

## 7. 脚本：多行、中间变量、return

一个工资项可以写**多行脚本**（`097`）：

```
d = PRESENT_DAYS
full = if(d >= 21, 1, 0)
bonus = POST_ALLOW * 0.1
return bonus * full
```

规则：`名字 = 表达式` 攒中间变量 → 后面能引用 → `return 表达式` 给结果。
最后一行是表达式时等价于 return。`#` 或 `//` 开头是注释。

三条限制（不是懒，是边界）：

| 限制 | 为什么 |
|---|---|
| 没有循环 | 想循环的人其实想要规则；该类参数由系统提供（天数、次数），不该由脚本遍历数据 |
| 没有 IO / import | 薪资要可审计、可重复、可回滚 —— 能 import 任意模块的世界里这三条都不成立 |
| 中间变量不能与工资项同名 | 否则"读这一项"和"写变量"混成一个名字，值从哪来将无人说得清（`E_SCRIPT_NAME`） |

**这是"内嵌代码"，但不是 eval**：每一行仍然是白名单表达式，仍然被编译成 SQL 片段，仍然没有函数定义。

## 8. 计算规则（钩子）

表 `salary_rule`：`stage` + `formula`（命中条件，非 0 即命中）+ `action` + `message`。

| stage | action | 行为 |
|---|---|---|
| `before` | `block` | **算薪之前**当门：命中就挡住这个人，不生成工资条，但留一条命中记录 |
| `before` | `warn` | 算薪前命中只记录 |
| `after` | `warn` | 算完留一条提示（"实发为 0，检查结构"） |
| `after` | `block` | 同 warn（已经算完了，拦不住钱） |

例子：

```
if(GROSS > 50000, 1, 0)            # 应发超过 5 万 → before/block
if(NET = 0, 1, 0)                  # 实发为 0 → after/warn
if(SI_BASE > 36921, 1, 0)          # 社保基数超上限 → before/warn
```

两个设计判断：

1. **before 规则不在算薪函数里跑**，由服务层在算薪前统一预跑。
   因为在函数里 RAISE 会让整个事务回滚，刚写下的命中记录一起消失 ——
   结果"拦住了但没有任何痕迹"，而"这个人为什么没算出来"只剩一句 `E_RULE_BLOCK`。
2. **规则自身写错按 block 处理**。坏规则放行，等于把门焊死成通道，而没人会注意到门没了。

## 9. 给 AI 的接口

开放层（`/api/mcp/*`）新增四个工具，AI 可以自己闭环"读 → 写 → 试 → 改"：

| 工具 | 类型 | 用途 |
|---|---|---|
| `salary_items` | 只读 | 项目清单 + 函数库 + 内置变量 + 脚本语法说明 |
| `salary_formula_preview` | 只读 | 公式/脚本试算，**可给多组样例**一次看多档结果 |
| `salary_item_plan` | 两阶段写 | 新建/改项目；预览含：改前改后、试算值、**这个项已经出现在多少条工资条里** |
| `salary_rules` | 只读 | 规则清单 + 最近命中 |

`salary_item_plan` 的预览会明确警告：
"这个项目已经出现在 N 条工资条明细里，改语义会让历史对不上（建议新建一项）"。
AI 拿得到这条，就不会悄无声息地改掉一个已经发过钱的项目。

**为什么 AI 必须先试算**：模型写公式一定会错几次，而"改完直接算薪"是最坏的验证方式 ——
钱已经发了。试算让它自己闭环，人只在最后确认一次。

边界：AI **不能**直接改已发放的工资条（`payslip` 有封账冻结），
只能改"下一次算薪用什么规则"。这一点由 `payslip` 的冻结触发器保证，不靠提示词。
