# 节假日年度维护：缺口要自己说出来

> 记录日期：2026-11-15 ｜ 迁移 130 ｜ 断言 437 / 187 / 21

## 1. 125 留下了什么，缺了什么

125 把三种类型分清楚了（`legal` 300% / `rest` 200% / `workday` 上班），也留下页面上的增删改。
但真实场景是这样过的：

> 12 月 20 日算明年 1 月的薪 → 库里没有 2027 年的节假日 → 元旦被当成工作日
> → 那天上班按平日 **150%** 给（该给 **300%**）→ 少付，且**没有任何报错**。

"能维护"与"知道该维护什么"是两件事。这一版补的是后者。

## 2. 五种缺口，各自一条提示

`fn_holiday_year_check(year)` 返回 `(level, code, hint)`：

| code | 级别 | 什么情况 | 后果 |
|---|---|---|---|
| `HOL_NO_DATA` | **error** | 该年一条数据都没有 | 应出勤按纯周末算，法定日上班按 150% |
| `HOL_LEGAL_COUNT` | warn | 法定天数 ≠ 制度值（`PAY_LEGAL_DAYS_YEAR`，默认 11） | 应出勤偏高或偏低 |
| `HOL_NO_MAKEUP` | warn | 有"调休放假"却没有任何"调休上班" | 长假挪的周末没登记，应出勤少算 |
| `HOL_MAKEUP_WEEKDAY` | warn | "调休上班"标在了工作日 | 应出勤多加一天 |
| `HOL_UNCONFIRMED` | warn | 还有 `is_confirmed = false` 的行 | 数据没对着公告核过 |

只有第一条是 error：其余都会让数字偏，但偏得看得见；第一条是"整年空白"，
它不会让任何一条既有断言变红，只会让那个月的工资静默少付。

## 3. 骨架：只给公历能确定的，农历不猜

`fn_holiday_skeleton(year)` 只生成 **元旦 1/1、劳动 5/1、国庆 10/1–10/3** 五天，
全部标 `is_confirmed = false`、`source = 'skeleton'`。

**不做"从上年整年复制"**，理由很具体：

> 2026 的春节是 2/15，2027 的春节在 2 月上旬，星期也全变了。
> 复制过来会生成一整套**看起来正常、实际全错**的数据 —— 比空着更危险：
> 空着会被缺口检查抓到，错了不会。

春节、端午、中秋按农历，让 HR 对着国务院公告填。系统在这里的角色是**提醒**，不是**猜**。

## 4. 覆盖表：明年的事，今年就看见

`fn_holiday_coverage(from_year, years=2)` 返回每年一行：legal / rest / workday 天数、
待确认条数、状态（`ok` / `unconfirmed` / `missing`）。

政策页把它渲染成两个胶囊：

```
2026 年 · 法定 11 天 · 放假 22 · 调休上班 6      ← 绿
2027 年 · 没有数据                                ← 红
```

为什么放两行：**12 月才发现明年没数据就晚了**。那时 1 月的算薪已经按纯周末跑过一遍。

## 5. 断言钉的是什么

| 断言 | 钉的 |
|---|---|
| `HOLY1` | 2027 年空 → 直接 error（不是 warn） |
| `HOLY2` | 骨架只生成 5 天，全是待确认，且不含春节/端午/中秋 |
| `HOLY3` | 骨架可重复执行：已存在的日期不覆盖 |
| `HOLY4` | "待确认"是个状态：生成后报，确认后不报 |
| `HOLY5` | 法定 5 天 ≠ 制度 11 天 → 报（确认 ≠ 补齐） |
| `HOLY6` | 调休上班标在周二 → 报 |
| `HOLY7` | 有放假无调休上班 → 报 |
| `HOLY8` | 覆盖表：2026 ok（≥11 天）、2027 只有骨架 5 天 |
| `HOLY1–3`（接口） | 页面数据里带 `gaps` 与 `coverage`，不是只存在于库里 |
| `UI20` | 政策页同屏：年度胶囊 + 两个按钮 + 缺失提示 |

`HOLY8` 最初写成 `legal_days === 11`，跑出来是 12 —— 因为 `HOL` 组会往里插一条"测试用假日"。
改成 `>= 11`：断言应该钉"覆盖表对不对"，不该钉"有没有人插过测试数据"。

## 6. 这一轮踩的坑

| 现象 | 真因 |
|---|---|
| `structure of query does not match function result type` | `RETURNS TABLE(... hint varchar)` 而 `format()` 返回 `text`；varchar 不会自动匹配，报错读起来像列数不对 |
| 改了 `fn_holiday_year` 加两列 → 42P13 | 返回类型变了必须 `DROP FUNCTION` 再建（`CREATE OR REPLACE` 换不掉） |
| 接口 500，页面没胶囊 | 持久库**只在空库时跑迁移**（`if (fresh)`）；截图用的演示库是旧的，缺 130 —— 重建库才有 |
| `SUITE.API-HOLY 未登记` | 断言组名要先登记进 `sys_check_registry`，否则记录结论时被拒 |

## 7. 还没做的

| 项 | 为什么 |
|---|---|
| 农历节日的自动推算 | 农历表可以内置，但"国务院公告里的调休安排"永远推不出来。只推一半（日期对、调休错）比空着更危险 |
| 从外部接口拉当年公告 | 没有稳定公开接口；且公告是 PDF，解析错了没人看得出来 |
| 跨年"调休上班"落在别的月份 | 现在按 `holiday_date` 的年归类。2027-01 的调休实际可能由 2026-12 的公告决定，但落到哪个日期就归哪年 —— 只要日期本身对，应出勤就是对的 |
