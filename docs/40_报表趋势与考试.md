# 40 · 报表趋势与考试

> 两件"再往前一步"才出现的事。报表从一期变成一条线，多出来的不是图，是怎么证明线上的每一格与
> 报表上的那一格是同一个数。培训从到场变成学会，学时只证明人坐在教室里。

## 一、报表多期趋势

### 1. 单期快照答不出"在涨还是在跌"

055 的面板是"这一期"的快照：`as_of` 贯穿到底层，每个指标钉在一个时点上。这个设计是对的——它让
"三月的人数"只有一个答案；但它答不了"三月比二月多了还是少了"，那需要两个答案同时在场。146 补的
是 `fn_rpt_trend(p_org, p_from, p_to)`（`146_rpt_trend.sql:42`）：逐月一行，加两个环比列；接口
`/api/report/trend`（`server.mjs:3588`），服务层 `report-trend.mjs` 只有 77 行——薄是刻意的。

### 2. 口径同源：逐期调 `fn_rpt_panel`，不另写 sum

核心是一句 LATERAL（`146:112`）：`CROSS JOIN LATERAL public.fn_rpt_panel(p_org, per.per) pan`。
逐期调用面板，把那一期的字段原样取下来；不重算、不重写过滤条件、不重排时点基准。

**不这样会怎样：** "按月份分组再 sum"看起来只有一句，写起来比调函数顺手，于是旁边就多出第三份
口径。它和面板读同一批表，会**先一致、后分叉**——分叉发生在某次只给一处加过滤条件的时候（漏一个
`daterange` 闭区间、把期末归属写成期初、少 join 一次子树）。两边都"看起来对"，没有一处会报错，
只会有人说"为什么趋势图上的三月和报表上的三月不一样"——而那通常在有人已经拿着图开完会之后。代价
写在文件头（`146:17-19`）：每期一次面板、7 个指标，日均人数要逐日数。慢是明码标价的。

- **每期只调一次面板**（`146:105`），一个指标一个格子用 `max(pan.value) FILTER (...)`。写成
  "每期调四次"结果等价，但同期被算四遍，四遍之间任何差异都会变成一行里两个格子对不上。
- **面板没有的两列**（社保、个税）从工资条取，复用 `fn_rpt_payroll` 那条归属子句**本身**
  （`146:118-125`），只把数字换成 `si_employee/tax_amount`。工资条按「人归属的成本组织」汇总，
  跨法人借调时与「发薪法人」给出不同的数；两处一分开，趋势图上的社保与旁边的应发就不再来自同一
  批人，而两张图各自都自洽。守卫是 `net = gross − 社保 − 个税`（RT1）。

### 3. 没有数据的月份也出行

`generate_series` 铺出期间内每个月（`146:96`），`per` 是链的起点，所以每期必有一行。`has_data`
取 055 的 `fn_rpt_has_data`（`055:100`），false 时七列全 0，RT2 逐列核。

**不这样会怎样：** 跳过没算过的月份，折线把两个真实点直接连起来，图上就多出一段"掉到 0 又涨回来"
的斜坡——而那两段斜坡一天也没发生过。没人会去质疑一张"看起来有起伏"的图。配套一条：**值为 0 与
`has_data=false` 不互相改写**（`146:171-173`）——人数 0 可能是真算过（有人离职），不为 0 也可能
从没算过考勤（人还在编，只是没导）。压成一个数，丢的就是"到底算没算过"这一位。

### 4. 环比 NULL ≠ 0

三种"算不出"全部给 NULL（`146:191-198`）：第一期没有上月、上月没有数据、本月没有数据；百分比在
上月为 0 时是除零，也给 NULL（`146:199-206`）。**0 是持平，NULL 是算不出**——把算不出写成 0，图上
就凭空多一次暴跌后暴涨，和上一条是同一个错误的两个版本：把"没有数"当成"数是 0"。本月没数据时连
"−上月"那个数也不给：给了会被读成"这个月掉到 0"。

### 5. 行闸：趋势是"一整年"，比单期更该拦

```js
await requireOrg(tx, { userId, resource: RES, orgId, dim: 'cost_org' });
```

`report-trend.mjs:50`，维度和 `panel()` 一致。**不这样会怎样：** 任何登录账号换个 `org` 参数就能
读别人一整年的工资曲线。这比读单期更糟：单期泄漏的是一个点，趋势泄漏的是一条形状——规模、季节性、
有没有裁过员，一年之内全看得出来。行闸在服务层而不在 `fn_rpt_trend` 里，因为库函数不知道调用者
是谁；所以 RTA1 必须在接口层再验一次。

### 6. 断言

| 层 | 条数 | 钉什么 |
|---|---|---|
| 库 | 4（RT1–RT4） | 逐期同源、空月出行、环比 NULL、期间校验 |
| 接口 | 2（RTA1–RTA2） | rows + kpi、越权 403、期间写错 400（不是一排 0） |

- **RT1** 拿每期的 `fn_rpt_panel` 与趋势行四个字段逐一比，再核恒等式。区间定在 2027-07~12，因为
  2027-09/10 在成本组织 10 上有真实工资条（应发 8000、社保 1000、个税 500）——换成社保全 0 的
  月份，这条断言会绿得毫无意义。
- **RT2** 扫出一个确实没数据的月份，断它出一行、七列全 0；再断 6 期窗口正好 6 行且月份连续。
- **RT3** 断第一期 NULL，其余逐期对差额；上月为 0 时只断百分比是 NULL（差额是全额，不是算不出）。
- **RT4** 写反 → `E_RPT_RANGE`；37 期 → `E_RPT_TOO_LONG`；36 期正好放行（行数 = 36）。

## 二、考试

### 1. 只记学时不够

39 的四步链（课程 → 场次 → 到场 → 结业）对听课类培训是对的，对另外两类是错的（`147:5-9`）：安全
生产培训监管查的是"考没考过"，不是"坐了几个小时"；岗前培训签到了不等于记住了。只记学时，等于把
"人在教室里"当成"人会了"——页面上那句（`index.html:4704`）："没有考试，'学完了'就只是'人到了'。"

### 2. 四张表

`exam_paper` → `exam_question`；`exam_attempt` → `exam_answer`。一张卷多题，一次作答多行明细。

| 表 | 一句话 | 钉住的 |
|---|---|---|
| `exam_paper`（`147:39`） | 卷挂课程，及格线是这张卷的 | `pass_score` 不是全局的：安全考试 80 与入职 60 是两回事 |
| `exam_question`（`147:61`） | `kind ∈ single/multi/judge` | `answer` 是判分唯一来源；形状由 `ck_eq_ans` 查，顺序去重交给 `fn_exam_norm` |
| `exam_attempt`（`147:100`） | 一份卷一次提交 | `ck_ea_state` / `ck_ea_pass`（`147:109-112`）：没交卷就没分数，没分数就没及格与否 |
| `exam_answer`（`147:128`） | 选了什么、这题得多少 | `uk_exa_once` 一题一行；`picked` 与 `score` 分两列 |

**半个状态比没有状态更难解释**——与 `ck_pr_sealed`、`ck_te_done` 同一条规矩。

### 3. 五条判据

| # | 判据 | 落在哪 | 不这样会怎样 |
|---|---|---|---|
| ① | 判分在库，前端只交"我选了什么" | `fn_exam_submit`（`147:417`），`score` 由函数填（`147:420`） | 接口收分数，改一个参数就能及格，而这分是给监管看的 |
| ② | 多选完全一致才得分 | `v_pick = q.answer`（`147:417`） | 给部分分，4 个选项全勾每题至少拿一半，几道题就攒够 60 |
| ③ | 交卷后不可改、不可重交 | `E_EXAM_SUBMITTED`（`147:217`、`240`） | 已经当证据用出去的分数还能改，等于允许把交出去的改漂亮 |
| ④ | 答案不下发 | `fn_exam_paper_for` 无 `answer` 列（`147:304`） | 答案随卷进浏览器，按 F12 就看到，而线上监考做不到 |
| ⑤ | 结业 = 学时够 + 考过 | `E_TR_EXAM_REQUIRED`（`147:505`） | 学时够就算学完，安全培训"考没考过"这一问永远答不上来 |

- ①的配套是 `fn_exam_norm`（`147:146`）：写入与判分**共用这一份**规范化；两处各写一遍，不同步的
  那天正确作答的人会得 0 分，而且不报错（EXAM1 里多选写成 `"B,A"` 也算对）。
- ③是两道闸：`fn_exam_answer_guard`（`147:206`）管明细，`fn_exam_attempt_guard`（`147:232`）管
  答卷本身且**只看 `OLD`**（`147:237-239`）——`fn_exam_submit` 自己那次 UPDATE 的 OLD 是"未交卷"，
  必须放行；按 NEW 判会把判分函数拦在门外。要重考就再发一份卷，只禁止改历史。
- ⑤是 `CREATE OR REPLACE` 了 144 的 `fn_training_attend`，原件照抄只加一段（`147:452-457`）：结业
  判据一旦有两份实现，两条规则迟早各自漂。学时不够仍返回 `attended`（144 的老行为）。**不写"先置
  attended 再报错"**（`147:502-504`）：同一条语句里 RAISE 会把那次 UPDATE 一起回滚，是死代码；而
  "去了但没考试"的记录将来会被当成结业证据。

### 4. 一个刻意的顺序

**① 先整体校验，再动数据**（`147:366-385`）：参数是数组、每个 `q` 属于这份卷、同一题不许出现两次
——全部查完才写第一行 `exam_answer`。半份答案落库比整份被拒更难解释：调用方会重试，而那时已落库的
行还在。

**② 明细先落、总分后落。** 逐题 `INSERT exam_answer`（`147:420`），循环结束后才
`UPDATE exam_attempt SET submitted_at, score, passed`（`147:433`）。反过来不行——先把
`submitted_at` 盖上，紧接着的 INSERT 就会被自己的闸拦下（`E_EXAM_SUBMITTED`）。第 433 行是**全库
唯一一次写分数**的地方：它是"盖章"，不是"开始"。

### 5. 两份不做

**① 题库分类与难度。** 不打标签、不分难度、不随机组卷——那是 LMS 的活。

**② 防作弊（切屏、限时、摄像头）。** 线上监考做不到，做半个会更坏：让人以为系统在监考。

### 6. 断言

| 层 | 条数 | 登记码 | 位置 |
|---|---|---|---|
| 库 | 4（EXAM1–EXAM4） | `SUITE.EXAM`（`147:536`） | `run.mjs`，法人 995 独立造数 |
| 接口 | 3（EXAM1–EXAM3） | `SUITE.API-EXAM`（`147:540`） | `api.test.mjs`，四步全走 HTTP |
| 界面 | 0 | — | 见下 |

- **EXAM2 多断一条阳性对照**：报错后 `picked` 仍是 `'B'`——只断"报错了"不够，更坏的是"先改再校验"（同 TRN5）。
- **EXAM4 断三段**：学时 8/8 但没考 → 报错；状态**不是** `completed`；补考过再记一次到场 →
  `completed`。"去了但没考过"的记录若落成 `completed`，将来就是结业证据。
- 接口侧编号写 `EXAM` 而不是 `EXA`：收口块按 id 前缀拼登记码（`api.test.mjs:3054-3058`），`EXA1`
  拼出 `SUITE.API-EXA` 会被 `fn_chk_record` 以 `E_CHK_UNREGISTERED` 拒写，而那个异常没有 catch，
  整个接口册当场挂掉。变量名还留着 `EXA_COURSE`，编号不能动。

**界面这一行是 0，要写清楚。** 考试卡与培训三块在同一屏（`index.html:4662` 起），但 UI36 只钉了
培训那三块与"还没做"不能再出现（`ui.test.mjs:595`）。"分数不由前端传"这些文案在页面上却没有一条
断言守着——本篇唯一一处"写了但没钉住"的地方。
