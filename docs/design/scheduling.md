# 天意HR高级排班完整设计

版本 V1.0　2026年11月16日

本文件供产品负责人评阅，并作为界面、规则、数据、审批和验收的共同开发规格。范围为餐饮集团高级排班，包含与人员、假期、打卡、考勤、薪酬及外包服务的接口。设计依据是鸿欢原白皮书、功能比对表、餐饮方案、视频实操、WorkBuddy已有设计和用户明确补充。

本文件交付的是详细设计，不表示天意系统已经实现以下全部功能。上一轮V6为整体差距核查；高级假期仍需独立详细设计，本文件明确其全部排班接口和待细化范围。所有示例采用天意集团、香香鱼米、大富烤肉及虚构人员，不复制原材料中的人员数据。

## 阅读指引

负责人先看第1至3章了解边界和工作台，第4至6章核对手动画线、Ctrl拖拽复制及手机操作；第7至12章定义排法、规则、发布和业务申请；第13至17章说明人事假勤薪酬联动、权限和异常；第18至22章供开发和验收逐项执行。附录A逐项映射50项来源能力，附录B列出假期独立设计范围，附录C记录视频与原件阅读覆盖。

## 1 产品边界与完成条件

### 1.1 产品目标

排班员能够按人员、班组、班次、岗位技能安排多人多日的工作，直接在时间轴手动画出临时班段，也能复制已有班次、按周期生成、导入表格。员工能在手机查看并申请调班、互换、替班和支援；主管能审批。发布后的排班与假期、实际打卡、工时确认和工资来源保持一致。

排班工作台使用统一人员和组织资料。集团、品牌公司、门店仍按各自范围管理；同一自然人在不同品牌或门店的雇佣及服务关系分别保存，冲突按永久人员身份合并检查。

### 1.2 本次明确要求

- 手动画线生成任意合法时间段，临时班次不必预先建模板；可设置休息、颜色和名称。
- 班段可编辑、平移、拉伸、拆分、删除草稿、撤销重做，复制一个或多个班段。
- Windows与Linux按住Ctrl拖动班段执行复制，Mac按Option拖动；普通拖动执行移动。复制粘贴同时支持键盘及按钮，手机有对应可触操作。
- 按人、班组、班次、岗位技能、周期和Excel导入共用一天多班与跨午夜能力。
- 规则、权限、发布审批、员工申请、跨店支援、考勤薪酬和手机页面都有可执行的行为定义与验收用例。

### 1.3 完成条件

每项能力必须有页面入口、操作反馈、保存规则、失败结果、权限、生效状态和验收证据。只存在数据库字段、接口、静态演示或菜单入口均不算完整完成。自动提醒与到期回归必须有任务执行、失败重试和结果记录，不能只保存开关。

## 2 概念与业务归属

| 概念 | 本设计中的定义 |
|---|---|
| 人员 | 同集团永久身份，用于识别跨品牌多门店同一自然人 |
| 雇佣或服务关系 | 班段工作的依据，区分直营劳动关系、第二份独立雇佣、外包服务和临时支援 |
| 任职 | 某期间在公司、部门、岗位、档口、职级的有效安排 |
| 考勤组 | 规则、人员范围、日历、班次和负责人构成的考勤管理范围，不等于公司或雇主 |
| 班组 | 在具体雇佣或服务关系及考勤组中一起排班的人员集合，成员有有效期间 |
| 班次版本 | 可重复引用的班次定义，可含多个工作区间和休息；历史发布班段引用确定版本 |
| 临时班段 | 在某日手动画出或输入的工作安排，可不关联标准班次模板 |
| 排班方案 | 门店或考勤组在指定日期范围的排班草稿及修订版本 |
| 排班发布 | 将核准方案版本对员工及业务正式生效，不等于保存草稿 |
| 计划工时 | 排班跨度扣除按规则计入的休息后形成的计划工作时间 |
| 实际工时 | 由原始打卡、核定与异常办理计算的时间，不由排班直接认定 |
| 计薪工时 | 由地区规则、审批、考勤确认和封存得到的薪酬输入 |

### 2.1 四种归属分别保存

每个班段保存雇主及雇佣、实际工作公司及门店、部门岗位档口、考勤规则归属、成本承担、计薪归属。日汇总只是多班段聚合，不能因“一人一日一行”而强迫所有班段属于同一份雇佣。

例如周嘉禾上午依据香香鱼米A店雇佣工作，晚上依据另一公司独立兼职雇佣工作，两个班段分别归属。若只是A店派到B店临时支援，则保留A店劳动关系，工作地点和成本承担按支援单记录，不伪造B店入职。

### 2.2 时间与区间

业务时间精度为分钟，所有区间使用包含开始、不包含结束的定义。09:00–12:00与12:00–16:00不属于时间重叠，仍需检查休息及通勤规则。存储同时保留绝对时间、工作地点时区及归属工作日；界面明确本地日期及次日标记。

跨午夜班保留原归属工作日，并按自然日期切分用于节假日、加班及成本计算。跨月不得把月底之后的部分丢掉。演示内地和香港分别配置地区、币种、时区，不按品牌名称猜测，也不把旧演示单段16小时限制当作法律或永久产品限制。

## 3 角色与排班工作台

### 3.1 角色职责

| 角色 | 可办理事项 | 数据范围 |
|---|---|---|
| 集团HR总监 | 共享规则、集团跨品牌统筹、授权内排班和争议处理 | 本集团全部授权公司 |
| 公司HR总监或HR | 维护本公司适用政策、审查排班及人事影响 | 授权公司及下属 |
| 排班经理或店长 | 建草稿、安排人员、提交、按权限发布及处理申请 | 所管门店或考勤组 |
| 班组长 | 按授权调整班组草稿，处理本组建议 | 授权班组，不因此获得规则修改权 |
| 员工 | 本人排班、申请、确认；开启自排时提出本人班段 | 本人，不直接改他人或跳过审批 |
| 供应商服务负责人 | 查看及提交本供应商授权服务人员的排班建议 | 合同及派驻范围 |
| 薪酬专员 | 查看封存工时与来源、提出核对事项 | 薪酬授权范围，不默认拥有排班修改权 |
| 系统管理员 | 系统参数、角色和接入配置 | 不因配置权限直接办理HR业务 |

### 3.2 工作台布局

顶部为组织与考勤组、日期、人员维度、视图切换和方案状态；工具栏为画线、套班、选择、复制粘贴、撤销重做、校验、保存和发布。左侧固定人员姓名、岗位及工时摘要，中间为可缩放时间轴或周月网格，右侧为编辑抽屉、冲突清单或需求缺口。画布内部滚动，操作栏保持可见，详情不在页面底部无限堆叠。

日时间轴用于精确安排小时分钟；周视图用于看多人连续日期和多班；月视图用于周期、排休、覆盖和统计。日周月不是不同数据源，切换后使用同一草稿版本。

人员、班组、班次、岗位技能是呈现维度；套用、手画、周期、复制、导入是生成方式；一天多班是共用能力。这些不得设计成互斥的“七种模式”下拉框。

### 3.3 显示及状态

未排班、明确休息、已批假、待批假、缺勤分别显示。缺勤由实际考勤判定，不能把未排班自动画成旷工。颜色由班次设置，状态另用图标、边框及文字表达，保证颜色相同也能区分。

每个班段显示起止、次日、工作门店、岗位档口、休息及净工时；多段可展开。工时摘要区分已排计划、已发生实际、待审批占用、可用余量，不合成一个含义不清的“总工时”。

## 4 手动画线的完整交互

### 4.1 进入与创建

用户切换日时间轴，选择“手动画班”。横轴显示小时和分钟刻度，纵轴显示人员或岗位。在某人空白时间处按下主鼠标键，左右拖动，实时出现半透明班段；松开后进入“新增临时班次”抽屉。此时尚未写入正式排班。

预览随指针显示开始、结束、总跨度、预计休息及净工时，并显示规则预警。不得要求先选择标准班次才能划线；可在保存后另选“存为班次模板”，该操作需要模板维护权限。

示例：在周嘉禾一行从10:00拖到14:00，生成临时班段；再从17:00拖到21:00，生成第二段。中间空档不算工作。两段分别设置岗位和休息，同日允许多段，但必须共同参与工时和冲突检查。

### 4.2 时间精度及吸附

| 参数 | 天意设计决定 |
|---|---|
| 存储精度 | 1分钟，不保存任意秒作为排班时间 |
| 网格显示 | 小时主刻度，随缩放显示5、15或30分钟细刻度 |
| 画线吸附 | 默认15分钟，可在政策允许集合1、5、10、15、30、60分钟中配置 |
| 吸附算法 | 起止各吸附到最近合法刻度，正好居中时取较早刻度；实时显示最终时刻 |
| 数值输入 | 可精确到分钟；若政策强制时间步长，明确提示不合法而非静默取整 |
| 最短班段 | 由适用政策配置；零时长不能创建 |
| 时间窗 | 单日可展开至次日或滚动48小时，超过窗口用日期时间编辑，不猜跨日 |

反向从14:00拖到10:00时归一为当日10:00–14:00，并明确预览。若需要22:00–次日02:00，必须在可见次日时间轴继续拖，或在抽屉明确选择结束日期/次日。向左拖动不会自动解释为24小时夜班。

### 4.3 临时班次字段

| 字段 | 规则 |
|---|---|
| 人员与工作关系 | 默认当前行；多份关系时必须选择具体雇佣或服务关系 |
| 名称及颜色 | 名称可使用政策默认值，颜色可选，历史发布快照保留原值 |
| 起止日期时间 | 开始早于结束；必须在有效雇佣、任职及排班范围内 |
| 实际门店及部门 | 默认工作上下文；跨店必须有有效支援或另一雇佣依据 |
| 岗位档口 | 使用目标工作日有效配置，检查岗位技能和证照 |
| 休息 | 可按自动规则生成或手工设置；手改需权限，显示差异和依据 |
| 归属及备注 | 计划工作日、考勤、计薪、成本归属可见，修改按权限限制 |

### 4.4 调整班段

选中班段后显示两端手柄：拖左端改开始，拖右端改结束，拖块中部平移而保持跨度；抽屉可输入准确时间。休息明确分为相对班段起点的区间、当地绝对时刻区间、仅扣分钟规则。相对区间随班移动；绝对区间按目标当地日期重建并与目标班相交；仅扣分钟按目标政策重算。三者不能共用含义不清的“固定休息”。

拆分在指定分钟将一个班段分为两个，二者继承来源及关联但各自可编辑；休息重新分配，禁止重复扣除。合并仅限相邻、同工作关系与归属且没有打卡、申请或封存冲突的草稿段，合并前显示休息及工时变化。

右键班段可编辑、复制、设置休息、拆分或删除；手机以长按菜单替代。删除未发布草稿段可撤销；已发布班段必须创建取消或变更版本，不允许静默删除。

### 4.5 取消撤销及误操作

Esc、点击取消、指针捕获丢失或窗口失焦均取消当前未提交拖动，源数据不变。顶部撤销重做按本次草稿编辑序列执行；Ctrl+Z或Cmd+Z撤销，Ctrl+Shift+Z或Cmd+Shift+Z重做。撤销已保存草稿需形成新修订并重验；已提交审批或发布后不能用本地撤销改历史。

画线一次只作用当前人员行。跨行拖动不自动给其他人排同一班；多人操作必须显式选择人员及时间范围，查看批量预览后提交。

## 5 复制粘贴与Ctrl拖拽复制

### 5.1 操作语义

| 操作 | Windows与Linux | Mac | 结果 |
|---|---|---|---|
| 平移班段 | 普通拖动块中部 | 同左 | 目标提交成功后移动，源位置移除 |
| 复制班段 | Ctrl加拖动块中部 | Option加拖动块中部 | 源班段保留，目标生成独立草稿段 |
| 复制粘贴 | Ctrl+C及Ctrl+V | Cmd+C及Cmd+V | 粘贴到选定人员及时间锚点，先预览 |
| 剪切粘贴 | Ctrl+X及Ctrl+V | Cmd+X及Cmd+V | 仅草稿可剪切，目标成功后才移除源 |
| 批量复制 | 选择多个班段后复制 | 同左 | 保留段间相对日期时间与间隔 |
| 跨日复用 | 复制到次日、下周或指定日期 | 同左 | 使用目标本地日期重建安排并重新校验 |

班次库模板的“复制模板”与班表上的“复制已排班段”分开。复制模板产生新的编码和版本；复制班段不会自动新增模板，也不会共享可变数据使后续一改全改。

### 5.2 Ctrl拖拽复制的操作过程

选中一个或多个班段，按住Ctrl从块中部拖起，光标出现加号，源块保持原位，半透明副本跟随指针。目标行和日期时间高亮，预览明确标“复制”，列出将新建的班段数量、起止和净工时。松开鼠标后进入目标确认抽屉；确认时一次保存目标副本。

单班段落点以指针抓取点保持相对偏移，避免拖起块中部后起始时间突然跳到指针位置。多选时以本次实际抓取的班段为锚点，保留抓取点偏移；其他段保持相对日期、时间距离和人员行偏移，不以选择先后另取锚点。拖过画布边缘时缓慢自动滚动，时间轴可滚到次日；边缘停留期间显示目标日期，避免复制错天。

拖动中按下或松开Ctrl时可在“复制”和“移动”间切换，预览、光标及源块状态同时更新。以松开指针时的修饰键状态确定操作，确认抽屉再次显示操作类型。Mac不把Control右键当复制。

### 5.3 复制目标与冲突

可以复制到同一人员的另一时间、另一日期，也可复制到有授权的另一人员。目标人员必须重新选择或匹配其有效雇佣、岗位资格及归属，不能把源人员的雇佣编号带给目标人员。跨店目标仅在用户有两端权限且存在合法工作依据时可用。

多人复制冻结源人员行的稳定编号与顺序，以抓取行到目标行的位移建立默认人员映射；不把所有人的段都复制给一个人。筛选、排序或分页导致目标缺行时，必须显示源到目标的显式映射表，用户补齐后才能提交。允许用户另选“一组段全部复制给同一人”，但需明确目标并逐段检查重叠。跨公司目标无法唯一确定工作关系时阻断待选，不自动套第一份关系。

同一人完全相同时间的复制默认判为重复或重叠，阻止保存；不合并工资和工时来掩盖重复。目标已有班段时，默认追加并校验；“替换选定目标”必须另选、展示将被移除的草稿段并有权限。不得因按Ctrl自动覆盖已有班次。

复制不带原人员打卡、审批结论、工资结果、确认签名或历史异常。目标重新计算日型、休息、资格、工时上限和规则版本；复制后新段保留源段编号用于审计，但独立编辑。源休息是否允许沿用取决于目标政策；相对区间重建，绝对窗口按目标日重算，手改扣休若不再被目标政策允许则提示并要求重新确认，不能静默保留。

### 5.4 批量与剪贴板

支持单段、多段、某人某日全部班次、多人多日区域、整周和周期模板复制。跨日期粘贴使用相对日期偏移；遇跨时区时明确按目标当地时刻或绝对时间复制，默认目标当地时刻，确认页显示转换差异。

内部剪贴板保存结构化班段，外部文本按导入规则解析，不执行脚本。剪切先标记待移动，网络错误、无权限、冲突或取消时源段不删除。批量预览列出新增、替换、跳过和阻断，用户明确选择“仅提交可用项”才允许部分提交，提交后保留逐项结果。

### 5.5 关键验收

Ctrl拖10:00–14:00至15:00–19:00后，应同时存在原段和新段；普通拖动则仅在目标成功后保留新位置。Ctrl复制到另一人时，源人不变，目标关系重新校验。释放Ctrl、Esc、拖出可用区域或目标冲突均不得误删源班。键盘复制、工具栏复制和手机复制应得到同样结果。

## 6 手机排班与员工页面

手机首页显示本人今日及后续班次、工作门店和档口、待确认申请与提醒。店长入口提供人员搜索、班组与班次切换、日周视图、工时摘要和缺口。长名单分页或虚拟列表，不将整月所有员工挤进一屏。

手机手动画班先进入明确的“画班模式”，单指在人员时间轴拖出区间；普通浏览模式保留滚动。长按班段打开编辑及复制菜单，拖动手柄调整时刻；手柄有效触控区域至少44像素。提供起止时间选择器，缩放困难或精细到分钟时可直接输入。横向时间轴在画布内滚动，页面主体不溢出。

手机复制使用“复制班段→选目标人员和日期时间→预览确认”，不依赖键盘Ctrl。支持同一天复制第二段、复制次日及多日；跨人跨店仍检查权限及工作关系。员工自排默认为建议草稿，由政策决定是否需主管批准；不能直接覆盖已发布安排。

员工申请、对方确认、主管审批、证明附件上传、撤回及查看审批进度都有手机页面。审批详情同时展示变更前后班表、工时、冲突、成本归属和本人需确认事项，不仅提供“同意”按钮。

## 7 标准班次临时班次与休息规则

### 7.1 班次字段与版本

班次包含编码、名称、颜色、适用公司及考勤组、地区、有效起止、工作区间、休息方式、打卡要求、跨日归属和状态。一个班次模板可以展开多个工作段；同日可引用多个班次。标准模板修改产生新版本，已发布安排继续保留原版本，未来草稿可选择升级并预览差异。

总部可以共享班次，品牌公司受控引用或另建。停用模板不删除历史；已有未来安排需提示迁移。临时班段可另存模板，但不能让复制临时段改变集团标准。

### 7.2 休息计算

| 类型 | 计算与校验 |
|---|---|
| 相对区间休息 | 保存相对班段起点偏移，复制或平移时随新起点重建，再求交集合并 |
| 当地绝对时刻休息 | 按目标日期及时区重建固定窗口，与班段求交，不能一律随班平移 |
| 按跨度阈值扣休 | 达到阈值扣指定分钟，按互斥或累进规则配置，界面明确是哪一种 |
| 分段间隔 | 两个班段之间空档不算工作，也不再作为段内休息扣一次 |
| 有薪休息 | 作为休息事实保存，是否扣计划或计薪按适用政策分别决定 |
| 自动休息 | 创建或移动后重算；允许手改与否由权限和政策控制 |

总跨度、休息分钟、计划净工时分别显示。任何扣休不得使净工时为负；休息跨出班段、相互重叠、被拆分重复计算必须给出具体错误。只有总扣休分钟而没有位置时不能凭空生成精确休息时刻用于打卡判断。

### 7.3 未排班与打卡

政策分别配置未排班是否可打卡、是否允许选择班次打卡、如何自动对班、是否需主管核定。自动对班输出候选和依据；无法唯一匹配则进入异常待办，不擅自把打卡变成排班，也不删除无法匹配的流水。

## 8 各种排班方式与批量处理

### 8.1 按人员班组班次与岗位

按人员在日期格套用一个或多个班次，或进入时间轴手画。按班组可整组套班并展开成员，批量结果仍按每人资格和日期校验。按班次点击某日班次格选择人员，显示需求人数、已排和缺口。按岗位技能先定义岗位需求，再选择合格人员，确认后同步形成真实班段，不能只是筛选岗位。

班组属于考勤组，成员归属按具体雇佣或服务关系及有效期间管理。同一关系同一时间仅一个主班组；同一自然人在另一公司有另一有效关系时可以属于那里的班组。转组保留历史，不能使用“最后一次修改覆盖全部过去”的方式。

### 8.2 周期排班

周期定义长度、每个周期日的多个班次或休息、相位锚点及适用考勤组。套用时选择起止日期和人员班组；默认从所选日到当月末，符合原规格；可选跨月持续，并明确下月延续原相位或重新起算，保存锚点而非按月猜测。

遇请假、禁止改排休、无有效雇佣、临时支援、封存或资格问题，逐人逐日预览原因。半日假默认跳过整个人日；仅在明确选择“按请假区间切分”、政策允许且预览确认后生成剩余工作段，并重新计算休息和需求缺口。默认受影响的人日作为原子单元，该日多段共同成功或共同跳过；整张方案可选择全量失败即回滚。用户明确确认跳过清单后才提交，跳过不改变周期后续相位。

### 8.3 周月网格及批量

周月表支持单元格选择、Shift扩展连续区域、框选多人多日、按班次涂刷、复制次日下周及指定区间。Ctrl拖动已有班段用于复制；Ctrl在空白选择区的含义不与班段复制混淆，工具栏显示当前“选择”“套班”或“画线”模式。

批量套班、排休、清空、复制、应用周期都先显示受影响人数、人日和班段。排休修改单独鉴权。清空未排班格不生成休息；清空已发布或封存记录被拒绝并引导变更。

### 8.4 Excel导入导出

导出范围可按组织、考勤组、期间，包含稳定人员编号、雇佣或服务关系、日期、每段起止、次日、班次版本、岗位档口和休息。导入支持修改导出的文件和标准模板，一天多段用明细行，不以姓名作为唯一匹配键。

导入阶段仅解析预检，报告工作表行号、目标人员、错误码及建议；检查越权、重复、版本、时间和地区格式。用户确认新增/替换/跳过策略后再提交。文件重复提交使用操作标识防重；不能只返回“成功”而隐瞒漏排。导出和导入权限分别维护。

## 9 排班规则及校验

### 9.1 政策与参数

| 规则域 | 必须配置或明确的参数 |
|---|---|
| 日历日型 | 工作日、休息日、节假日，各自是否允许排班；地区日历与门店营业日历分别保存 |
| 工时限制 | 不同日型每日、每周、每月上限，统计周期、计入休息或加班的口径 |
| 连续与休息 | 单次连续工作分钟上限、哪些休息可打断累计；连续工作天数、班间最小休息、跨店通勤间隔分别配置，跨周跨月计算 |
| 排休 | 月最少/最多排休、固定排休、谁可修改、是否允许临时豁免 |
| 预警 | 日、周、月至少各支持3级可配阈值，颜色文字、主管关注及发布前处理 |
| 资格 | 关系与任职有效期、技能等级、健康证或岗位证照及工作当日有效性 |
| 时间与修改 | 吸附步长、最短班、允许回填时窗、已打卡已确认已封存的限制 |
| 发布审批 | 四种发布模式、流程版本、自动发布时机、通知对象 |
| 提醒 | 未排班提醒提前时间、按营业日或班前触发、对象、去重及失败重试 |
| 规则继承 | 集团共享、公司引用和受控覆盖，范围、生效日期、版本及审批 |

所有具体工时、休息和地区制度值来自明确配置；本文不预设法定数值。演示值须标为虚构测试政策。

### 9.2 校验级别

不可降低的完整性约束包括有效身份、无授权写入、非法时间、同人真实工作区间重叠、冻结历史和重复生效。政策性限制按规则确定硬阻断、授权豁免或提示；被设为硬约束的资格和制度不能由普通排班员忽略。

豁免必须显示具体规则、依据、申请人和批准人，绑定方案版本及日期范围，不是给用户一个永久“忽略冲突”开关。仅预警可以带理由继续，但记录原因并进入审计。

### 9.3 校验时机与隐私

拖动中做本地即时预判；保存草稿执行服务端校验；提交和发布做全量重验，覆盖本人其他门店、相邻日期、假期、资格及当前政策。审批期间原班、人员或假期变化使先前绿色校验失效，批准和实际生效均重新检查。

跨公司检查按永久人员完成。若操作者无权查看另一品牌详情，只提示“该人员此时间已被其他授权组织占用”及必要冲突区间，不暴露对方薪资、完整花名册或无关合同。

### 9.4 工时口径

同一人跨多关系统计真实排班占用，不能通过两个账号绕过工时上限。每个班段先执行自身关系在工作日适用的政策，再执行集团定义的自然人聚合政策；两类约束都要满足。每项冲突显示政策来源、版本和统计范围。没有可确定的适用政策时阻断发布，不能任取最后一条配置，也不能不加说明地混用不同统计口径的数值。计划与实际分别统计，休息和通勤按政策处理。跨店默认按班段整体跨度检查占用，不能把在A店的休息自动当作可在B店同时工作的空档。远程支持如只是成本或任务分摊，作为来源分摊记录，不重复造一段同时工作和工资。

## 10 保存审批发布与版本

### 10.1 四种发布方式

| 模式 | 可观察行为 |
|---|---|
| 保存即发布 | 保存前完成正式发布级校验，提交的是不可变发布版本；有失败则不部分发布 |
| 手动发布 | 可反复保存草稿，点击发布后重验并生成发布版本 |
| 审批后自动发布 | 提交快照审批，全部批准后生效任务重验并自动发布，失败进入阻断待办 |
| 审批后手动发布 | 审批冻结版本，授权人另点发布；修改内容需要新修订和重新审批 |

“保存即发布”时，画布本地编辑与保存按钮之间仍有明确提交边界，不把每次鼠标移动直接对外发布。普通草稿自动保存如开启，必须与正式发布区分显示。

### 10.2 状态与执行

方案状态为草稿、校验有效、待审批、已批准、已发布、已被替代、撤回或作废。校验结果绑定修订号、规则版本和数据基线。审批拒绝回草稿新修订；待审期间不允许悄悄改变被审内容。

已批准不等于已生效。任务执行时有冲突、资格失效、权限变化或网络失败，状态显示“待处理”及原因；不能继续显示已成功发布。重试保持同一业务操作标识，只成功一次。

发布单元为明确门店或考勤组及日期区间；支持部分门店先发布、确认和封存，不强迫整个集团同月一起完成。跨店人员仍参加全局冲突校验。多门店联合发布若设为一批，必须事先展示原子范围。

> 界面设计：排班发布与申请状态示意；公共界面见[总体设计](overall.md)。

### 10.3 发布后变更

已发布班表创建变更草稿，显示增删改及受影响人员；按规则审批并发布新版本，原版继续可查。变更通知带差异和生效时间。已发生打卡后的回填需特定权限、原因和影响分析；考勤或工资已封存则走追溯调整，不能覆盖原班或工资快照。

## 11 员工调换班与替班

| 申请类型 | 前置确认 | 批准后结果 |
|---|---|---|
| 调整自己的班 | 本人提出目标班段或日期 | 修改本人安排，原版本保留 |
| 与他人互换 | 双方本人确认目标，检查两边工作资格 | 两边班段一起生效或一起不变 |
| 我替别人 | 被替者确认，必要时主管确定原人是否释放 | 新人承担指定班段，原班处理明确 |
| 别人替我 | 接替者确认并具备资格 | 同上，不能只给接替者加班而漏释放本人 |

申请页面选原班、目标、原因、附件和受影响日期，预览两人的工时与规则。对方拒绝、超时、撤回或原班改变后申请失效或需重新确认，不能沿用旧同意。本人确认不能由具有排班写权限的管理员冒充。

### 11.1 申请状态

申请为草稿、待对方确认、待审批、已批准待生效、已生效、拒绝、撤回、失效或执行受阻。已生效后的取消是新的反向变更，不能抹除原申请。

### 11.2 多人多时段批量申请

有代操作权限的主管可在同一单据录入多人、多日期、多时间段的加班、补卡或请假。表头保存事由及共同附件，每条明细保存人员、具体关系、类型、区间、时长及证明。提交前逐条规则和额度检查，显示是否需要员工本人确认。

不同公司或审批路径自动拆为可追溯子任务，审批人仅看到有权的明细。单据头展示全部、部分或未生效的聚合状态；默认全单通过预检才提交，明确选择可用项时允许部分提交。执行以单条明细为单位；互换的两边仍是同一原子单位。撤回、拒绝和失败补偿按明细释放占用，不能用一次表头批准跳过某人的证明或余额检查。

主管批准前和实际生效前重验班段版本、资格、工时、假期、打卡和封存。员工互换不能交换劳动合同或薪酬档案；若目标门店需要新工作关系，则引导对应人事或支援手续。

## 12 跨店支援与到期回归

支援申请保存人员及来源关系、派出和接收门店、起止、岗位档口、考勤组、成本及计薪依据、双边负责人和是否接收排班权限。支援期间允许在接收门店设备打卡，但设备、地点及人员授权须实际配置。

原门店重叠班段进入显式调整，不是整段删除人员历史。接收门店只获得支援期间必要资料和班段权限。不同品牌之间是否允许支援由集团规则决定，不能跨集团借权限。

到期任务自动结束临时工作归属及权限；原店未来班表需要恢复时产生显式差异变更或待处理任务，先比较来源版本。可显示“关系已回归、排班待处理”，不能用一个完成状态掩盖漏排。若原店已改班、本人有新申请或期间已封存，生成待处理差异，不用旧快照覆盖新安排。提前结束或延期同样走审批并处理两端未来安排，历史已发生工时按实际工作地保留。

成本按核定工作时间及明确规则分摊到实际工作公司；不同币种不直接相加，计价规则和汇率另有版本，不能仅因跨店就自动换雇主或重复发工资。

## 13 假期加班与排班联动

### 13.1 请假占用与回写

请假提交前使用实际班段、日历和假期规则计算申请时长，展示扣减批次及余额。待批假以预占及风险覆盖层显示，保留原计划；批准后成为正式请假事实，冻结额度转使用并影响考勤，原计划仍可用于应出勤追溯。

半段假按区间切分覆盖，不得简单把整日设为休息。已发布的原计划由假期覆盖层保留；新建、复制或移动到已批假区间的工作安排则阻断，待批假按政策预占或提示，不能将原计划覆盖层误判为重复排班。长病假、哺乳周期或育儿资格通过假期服务提供，排班只读取对应有效区间和规则结果。撤回、驳回、销假分别释放或冲销额度及占用，重复回调不能重复扣减。

### 13.2 加班与调休

计划安排不等于已认定加班。员工或主管申请，按实际打卡及规则认定后，才进入加班费或调休。补偿方式、比例、有效期由地区和制度版本确定，防止同一来源既全额发加班费又全额入调休。调休使用后与普通请假一样回写排班考勤，额度批次和来源可追溯。

### 13.3 两服务的约定

假期服务提供人员关系与日期下的资格、可用余额、多批次扣减试算、有效假期区间、证明要求、申请状态及撤销结果。排班服务提供原计划、净工作区间、工作地点日历和封存状态。二者共享审批实例及幂等生效记录，不通过复制一份“假期余额”互相猜测。

## 14 打卡对班考勤与工资

每个需要打卡的工作段有独立的上下班及休息要求，一天多班不能只取最早和最晚两张卡。原始打卡只追加，补卡、人工核定和自动匹配保留依据与版本；无匹配的打卡进入待办，不丢失。

迟到、早退、缺卡、异常和加班由适用考勤规则计算。员工及门店确认后按门店或考勤组区间封存；日汇总、月汇总和工资输入绑定封存版本。计划改动不会直接改写已经确认的实际工作。

工资只接收明确计薪关系及币种下的核定来源；同一事实不因复制、跨店或重复消息重复过账。封存后纠错以调整单产生差额与追溯关联，原工资和考勤快照不改。

## 15 岗位需求自排与外包服务

### 15.1 需求与补位

门店可按日期、时段、岗位、档口、技能和人数设置需求，显示已排、缺口及超排。缺口推荐基于资格、可用时间、工时余量及授权范围，列明推荐依据；由有权人员选择并形成真实班段。硬冲突人员不进入可选列表。

员工自排开关可配置适用范围、可选班次、提交时窗、最大申请及审批。自排建议不自动占用正式名额；提交时可预占，冲突时按明确规则排队或拒绝，不能靠最后保存者覆盖。

### 15.2 外包人员

外包服务人员必须处于有效合同、服务关系和派驻范围，班段关联服务关系、供应商及实际工作地。供应商只能提交或确认自己服务人员的授权安排；企业按合同验收后服务工时才可进入供应商账单。个人工资、单位内部假期及供应商账单分开授权，不因排班可见而泄露其他资料。

## 16 人事考勤日报月报与版本管理

日报和月报是本模块供HR核对、主管确认、薪酬采用的核心成果。报表不能只是一张排班统计截图：要能解释每个数字的来源，允许有权限的人手工调整或Excel导入，形成独立的新版本，再复核确认，并支持Excel导出。

### 16.1 报表入口和默认工作区

“排班考勤→考勤日报”“排班考勤→考勤月报”是独立二级菜单。进入先选集团或品牌公司范围、门店或考勤组、日期或月份、关系类型及报表版本；显示期间、计算状态、复核状态、当前生效版本、是否被工资采用。

顶部固定查询、重新计算、创建调整版、导入Excel、导出Excel、版本对比、提交复核、确认封存等操作；无权的按钮隐藏，后端仍单独鉴权。列表左侧固定工号、姓名、公司和日期；指标按应出勤、实际、假勤、加班、计薪、异常分组，可保存列视图，不默认把几十列全部铺开。

默认月报一行是一人一份有效雇佣或服务关系在指定公司及计薪方案下的当月汇总。按人员查看集团全貌时另提供去重聚合，不能将不同公司或币种的计薪数据直接混成一条。日报默认按人员、关系、工作日展示，可展开每个班段和打卡。

> 界面设计：人事考勤月报示意；公共界面见[总体设计](overall.md)。

### 16.2 日报字段

| 字段组 | 必要内容 | 展示和来源规则 |
|---|---|---|
| 身份组织 | 永久工号、姓名、雇主公司、实际门店、部门岗位档口、关系类型 | 可查当日有效关系；汇总与成本地点分开 |
| 日期日型 | 归属工作日、星期、自然日期、日型、地区、时区 | 夜班明确次日；不按页面当前日期猜 |
| 计划 | 各段班次、开始结束、休息、计划净工时、应出勤日 | 来源发布版排班；未排班与排休分开 |
| 原始事实 | 每段打卡、设备或来源、跨店地点、缺卡标记 | 原始流水只读；展开看全部而非只取首尾 |
| 核定出勤 | 实际在岗、核定工作、核定加班、出勤状态 | 展示自动计算值和核定依据，不将计划当事实 |
| 异常 | 迟到、早退、缺卡、旷工、未匹配、待处理数 | 分钟、次数、天数分别标单位 |
| 假期 | 假种、申请时段、批准时长、有薪或无薪、调休使用 | 已批与待批分开；可下钻申请及额度来源 |
| 加班 | 工作日、休息日、节假日认定，转调休或计薪去向 | 原申请、实际核定及补偿分开，防重复 |
| 支援 | 派出及接收门店、工作工时、成本归属 | 不因此改雇主；权限受支援期间限制 |
| 计薪输入 | 计薪出勤小时或折算天、扣薪或补偿工时、采用状态 | 由薪酬方案规定口径，不默认等于在岗时间 |
| 处理版本 | 异常处理、员工和主管确认、报表版本、调整标记、原因 | 单元格可打开来源和前后差异 |

日报默认显示工号、姓名、日期、公司或门店、班次、计划工时、核定工时、迟到早退、缺卡、请假、核定加班、计薪出勤和处理状态；其余进入字段组或明细。切换列视图不改变底层统计口径。

### 16.3 月报字段

| 字段组 | 必要指标 | 勾稽关系 |
|---|---|---|
| 人员范围 | 永久工号、姓名、公司门店、部门岗位、关系、计薪方案、期间 | 期间内入离调转按有效日期取数，不重复计同段 |
| 应出勤 | 适用天数、应出勤天数、计划工作小时、排休天数 | 以发布计划和适用政策为依据，保留口径版本 |
| 实际出勤 | 实际在岗天数、核定工作小时、夜班或跨店小时 | 出勤天数按有核定工作的日期去重，不直接折算成计薪天 |
| 计薪出勤 | 折算计薪天数、计薪小时、月级调整、最终采用值 | 系统派生版为日报汇总加月级调整；外部核定版采用来源合计并标无日明细 |
| 假期明细 | 各假种天或小时、有薪无薪、调休使用、待批预占 | 单位分列，假期批准量与台账及日报一致 |
| 迟到早退 | 次数及分钟、核定豁免、最终计薪影响 | 事实次数与允许核定的计薪影响分开 |
| 缺勤异常 | 缺卡次数、旷工小时或天、未匹配、待处理数 | 明确已处理及待处理，不把未排班当旷工 |
| 加班调休 | 三类核定加班、转调休、计薪加班、补偿调整 | 同一来源的补偿去向可追溯且不重复 |
| 支援成本 | 派出接收天或小时、实际工作公司、成本归属 | 不同地区币种分别展示；主月报不强行展示工资金额 |
| 版本状态 | 来源日报版本、人工或导入调整、复核封存、工资采用批次 | 可回到具体版本和调整依据 |

计薪天数折算规则必须由方案显式定义。举例中的“8小时折1天”仅可作为虚构测试方案，不作为内地或香港统一制度。集团去重人数、人日、各公司计薪天和成本小时分别汇总，不能将不同口径的“天”相加后叫出勤天数。

### 16.4 计算版调整版和生效版本

自动计算产生计算版V1，记录排班、打卡、核定、假期、规则及算法版本。已有版本创建调整版V2必须选择父版本及完整范围；首次外部导入允许创建无父版的V1，之后的更新要指定父版和替代范围，保存原计算值、调整值或增减量、最终值、操作者、时间、理由及凭证。原版始终只读可查。

报表版本状态为草稿、校验通过、待复核、已确认、生效采用、已封存、被新版本替代或作废。当前生效版有明确标识；草稿版不能被薪酬误用。更改基线数据后重算产生另一个候选版本，先比较现有人工调整，不能覆盖掉它们。

同一报表版本内字段有明确来源类型：自动计算、审批核定、人工调整、Excel导入或月级补调。单元格显示修改标记，点击看到原值、调整值和最终值。版本比较支持按人员、日期、字段及差额过滤，并显示新增、删除和状态变化。

### 16.5 手工调整

用户进入“创建调整版”后，可单格或批量维护授权字段，例如计薪出勤、核定加班、迟到豁免或假期分类调整；具体可写字段由字段权限和政策决定。原始打卡、永久身份、来源主键、公式合计与封存标识不能直接改。

调整前后即时校验单位、精度、最终计量值非负等约束及上下游关系；增减差额和月级补调允许负数，例如100小时调到90小时，差额为负10小时。调整实际时刻或缺卡必须走核定补卡业务；调整假期消费须关联批准申请或额度调整，不能只改月报造成台账不一致。月报可单独追加月级计薪补调，不自动回写某天；需要日级变化时创建日报调整版后重新汇总。

每笔修改必须填写原因；达到政策门槛时需凭证和指定复核人。批量填数先显示涉及行列及前后差异；越权行、已封存行和非法值不会被部分静默写入。未经授权的普通查看者不能通过编辑接口、粘贴或导入修改数据。

### 16.6 日报月报的版本勾稽

从本系统计算的月报绑定一组明确的已确认日报版本及规则快照，最终月值等于日报汇总加该月独立调整。日报来源按人员、具体关系、工作日及指标唯一，同键不能同时采用旧版和新版；缺日期显示缺口，不能默认零。导入或手改日报后，月报提示来源已变更并产生待重汇总任务，不静默改变已确认月报。

月报调整版如果未分摊到日期，日报继续显示原值，并在月报“月级调整”列和差异页明示。重汇总必须保留、冲销或重新确认这些月级调整，禁止把手调差额丢掉。跨月夜班按规则切分但只使用一次事实来源。

外部已核定月报可以直接Excel导入建立独立的外部基线版本，即使本系统没有对应原始打卡或全部日报。版本明确标识“外部核定来源”，归档文件及核验依据，经指定复核后按政策允许采用；不能为通过勾稽而伪造打卡或日报。没有日级来源的指标标“无日明细”，不以缺少已确认日报为由禁止此类版本复核和采用。同一月混用两类来源时，按人员、具体关系、公司、期间及指标确定唯一生效来源，外部月合计不再叠加系统日合计。若以后补齐日报，则新建对照版本，比较并确认差异，不覆盖已经采用的外部基线。

### 16.7 Excel导入形成版本

日报和月报均提供模板及导入入口。模板带报表类型、范围、期间、父版本、单位和字段字典；每条记录包含永久工号、公司、具体关系或可唯一匹配的关系代码，日报另有日期。姓名仅辅助核对，不能据姓名自动合并。

支持完整范围替换、指定记录更新、差额调整三种模式。完整范围导入要求范围内记录齐全，缺行先阻断并列出；指定更新只改明确列出的行及可写字段；差额模式将数值作为增减量。空值、零、缺列的含义分开，绝不把空白默认清零，也不把“覆盖”误作“增量”。

导入先进入暂存预检：识别文件、匹配人员关系、检查期间和重复、字段权限、数值单位、公式与适用的日月勾稽、请假加班依据、封存与已被工资采用状态。预览逐行显示Excel行号、原值、新值、差额、错误及匹配结果；用户确认后创建导入草稿版本，默认仍需复核才能采用。

多人多公司或多关系无法唯一匹配时要求显式选择，不取第一条。重复文件或重复提交使用文件摘要和操作标识提示已导入；重复主键按用户明确选定规则处理，默认阻断。Excel单元格公式不执行外部链接或宏；需要公式结果时采用可核验的数值及系统独立复算，不猜缺失结果。

导入更正只影响候选版，不覆盖父版。导入失败返回可下载错误清单和成功候选数，但未经明确选择“只提交已通过行”不得产生半成品生效报表。原始导入文件、摘要、模板版本、操作者、映射及处理结果按权限归档。

### 16.8 Excel导出

日报、月报、明细、差异和错误清单都支持真正的XLSX导出，CSV为可选补充，不能只用CSV冒充Excel工作簿。导出按查询范围及字段权限执行，可选当前列视图或授权完整字段；页码只影响屏幕，不限制全范围导出。

工作簿包含说明与版本页、报表页、需要时的班段或调整明细。表头冻结、筛选、日期及数值格式、单位、合计、打印标题明确；月报可按门店分工作表，但每张带同样版本说明。说明页记录导出时间、期间、组织范围、报表版本、状态及是否可用于算薪；草稿导出显著标为未确认。

完整导出与打印分别授权。导出缺省不带无权证件、银行及工资金额字段。文本字段按防公式注入处理，不能让员工名称或备注作为Excel可执行公式。

### 16.9 复核封存和算薪采用

表格调整和Excel导入完成后提交复核，复核人可看差异、依据及异常，不必逐行寻找修改。审批规则由系统设置中的审批流设计器配置，绑定这份报表版本。提交后版本只读，退回后开新修订，不能审批旧数时悄悄改新数。

确认与封存可配置分工。封存后产生稳定版本供薪酬选择或自动采用，工资批次记录报表版本及来源，采用按公司、人员关系、期间及指标的业务键控制替代关系。V2替代V1时采用最终新值或明确差额，不能把V2全量再加一遍；同一事实在系统来源与外部核定来源之间切换也只替代不叠加。报表已被工资锁定采用后，新调整版不能反向改工资；系统提示影响，走明确的差额重算或后续补调流程。

解封或更正需要独立权限、原因和审批；原封存版、确认人与被采用批次保留。报表生效与实际付款不同，考勤确认不会直接触发支付。

### 16.10 手机核对与异议

手机按本人日期卡片或月份摘要展示应出勤、实际、假期、加班、异常、计薪结果和版本；可展开来源，查看调整前后、确认或提出异议。员工不能直接改核定数。店长手机看本店待复核和差异列表，按权限处理；复杂全月批量编辑仍以PC表格为主。

### 16.11 其他台账与提醒

原排班日报、排班周月报、计划实际对比、未排班、调换、支援成本及员工确认台账保留，并能穿透到本章人事日报月报版本。未排班提醒按规则计算对象和时间；发布、变更、支援到期、资格到期和申请待办分别去重。

任务保存下次运行、重试次数、失败原因和人工补发记录。站内通知先可用，钉钉飞书消息失败不回滚已生效业务，必须展示通知失败待办。人员全貌按授权汇总班表、申请、核定、报表调整和工资采用来源。

## 17 系统设置权限审批与失败恢复

### 17.1 独立的系统设置界面

系统设置是管理员独立入口，包括操作人员、角色与菜单权限、数据范围、字段权限、表单设计、审批流设计、版本发布、流程监控、接入配置和操作日志。日常员工从办事大厅发起、主管从我的审批处理，不进入设计器改流程。

操作人员界面支持新增和停用账号、关联内部员工或供应商联系人、分配角色与授权期间、重置登录凭据、查看有效授权。离职或服务终止后回收对应访问；不能仅凭显示姓名绑定身份。系统管理员有配置权，不自动获得考勤修改或工资查看权限。

考勤报表权限分别设置查看、查看调整依据、创建调整版、可写字段、Excel导入、XLSX导出、打印、提交复核、复核、确认、封存、解封更正、算薪采用和代操作。角色决定动作，数据范围限定集团品牌公司门店及人员，字段权限限定具体列和凭证；三者同时满足才能执行。

### 17.2 审批设计和日常办理

表单设计、审批流设计及版本发布统一放系统设置。排班发布、调班互换、支援、补卡、加班请假、日报月报调整与导入复核、封存解封分别绑定适用表单和流程版本。支持条件分支、主管岗位或角色找人、会签或签、抄送、转签、代理、加签、退回撤回和超时提醒。

设计器先校验和仿真再发布；实例冻结发起时的表单、流程版本与业务快照。审批人缺失不自动通过，产生配置待办。流程配置与审批处理分别授权，模板修改不改正在审批的旧实例。每个流程必须绑定明确生效处理器，批准后更新对应班表或报表版本，失败有补偿和重试记录。

### 17.3 编辑权限与并发恢复

查看、导出、编辑草稿、批量编辑、清空、修改排休、回填、规则配置、提交、审批、发布、豁免和代操作分别授权。权限改变应在保存及发布时重新核对，前端隐藏按钮不能代替后端检查。

同一方案采用修订号控制：两人同时编辑，后提交者看到前后差异并重新载入或合并，不能静默覆盖。多个方案给同一人员发布时，按统一人员与区间串行检查，不能各自检查“当时空闲”后同时成功。

批量提交有操作标识及逐项业务键；重复点击、网络超时或回调重试返回同一结果。前端显示未保存、正在保存、已保存、失败和冲突状态，失败后保留本地未提交修改。已成功但响应丢失时通过操作标识查回结果，不再复制一遍。

边界失败需保留具体对象、规则、原目标值和可处理路径。越权数据不写入；确认前的预览不形成正式考勤或工资。系统日志只记录必要标识及变更，不写敏感凭据。
