# 天意HR薪酬与薪税管理完整设计

版本 V1.0　2026年11月16日

本文件定义餐饮集团薪酬产品的完整业务链，供产品负责人审阅及后续开发验收。范围包含中国内地与香港两套可选算薪体系、工资项目、薪资档案、考勤绩效输入、社保公积金及MPF、个税及香港雇主申报、发薪、工资单和用工成本。参考人力家及易路People+，以已有餐饮参考业务材料检验场景覆盖，所有示例独立虚构。

复杂公式、多项目引用、触发器、自定义代码及AI接口作为天意自身扩展设计，不归因为参考厂商已被证明具备全部这些能力。

这是详细设计稿，不表示现有代码已全部实现，也不表示真实客户工资已经算准。餐饮参考业务材料用于理解业务，不导入真实员工与金额。原表中的历史比例、按姓名例外或无法解释的公式不能直接变成法定规则。

## 阅读指引

先读第1至4章理解产品边界、两套体系及公司门店选择，再看第5至9章的项目、档案、算薪界面和版本。第10至14章分别说明内地社保个税、香港供款与报税；第15至21章为补发更正、发薪工资单、外包、成本、权限及系统设置；后续章节列客户场景与验收。章节内的规则来源标识对应附录官方资料，适用状态核对至2026年11月16日。

## 1 产品主线与完成条件

产品主线为统一人事档案和有效雇佣关系，取得已核定考勤、获批绩效、薪资变动及供款参数，计算、校验、比较、复核并锁定工资，形成发放任务、工资单、申报数据和成本结果，再接收银行、税务及供款回执。每个阶段有自己的状态，不能以“工资已确认”代替已发薪、已申报或已缴款。

工资项目及规则能够覆盖客户真实业务类型，未知规则能明确配置，异常能解释，版本可追溯。验收要比较逐项、逐人和汇总，而不是只让实发合计碰巧相等。系统缺关键身份、规则或来源时阻断正式确认，演示可用明确标记的虚构配置运行。

参考资料的能力与天意设计分别归因；不继承供应商宣传准确率、承诺税局银行已经直连、也不要求客户理解两个旧引擎或手工做新旧人员接续。

## 2 金额主体与期间

### 2.1 六类金额

| 金额类别 | 定义及边界 |
|---|---|
| 员工应发 | 本批次应支付给员工的现金工资收入，不包含仅供计税的非现金利益 |
| 员工扣款与实发 | 员工承担的供款、税及有依据扣款；实发是支付义务，不等于银行成功金额 |
| 计税或相关入息 | 各法域独立定义的税务收入、MPF相关入息等，不直接等同现金应发 |
| 企业承担 | 企业社保公积金、雇主MPF、保险及其他雇主成本，不从员工实发再扣 |
| 代发及代缴资金 | 委托供应商或渠道代发代缴的资金项目，不能与相应工资供款再累计一次 |
| 财务人力成本 | 工资成本、企业承担和其他人力费用按权责发生与科目映射汇总，不能用净薪代替 |

### 2.2 主体和关系

永久人员身份贯穿集团，工资行绑定具体雇佣或服务关系。经营门店公司、合同雇主、发薪主体、个税扣缴义务人、社保或MPF雇主账户、成本承担分别保存，有有效期。门店独立核算不证明每个职责都由同一个注册主体承担。

同一人有两份真实雇佣可以分别算薪；同一发薪及扣缴主体的多岗位收入要按规定归并计算，不能拆岗位以重复享受扣除或供款门槛。临时借调保留劳动关系，成本分摊不产生第二份重复工资。

### 2.3 期间与日期

保存工作所属期、考勤期间、工资所属期、实际支付日期、计税归属期、供款期、绩效考核期及会计期间。内地纳税年度、香港课税年度和企业财年不能共用一个“年份”字段。补发归属过去的工作不代表税务、供款和成本都回写到同一月份，按适用规则分别映射。

## 3 两套算薪体系与公司门店设置

### 3.1 两套独立规则包

提供中国内地算薪CN_PAYROLL和香港算薪HK_PAYROLL两套独立配置及计算规则包。它们共用身份、工资项目基础框架、审批版本和导入导出能力，独立维护社保或MPF、税务、法定给薪、申报和地区报表。

公司或门店允许仅启用一套，也允许同时启用两套。双启用是可用能力集合，不是把全部工资自动复制计算两次；单个工资批次只能使用一个明确体系和支付币种。

### 3.2 新建及维护界面

| 设置项 | 产品行为 |
|---|---|
| 可用算薪体系 | 中国内地、香港两个复选项，可选一或两套，明确生效日期 |
| 默认体系 | 从已启用项选择；双启用时可以设置默认，但算薪仍显示明确选项 |
| 体系配置 | 分别维护地区、支付币种、工资组、日历、供款及税务配置 |
| 主体映射 | 关联真实发薪、扣缴或香港雇主报税主体、供款账户及适用关系 |
| 授权范围 | 指定谁能看、算、调整、复核、发放、申报及导出，各体系可分别授权 |
| 变更停用 | 已有工资不能直接改成另一体系；存在未结计算、审批、支付或申报时禁止即时停用，可设未来失效日；历史查看、导出及更正按原有效配置办理 |

集团帐套提供两套共享模板，公司、品牌及门店分别设置“继承上级”或“独立配置”。上级默认只启用内地，不会仅因这一默认值阻断下属门店选择香港；有配置权限的人可以为下属启用另一套或两套，并补全主体、方案及日历。操作人同时受体系及数据范围权限约束。界面不按品牌名称猜地区；没有完整配置时可保存待配置公司，但不能完成正式工资确认。

### 3.3 双体系下的人员和批次

公司薪酬配置按公司或门店、体系、生效区间维护，包含工资组、发薪和税务供款主体、币种及政策版本；具体工作关系引用该配置。经营地区及帐套记账币种独立维护。具体工作关系关联可用工资组及体系，并明确发薪主体、币种、税务及供款账户。跨境或双重关系需要两套时，分别建立真实对应关系或明确的分拆依据。同一工资事实使用共同来源ID及唯一应付义务，不能仅加一个体系字段就绕开防重。合法分拆保存依据、比例或金额及分配上限。批次用途明确分为正式发薪、影子测算和申报计算；影子测算payable=false，不生成付款、正式工资单或正式对外申报任务，申报计算只承接申报义务。

建立工资批次时，选择公司门店后展示已启用体系；单启用可预填，双启用必须显式选择。选择内地后只展示内地规则与申报，选择香港后展示香港规则及表单；集团总览分体系和币种列示，不直接相加。切换体系不原地改变已计算批次，需另建批次及替代关联。

> 界面设计：双体系公司设置；公共界面见[总体设计](overall.md)。

## 5 工资项目与公式

### 5.1 项目字段

| 字段组 | 必要配置 |
|---|---|
| 标识 | 稳定编码、名称、体系及适用范围、性质、单位和币种 |
| 金额性质 | 固定收入、浮动收入、补贴、奖金、扣款、个人承担、企业承担、统计项或非现金利益 |
| 来源 | 薪资标准、考勤、绩效、补贴提成、外部导入、核定调整或公式 |
| 规则标签 | 是否支付、是否计税、是否计社保或MPF相关入息、是否进入平均工资及成本 |
| 计算 | 变量、公式、条件、依赖项、阶梯、分段、上限下限和取整 |
| 版本 | 有效日期、审批状态、前后差异、测试样例和停用规则 |
| 显示 | 工资表及工资单分组、员工可见性、排序、导出与财务科目映射 |

同一项目的税务、供款和平均工资标签可因体系及生效日期不同，不能用一个“计税”开关代替所有口径。企业承担不混成员工扣款；非现金利益可计税而不计入现金实发。

### 5.2 多项目引用与依赖计算

工资项目支持复杂公式，能够引用其他工资项目及中间统计项目，组成多级依赖。例如核定工时和时薪生成基本工资，基本工资、津贴和绩效生成应发，相关项目生成供款及税务基数，个人承担和税额进入实发。依赖通过稳定项目编码绑定，改中文名称不影响引用；保存时解析语法和类型，发布时冻结完整依赖版本，计算按有向依赖图排序。

同批次按阶段计算：输入及资格、分段收入及核定、计税供款口径、法定计算、税后调整、应付及成本。收入或基数调整回到前阶段修订并重算所有下游；跨阶段反向引用、缺项、循环、除零或非法结果报错并列依赖路径。税额倒推等迭代用专门有界求解器，声明输入、收敛及失败条件，不以隐蔽循环代替。

一项考勤或已确认绩效可被多个规则读取，但同一应付事实不重复过账。项目可以设为“仅计算不发放”，供其他项目引用；不能把中间统计项与最终应发再相加。停用仍被依赖的项目时显示影响范围，必须同步修订引用方案。

金额、单价、比例、天数工时及中间值分别定义精度，保存计算值与显示值，按项目明确舍入阶段、位数及模式；不默认每个中间项目先转为两位金额。公式内核可保留精确有理数或等价十进制精度，外部API和持久化使用明确精度的十进制文本，金额不得经过JS Number再传入。静态依赖检查覆盖全部分支，运行轨迹另记实际命中分支和读取值。

### 5.3 函数变量与取数库

| 能力 | 应支持的函数或操作 | 取数及计算约束 |
|---|---|---|
| 算术与判断 | 加减乘除、IF、CASE、比较、AND、OR、NOT | 金额、比例、天、小时、日期、布尔及枚举分类型；空白不是零 |
| 数值处理 | MIN、MAX、ABS、SUM、ROUND、向上向下取整 | 声明精度及舍入时点；禁止隐式浮点金额运算 |
| 阶梯与查表 | 区间阶梯、累进分段、条件映射、政策表匹配 | 区间端点、空档重叠、生效日和未匹配处理明确 |
| 薪资档案 | 月薪、时薪、津贴、岗位标准及有效期片段 | 按具体关系和片段取值，不用期末标准覆盖全月 |
| 考勤假期 | 已核定工时、天数、假期、加班、夜班、跨店及次数 | 绑定日月报版本和指标单位；同一段跨夜时间不重复取用 |
| 绩效奖励 | 已确认结果、资格、等级、基数及发放来源 | 固定选择算法及结果版本，比较结果不自动变成第二项应付 |
| 历史累计 | 上期、指定期、近N期、本年累计、已扣已缴与差额 | 指定主体、关系、体系及期间口径，工资累计与实际申报累计分开 |
| 日期与服务期 | 日期差、月边界、工作日、计薪片段、资格年资 | 端点和日历可查，连续性合约、集团承认年资及MPF资格分别计算 |
| 范围汇总 | 指定公司门店、部门、岗位、成本中心及授权集合汇总 | 采用预定义范围查询，不在表达式中拼SQL；结果保存成员及分配版本 |
| 法定模块 | 内地税、社保公积金、香港MPF、ADW及法定给薪调用 | 调用经过复核的版本化规则，返回完整计算明细，不能用个人公式悄悄绕过法定校验 |

跨人员奖金池、门店提成分摊先形成已确认的池总额、成员和分配依据，再计算人员金额。成员计算若反过来依赖尚未确定的本池总额，阻断循环。跨公司取数同时核对服务身份与实际授权，不因公式作者能见一个汇总就向工资行暴露其他员工明细。

> 界面设计：工资公式与扩展；公共界面见[总体设计](overall.md)。

### 5.4 历史多体系与有效期

历史函数明确“工资所属期”“支付期”“税务期”或“供款期”，并指定正式采用、已扣、已申报或已缴状态。过去N月可以只取有记录的月份或按自然月份补齐，必须由函数参数明确；缺月触发缺失或批准规则，不能静默补零。

同一关系跨月调薪、跨店或政策变更，计算先按生效边界切片，规则在片段内执行，汇总时按方案舍入。读取另一体系或币种必须是授权、显式目的的对照或换算；引用保留原币、汇率日期及版本，不能直接把HKD金额加到CNY工资项目。

### 5.5 高级规则编辑器与调试

PC使用分区工作台：左侧为项目、变量和函数目录；中间为公式或条件阶梯编辑；右侧为类型、依赖及解释；底部切换测试、逐步结果和错误。提供编码自动补全、函数签名、中文注释、条件可视化、依赖图、影响分析及版本差异；高级用户可直接编辑表达式，普通配置人用条件及表格构建规则，两种方式使用同一规则定义。

测试可以选择虚构样例或授权人员的冻结快照，展示变量来自哪里、哪条条件命中、分段及中间值、舍入前后和最终差额。测试不会修改正式工资或外部台账。可建立正常、边界、空值、零值、负调整及跨期样例组，发布前保存预期结果与实际结果；共享模板被多个公司引用时列受影响方案和待重算批次。

### 5.6 自定义代码与开发扩展

标准公式之外提供真正可编写的扩展模块，支持复杂条件、集合处理及客户特有计算。首版以JavaScript扩展为目标，TypeScript可编译成固定版本JavaScript后打包；不是把代码粘进普通公式后直接在服务器主进程执行。

每个模块声明稳定编码、版本、输入输出结构、金额及单位类型、依赖项目、适用体系、执行阶段和权限。开发者通过受控SDK读取本次已授权、冻结的数据，用精确十进制SDK处理金额；输入输出金额采用十进制文本或明确精度类型，原生Number金额运算不能直接作为正式结果。输出包含项目金额、解释明细和校验信息，由宿主再次验类型、范围、依赖、勾稽和法规最低要求。

采用隔离运行进程及能力受限宿主接口，明确CPU时间、内存、输出量、循环和执行步预算；不能只把JavaScript vm当安全隔离。模块不直接读取本地文件、环境变量、数据库、网络或其他帐套，不访问系统当前时间及随机数；确需日期或种子由冻结输入提供。外部依赖包按固定清单和版本审核，不在算薪时在线安装。超时、异常或非法输出按人员项目标错，正式批次不以部分结果冒充全体成功。

正式确认时，标准表达式继续走应用与数据库的独立复算；扩展模块由受信隔离执行器按冻结环境重新执行，服务端比对输出并记录模块摘要、输入摘要和执行证明，数据库仍校验状态、来源、金额勾稽、唯一应付和绩效采用等不变量。执行证明及结果只能由受控执行身份登记，客户端不能自报一份JSON就通过。新增函数、精度及规则版本同步更新校验两端，不能关闭已有一致性校验来接入JS。

代码模块支持草稿、测试、评审、批准发布、有效期和停用；代码摘要、SDK与依赖包版本及输入快照写入结果。已使用模块不可就地改写，修订新版本后才能影响新试算。回滚是切换未来配置或生成更正，不删除已支付的旧事实。

### 5.7 触发器时点与行为

业务触发器单独配置，声明事件、条件、作用范围、执行动作、优先级、版本和生效日期。可用条件及动作界面配置，也可关联已批准开发模块；触发器不等同于随意更新任何数据库表。

| 触发时点 | 可以执行的动作 | 必须保留的边界 |
|---|---|---|
| 人事变动或调薪已生效 | 创建薪资档案候选、应算名单影响或参保待办 | 不把审批通过但未生效的调薪提前覆盖档案 |
| 考勤或绩效新版本确认 | 更新未锁工资的输入候选，创建重算影响任务 | 已锁工资只能生成更正建议，不静默改结果 |
| 输入准备完成及计算前 | 受控派生变量、完整性校验、阻断或提示 | 写本次输入修订，不修改冻结来源和其他批次 |
| 项目计算后及批次校验 | 生成解释、异常及勾稽校验 | 不无痕覆盖另一项目；修正金额需作为声明的计算项目或核定版本 |
| 复核批准及确认锁定后 | 创建允许的工资单、支付、申报、成本候选任务 | 按正式、影子、申报用途约束；批准不能冒充外部执行成功 |
| 回执或工资单异议到达 | 更新对应明细状态、派发处理或更正任务 | 只认对应版本和真实回执，消息重送不重复生成应付 |

事件包含事件ID、来源版本、批次用途和关联链。采用事务发件箱保存提交后事件；重试以事件ID及动作键幂等，记录已完成步骤。因果链检测自触发、循环事件和重复投递，超过深度预算阻断并提示，不无限重算。必要前置校验失败阻断确认，通知等非核心失败进入待重试，不撤销已真实成功的付款或报送。

### 5.8 外部接入与副作用

公式与计算模块保持可重复的纯计算。需要外部数据时，先由授权连接器同步到有版本的输入候选区；需要发消息、送银行、报税或入财务时，由提交后业务任务按各自授权执行，不能在计算一人的工资时顺便调用外部付款接口。外部失败重试沿用原业务标识，部分成功按明细处理。

数据库触发器用于系统完整性及权限防线，工资管理员配置的是业务触发器和开发模块，不开放任意数据库SQL修改。

触发器执行记录包括哪个事件、条件及模块、输入输出、结果和重试。管理员可在系统设置的规则扩展与触发器监控中查看失败和停用版本；薪酬专员在批次内看到业务原因，不需要理解底层程序堆栈。

### 5.9 面向AI的接口与工具

本地部署提供有版本的服务API及可选MCP适配，模型供应商可配置。AI以明确服务身份和当前用户权限运行，菜单、动作、组织、体系和字段范围同样生效；提示词不能扩大授权。默认使用虚构样例，读取真实敏感字段或出境模型需要企业明确的数据策略与接入配置，脱敏规则由企业控制。

| 工具组 | 提供给AI的能力 | 结果及写入状态 |
|---|---|---|
| 规则目录 | 查工资项目、函数签名、方案、版本、依赖和政策来源 | 返回授权内结构化定义，不暴露账号密钥 |
| 规则起草 | 由自然语言生成表达式、条件阶梯或扩展模块草稿 | 写草稿及解释，不直接覆盖已发布规则 |
| 校验调试 | 解析、类型检查、依赖检查、测试样例、冻结快照影子试算 | 返回运行ID、中间值、错误和差异，不生成正式应付 |
| 差异解释 | 查询某人某项为何变化，列来源、公式、政策、版本和舍入 | 对照可验证计算轨迹，不用模型猜一个工资数字 |
| 影响分析 | 比较两版本，找受影响公司、关系、期间和候选批次 | 返回有范围的影响清单及可审阅更正草稿 |
| 流程辅助 | 起草调薪、核定、更正及规则发布申请，查授权任务状态 | 只创建获准的草稿或申请；正式执行继续走角色及审批规则 |

工具参数包含帐套、公司范围、体系、期间、对象版本和调用标识；写入带修订校验、幂等键和原因，返回明确成功、失败或需补件。AI不能把试算接口伪装成确认、发布、付款或申报。AI生成代码使用与人工代码相同的测试和发布流程，不能绕过已有禁自审或职责配置。

保留模型和工具版本、脱敏后的请求摘要、规则差异、测试运行及操作者；不把密码、密钥和整批工资明文写入通用模型日志。企业可关闭AI功能，关闭后同一规则和工资流程仍可手工完成。

### 5.10 虚构规则链示例

例一为时薪人员：核定普通工时乘有效时薪得到基本工资；夜班次数乘补贴标准得到夜班补贴；两项与已采用绩效进入现金应发。相关入息项目另按地区标签汇总，调用对应法定模块后再计算个人扣款和实发。例二为门店奖金池：先取得已批准池金额，再按核定贡献点分配，分币尾差用明确规则分配，总额等于池金额。例三为历史调薪：对受影响月份按当时考勤及新标准重算，减原采用值生成差额，不直接把新全额再发一次。

上述链条可在依赖图展开至每个输入及模块版本。发布规则前至少测试同人多关系、月内多批次、零工时、缺时薪、负差额、跨体系引用和缺失历史；相同冻结输入必须可复算出相同结果。

## 6 薪资档案与变动

工资档案按人员、具体关系、工资组、发薪主体及有效期间保存月薪、时薪、岗位薪、津贴和其他标准。月中转正、调薪、调岗、入离职按有效日期分段，段内用其规则和考勤，不能用月末标准覆盖整月。

定薪调薪有申请、审批、计划生效、实际生效及凭据；批量Excel导入先核验身份、关系、范围、时间重叠和金额，再形成待批准版本。外部来源的姓名仅辅助核对，不能作为唯一关联条件。

支付账户、身份证件、税务身份、参保及MPF资料为独立权限字段。账号更改有审核和留痕，不因可编辑工资而可擅自换收款账户。离职关闭未来档案，不删除历史标准和已采用版本。

## 7 工资计算工作台

### 7.1 批次建立

选择期间、公司门店、算薪体系、工资组、发薪主体、币种、批次用途、核算类型和计划发薪日。工资组支持月、周、双周及日等计薪周期与发放频率，工资期、税务期和供款期分别映射；同月多批次不等于新建一套累计账。核算类型包含常规、补发、绩效或奖金、离职结算和更正。显示应算名单与纳入排除原因，允许在权限范围内补入漏算人员，但必须有有效关系和依据。

名单按具体关系及期间确定，覆盖入职、离职、月中调动、跨店支援、多雇佣和外包边界。外包服务费进入供应商结算；企业受托计算个人工资时独立保存实际雇主与代发身份，不能因在本店排班就自动当直营发薪。

### 7.2 阶段化界面

1. 确认名单和主体，列出未配体系、无有效关系、重复事实和缺支付资料。
2. 取得已核定考勤报表版本、工资档案、获批绩效、补贴扣款、供款及税务累计。
3. 校验完整性、来源新旧、单位币种、规则依赖和前期状态；缺失不默认零。
4. 试算，展示逐人逐项结果及计算依据，不成功者留错误而不生成假结果。
5. 比较上月、上次试算、外部核定表和选定方案，按字段和差额过滤。
6. 修改输入或提出核定调整，重算受影响项和人员，形成新修订。
7. 复核审批，冻结本次名单、输入、规则和结果；批准后确认锁定。
8. 按批次用途生成允许的工资单、资金发放、申报和成本后续任务，状态分别跟踪。

> 界面设计：工资计算工作台；公共界面见[总体设计](overall.md)。

### 7.3 结果表与明细

默认固定工号姓名、公司关系、工资组及状态，按应发、个人承担、税、其他扣款、实发和企业成本分组显示。用户可选列、保存视图、过滤异常和分页；查询全范围合计与当前页小计明确分开。

点击一项可查看来源数据、公式变量、分段、取整、政策及输入版本、人工依据和差异。计算人员不必翻到长页底部才能找到错误；右侧异常列表可定位具体人员项目。年度累计、发薪及成本不混成同一张表的同一个“合计”。

## 8 输入来源考勤与绩效

### 8.1 考勤输入

工资采用V7设计中的已确认或封存考勤版本，绑定公司、人员关系、期间、指标和来源模式。系统派生日月报与外部核定导入版分别标识；没有日明细时不得伪造打卡。工时、出勤天、计薪天、假期、加班及月级补调按项目映射，不把实际在岗小时直接当所有项目的计薪小时。

报表V2替代V1时只替代一次，不能把新值再累计。已锁定工资不随考勤改动静默变化，产生影响清单和差额或替代重算任务。请假扣款、病假给薪、未休假补偿和加班费分别用地区及制度规则。

### 8.2 绩效与奖金

组织绩效指标、人员评分、奖金计算和工资过账分别保存。保留两套奖金算法及差异，客户在方案中选择正式采用算法、适用范围与生效期；另一套继续可作对照，不能同时重复计入实发。

绩效结果经过确认后，按奖励来源、人员、具体关系或分配依据、工资项目和发放期生成一次输入。跨店责任范围和按月职级保留有效历史，不能用当前门店或职级覆盖整个季度。更换算法生成替代结果及差额，已锁工资走后续更正，不删除旧结果。

### 8.3 其他输入

支持提成、夜班、驻店、跨店、伙食、交通、住宿、奖励、借款、扣款、补发及追溯等输入。项目适用条件、是否按出勤折算、是否计税供款、成本归属必须可配；有依据的零值与资料缺失分开。纪律罚款不能仅因输入一个负数就视为合法可扣，应走适用政策与审核路径。

## 9 手工调整Excel与工资版本

### 9.1 两条导入路径

路径一导入输入：模板或列映射把数据放入薪资标准、浮动输入、历史累计或考勤等候选区，核验后由引擎算薪。路径二导入外部已核定工资：建立标明来源的核定基线，不要求伪造完整公式和日考勤，但要核对主体、人员、期间、应发扣款实发、供款税额及来源凭据，经独立复核才能采用。

工资项目定义、公式、人员金额、累计税资料、缴费账单、银行回执和报税回执是不同模板，不用一个万能“导入”按钮猜含义。支持XLSX，CSV为补充，明确零、空白、缺列、覆盖和差额模式；外部公式、宏及链接不直接执行。

### 9.2 调整与替代

有字段权限的人可创建调整版，记录原值、增减量、最终值、原因及凭证。月中标准变化用有效期档案处理；核定例外和追溯用调整单，不能直接改公式结果而没有来源。差额可以为负，不能把合法调减挡成“不得小于零”。若调整使最终待付为负，不生成负金额银行付款；转待核定应收、符合依据的后期扣回或暂停支付，保存审批及员工沟通。

调整稿、导入稿、计算稿、已审批版和已采用版有明确父子及替代关系。首次外部核定导入允许无父版V1；后续V2更新明确范围，不再把V2当另一份完整工资重复发放。重算显示与人工调整的冲突，保留、冲销或重新确认后再采用，不静默丢掉人工核定。

### 9.3 导出

提供工资表、分门店及分体系明细、个人工资单、差异、错误、税务、供款、银行及成本XLSX导出。全查询范围与分页分开；工作簿包含期间、组织、体系、币种、版本、状态、字段单位和导出记录。当前列视图和授权完整视图分别选择，敏感列单独鉴权。

政府或银行专用文件按目标机构的版本化规范生成并校验；普通XLSX对账表不能冒称已完成正式申报或付款。打印及分门店打包有独立权限，包内文件与目录使用虚构或授权身份，不把他人的工资混发给员工。

## 10 中国内地社保公积金与保险

### 10.1 参保配置

分别维护参保主体、城市、险种方案、职工及单位比例、基数上下限、适用人员与有效期间。养老、医疗及生育归并口径、失业、工伤、公积金和补充方案由地区配置决定，不照抄全国统一比例或把工伤单位承担写成员工扣款。

参保地及主体可不同于工作门店和支付主体，必须有明确合法业务依据和映射。多公司雇佣不意味着重复参保；系统提示冲突，不能自动多扣。新入职、离职、停缴、转移、调基和跨年度补差形成独立任务与台账，按地方月度规则处理，不能简单按出勤天对所有社保按日折算。[CN03][CN04]

### 10.2 计算与对账

计算记录每险种的基数、比例、个人承担、单位承担、补退差及来源政策。按参保人、账户、主体及供款期间记录本期应扣、已扣和本批应补扣退；同月奖金批次不能再次扣整月供款。个人扣款进入工资；单位承担进入成本；统筹缴款与员工工资不是同一支付任务。社保经办或征收账单导入后，形成应缴与实缴差异，不能因工资扣过就显示机关已收到款。

公积金按缴存主体和城市规则维护个人及单位金额、基数、比例、账户、起缴及转移；相关条例已核对到2026年修订文本，具体城市参数和生效时间仍需版本管理。商业保险另保存投保对象、保单、保费、个人分担、税务属性和起止，不冒充法定社保或MPF。[CN04]

### 10.3 业务成果

提供增减员清单、调基清单、个人及单位应缴明细、补差表、机构账单核对、缴款任务和回执。各项有已准备、待申报、已受理、需更正、已缴款及对账完成等状态。导出标准表和当地适配模板分别标识；没有已授权直连接口时采用文件加回执，不声称自动直报。

## 11 中国内地个人所得税与报税

### 11.1 身份与累计

保存纳税人标识、居民或非居民身份、所得类别、扣缴义务人、税年、适用方法及扣除资料。居民工资薪金按适用累计预扣规则处理；劳务报酬、非居民及特殊待遇有各自方法，不因人员叫兼职就自动改成劳务所得。[CN01]

累计按纳税人、同一扣缴义务人、税年、所得及计税方法建立账。跨门店但同一扣缴义务人的相关收入归并；跨扣缴主体不能把集团所有工资累计混算。减除费用、专项及附加扣除、免税和其他依法扣除有来源，不一律置零；符合简化方法条件时记录资格及确认，不给所有人默认全年一次扣足费用。[CN01][CN05]

### 11.2 计算链与更正

记录本期及累计收入、扣除、应纳税所得、税率、速算扣除、累计应预扣、本期应预扣、已预扣和差额。负累计差额按适用税务处理，不自动当作当月退款。月内多批次按同一税务归属重算合并结果，补发不能重新享受一次完整月度扣除。[CN01]

先计算后续月份可以试算，但前期未定稿或累计基线变更时必须显示影响并阻止未核验锁定。重算从前期到后续检查依赖；历史已经申报或支付的更正另成版本与处理任务，不能只重写工资而不处理下游税表。[CN06]

### 11.3 奖金及特殊项目

季度奖金与一般绩效不自动标成全年一次性奖金。符合规定的全年一次性奖金可按政策选择单独计税或并入综合所得，保存选择、资格、年度使用检查和差异；相关延续政策目前执行至2027年12月31日。该日期之后的计算必须有适用政策版本，不能永久照用。[CN02]

离职补偿、未休假补偿、实物利益、雇主代负税、跨境工作等分别定义项目及核验路径。净额倒推仅在明确项目和承担方式下使用受控求解，显示倒推差异与收敛条件，不能手写循环规避税率。

### 11.4 申报与缴款

税务工作台按扣缴义务人和税款所属期汇总，准备人员信息、收入扣除、税额和适配申报文件，留格式版本及校验报告。工资应扣、实际代扣、申报提交、受理成功、缴款成功和更正分别记录；应扣为零不等于无需报送人员信息。[CN01]

导出文件并不改成已申报，需导入或授权查询正式回执。更正关联原申报批次与原因，标明后续月份累计影响；缴款失败、部分成功、退补或税务机关调整有逐笔结果。员工可查看本人所得及代扣信息，年度汇算提供数据与授权代办支持，不把企业月度扣缴当作已替员工完成年度汇算。[CN06]

## 14 规则变更与跨境边界

内地城市政策、税法方法、香港供款表、法定给薪及工资下限均按生效日期版本化。计算按所属制度和适用时点选择，不能用最新值重写历史，也不能因原表还用旧值就复制为新默认。

双体系启用不认定员工税务居民身份、实际雇主或社保资格；跨境个案记录工作地、工作日、居民及税务资料、供款资格和人工专业核定结果。两体系分别算，必要时关联税额抵免或跨境对账材料；没有完整依据不自动给出跨境最终税务结论。

规则缺失、资格冲突或样表与法规差异进入待处理队列，显示来源和可处理路径。历史源表可以作为对照或外部核定资料保留，法定最低保障由独立规则校验，不能靠姓名硬编码或调税额把每个人实发凑平。

## 15 补发追溯离职及关账

工资批次以人员、具体关系、发薪及扣缴主体、期间、核算类型和来源标识区分。相同事实只能采用一次；不同合法的补发、奖金和离职结算可同月并存，不为补发关闭全部防重。

同一项目追溯先计算旧采用值与新应有值的差额，再决定在哪个支付及税务供款期间办理。追溯可能影响多个月和不同规则版本，明确逐期差额和累计影响。已锁定原工资不可改；可生成差额批次或明确替代重算版本，替代版不再作为额外完整工资累计。

离职结算包含截至离职的工资、假期及加班、已批准奖金、适用补偿及代通知金、供款、税务、借款扣款和待发项目。账务、支付、报税及账号回收分别完成；内地与香港各用自己的项目和规则，不使用同一个全集团离职公式。

方案、工资批次、支付、税务和供款期间分别关账。重开或更正要有权限和审批，展示对工资单、银行、已申报和成本的影响；不能用一个“解锁”按钮抹掉全部外部事实。

## 16 工资发放与银行回单

计算确认后生成支付计划，按币种、发薪主体、银行或渠道分组，核对授权收款账户、金额和人数。付款审批绑定工资及支付计划版本；导出银行文件保存摘要、规范版本及操作人，原计划不可在审批后换账户或改金额。

支付状态包括待审批、待执行、已提交、部分成功、成功、失败、退回和取消。导出或银行接收文件不等于已付款；回单按支付明细匹配，逐人回写。失败重发只重发失败项并关联原支付标识，不能整批再次打款；已成功项不得重复支付。

病假及其他受法定支付时限影响的项目在核算计划中提示到期。HK离港扣款与普通银行失败分别处理。需要直接银行执行时另行接入授权和安全控制；本设计阶段不发真实付款指令。

## 17 工资单发布与员工手机

工资计算确认、工资单发布和银行付款是三个事件。模板按内地及香港体系定义项目分组、显示单位、隐私及双语名称；非现金利益、企业承担与员工实发分开列示。发布时冻结工资和模板版本，可立即或定时，明确哪些项目向员工展示。

员工PC及手机可查看、下载授权本人工资单、确认或提出异议；收到通知、已打开、已下载、已确认和异议处理分别记录。未查看不能自动当签收；修订工资单保留原版、变更理由和重新通知，不能用新PDF替换旧文件而不留痕。

钉钉与飞书共用同一人员绑定、工资单版本、权限和待办，通知链接回本人页面。消息失败不重复发布或改变工资金额，形成待重试任务。批量打包按公司门店和权限生成目录，不能把全店工资单发给一个普通员工。

> 界面设计：手机工资单与确认；公共界面见[总体设计](overall.md)。

## 18 外包代发与供应商资金

企业直营工资、外包服务工时、供应商雇员薪酬和代发服务分别归档。实际雇主与委托方明确；代发不等于劳动关系变更。

供应商账单分别列净薪代发、个人供款、企业供款、税款、保险、服务费和其他费用，与来源工资或供款任务绑定。若已计入员工应发或企业供款，不能在成本或资金汇总再计一遍。供应商共享范围由合同和角色限定，不因能对账而取得集团完整工资及税务资料。

双向确认、争议与更正沿用账单版本机制；真正支付代发资金和员工实际收到款分别留结果，供应商确认账单不等于员工已收款。

## 19 人力成本与财务对账

### 19.1 成本口径

工资成本、个人代扣、企业社保公积金或MPF、保险、外包服务、招聘培训福利等分开映射。实际支付、应计费用、负债及预算是不同口径。源损益表“人件费”包含工资之外项目，系统不能用净薪或工资引擎中的简化企业成本当作全部财务人力成本。

成本按雇主、实际工作门店、部门岗位、档口、成本中心及期间分摊；借调按已核定依据分配，和员工发薪不重复。分摊比例和金额勾稽，差额处理规则可见。跨币种先分别报告，需要集团管理币时保留汇率、日期、原币及折算版本。

### 19.2 成果与接口

输出工资分录建议、应付员工及机构、代扣税、企业承担、成本分摊和实际支付对账。凭证模板按财务科目和公司配置，审核后导出或授权接入，回执失败可重试且防重复入账。人件费预算实际和绩效使用同一指标字典，但财务认列不自动变成绩效成绩。

## 22 数据一致性及技术边界

### 22.1 统一对象

人员、具体关系及主体映射、可用体系、工资组、档案版本、项目规则及依赖图版本、函数和政策表版本、扩展代码与SDK版本、触发器及事件执行、AI工具调用与测试运行、输入来源、计算批次和结果修订、税务累计账、参保及MPF计划、申报批次与回执、支付明细、工资单、成本和审批采用记录分别建模。

地区属性不再承担“该公司只能使用唯一算薪引擎”的全部职责。保留公司经营地区，新增可用体系集合及关系和工资组的适用配置；不能让启用两体系覆盖原地区，更不能靠改region_code把历史工资转换制度。

影子测算读取冻结的累计基线和规则，不写正式税务或供款累计、不入正式成本账。申报计算仅为已有工资事实准备申报资料，不再新增工资应付、付款或成本；正式采用须有对应授权流程。

### 22.2 防重与并发

事实防重采用明确来源及业务键，区分月内常规、奖金、补发及更正，记录替代和差额链。同一应付义务及其已采用金额不能因两个批次或重试重复过账。考勤快照可以合法供基本工资、津贴和补差等多个规则引用，绩效两算法可同时比较；通过选定正式结果、来源分配、累计采用及替代差额链防止重复应付。支付指令及供款同样独立防重。当前代码只按集团月份公司人员判重的限制不能直接当完整产品规格。

输入和方案有修订号，保存和确认核对数据基线；两人同时改工资不能后者静默覆盖。正式确认时复验规则、主体、币种、来源版本及累计链，计算与正式发布采用同一确定性结果。失败不留下部分已付款或半锁定工资；外部回执的真实部分成功按明细保留，不因内部回滚伪造失败。

### 22.3 规则及政策包

每套政策含发布主体、原文、适用日期、参数、计算测试及复核记录。法规更新不能只改一段界面提示；历史与新日期样例均需验证。新数据库变更使用增量迁移；旧工资、税务、供款与新域逐条迁移并对账，不能只把旧页面放进框架证明已统一。
