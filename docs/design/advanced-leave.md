版本V1，2026-11-17。用途：作为天意HR高级假期可开发规格及V17整合依据。本文只写设计和来源摘录，不修改应用、数据库或旧迁移，不生成真实员工记录。中国内地与香港法定资格、期限、给薪及转换细则须接本轮两地官方基线；文中的金额、天数和比例算例均为独立虚构企业规则，不能当法定默认值。

## 1 产品目标与主线

员工可在PC与手机看清“已取得、可使用、待批占用、已批未休、已休、预支、即将到期和已转现金”，提交一次性或周期请假、组合假、补交材料、延期及销假。HR能配置适用规则、资格、授予及有效期，有据调整不确定资料并生成版本；主管按统一流程办理，排班考勤与工资只采用确定版本。

主线为人员真实关系及规则→资格/应得→可用额度批次→申请预占→审批与排班联动→实际休假核定→考勤与工资采用→更正和历史。额度、假期使用、法定给薪、工资确认与银行付款是不同事实。人工可修订事实或经批准权益，不允许通过配置、直接改余额或“特殊审批”取消已确认适用的法定义务。

## 5 界面及角色

一级“排班与考勤”，其中按假期任务设置二级入口：假期工作台、规则方案、资格与应得、额度发放、额度批次、请假与周期假、调休与补偿、结转到期、调整与导入、统计及设置。薪酬统一“来源采用”提供假期/调休/折现筛选；其他模块带相同筛选进入，共用同一采用台账。

PC列表固定筛选、分页20/50/100条、可选列；详情分概览/计算/批次使用/审批/排班考勤/工资/附件审计，避免长页。手机“我的假期”显示可用、待批、已批未休、预支和临期卡；支持分步申请、逐日片段预览、材料补交、销假及异议。管理员规则、大批导入和多维报表优先PC，不以手机简化为无审批。

员工只办本人；主管按当前管理关系及指定实例审批；HR按公司及法域维护资格/发放/核定；薪酬只读待遇所需的已核指标和现金补偿候选。规则编辑、规则发布、批量授予、手工减额、审批、工资采用及解封更正分动作授权。admin管理配置不自动看诊断/子女原件或替人签核；集团HR在已授集团范围穿透，不因永久编号无限开放附件。统一功能、字段、数据、期间及状态权限覆盖搜索、导出、报表和旧通知链接。

## 7 方案配置与生效

规则组包括：适用法域/地区与人群、资格/年资、权益及可用释放、单位和取整、申请限制、证明/补交、周期假、扣减优先级、预支、有效期/结转/延期、现金或调休分配、岗位排班、工资映射、审批及提醒。每字段声明可继承/可增强/需审核，记录上级来源与本地差异；法定底线不能由品牌/门店覆盖降低。

状态：draft→validated→pending_approval→approved_scheduled→effective→superseded/retired。发布冻结规则摘要、合法基线、样例、依赖、范围和起止；适用区间重叠须明确优先级及替代范围，不能最后保存者随机胜出。规则更改先预览未来额度、待批/已批申请、已休和工资，旧权益及已锁工资保留，新配置不就地改旧结果。

允许人工配置“企业优于最低保障”的额度/期限/对象，或修正事实与适用判断。法定规则未核时标待核，安排责任人；可经批准作不损害权益的临时安排或先发已确定工资，不把待核默认0、不自动拒绝受保护休假、不自动清零。人工也不能签一个“豁免”取消已确认适用义务。

## 8 资格、年资及应得计算

分开保存社会累计工作年资、同雇主连续服务、集团承认年资、当前公司任职、法定特定资格、企业试用/正式状态及特定事件。年资必须有来源、起止/断点和核定，不以首次集团入职日替代所有资格。需要子女/医疗等资料时只暴露必要资格结论，附件分权。

给定权益期E、方案版本R和有效服务片段S，先按规则判断`eligible(S,R)`，再查每片段的`annual_or_event_entitlement(S,R)`。只有适用规则明确允许按比例时，才计算`Q_exact=Σ[片段标准额度×该片段合资格日数/对应年度实际日数]`或批准的月/事件比例；法定日历/周年/事件规则分别执行，不统一除365或12。结果分别显示法定应得、合同增强、企业福利、允许使用及尚待取得，不用按月展示隐藏已依法取得的权益。

上式为企业配置通式，**不是内地法定年假新进/终止折算公式**。本轮官方CN02基线明确这两条法定路径分母365，按对应整天规则处理，闰年也不能机械改366。香港共同假期年首期向上整日与离职比例给付是不同分支，不能共用同一个FLOOR/CEILING。正式执行先选法定场景专用算法，企业增强另列，不用通式降低法定结果。

档位、年龄、子女资格或年资期中变化先切片，方案明确观察日制/达到资格即变/按片段比例；未明确则受阻，不用年末档位覆盖全年。零应得、未取得、资料待核、不适用是不同状态。假种无余额时仍要检查资格、申请区间和实际使用，不为其伪造无限额度批次。

## 9 发放、累计取整及重算

一次性、年发、月发、日累计、事件发和手工授予均通过同一授予命令。稳定键为权益根+发放期/事件，不含任务运行时间或导入文件名；重复任务返回原回执。未来应得只显示预计，未到取得/可用日期的批次不进入当前可用。

推荐按**累计应得差额**发放：`C(k)=获准累计取整(Q_exact×合资格累计比例)`，`本期应确认差额=C(k)−此前已确认累计授予`。按日模式用实际合资格日分子、对应计量周期分母；按月模式用批准的月片段。最终年度/事件应得先按适用法定规则核定，再处理业务步长；不能为整齐少给法定权益。负差额进入受控减额/更正，不用删除旧grant或强扣已休权益。

虚构企业规则：年度10天、12等份、累计向下到0.5天。1月累计0.5，2月累计1.5，3月累计2.5，4月累计3，12月累计10；各期差额依次0.5、1、1、0.5…，合计10。旧代码“每月先0.5、12月补4.5”不是默认。发放步长与申请最小步长可以不同；合法不足一个申请单位的尾数保留并按合法政策处理，不静默消灭。

规则重算保存旧目标、现目标、已用/已占用及差额。已取得后需要减少且低于保护/已消费量的，转资格/权益争议核定；不得把差额自动变员工应收或最后工资扣款。

## 10 额度批次与余额守恒

额度须能定位到grant_lot及权益年度，不只按员工+假种SUM。对观察日t及特定休假发生区间，先筛可依法使用且未失效的批次，再按顺序分配。批次余额为：

`可分配=已生效授予+批准增额+合法转入+已核回退−实际已用−待批预占−已批未休占用−现金转换预占−已转换耗用−合法过期/撤销−合法转出`。

已批准未来休假仍占可用，但单列“已批未休”，不显示已经实际休完。法定权益不足与企业批准预支分别记账，不能把负余额当一般多发。预支另存债务量/可抵未来取得量，不改真实已授予总量。

默认扣减策略为适用范围内先临期、再取得时间、最后稳定批次ID；法定/福利先后、指定原加班类型或指定批次由方案及合法边界声明。申请发生日而不是提交日决定批次能否覆盖；跨批次/跨年须分配明细。可用查询返回as_of、规则修订和余额修订，不能用“今天余额”复现去年工资。

## 11 计量及跨夜多班

至少区分：申请日历区间、法定/政策休假日数、排班工作分钟、实际缺勤分钟、额度耗用单位、给薪日/小时及平均工资参数。它们可关联但不强制相等，不全局规定一天=8小时。

小时型假按`M=时长(申请区间∩应工作区间的并集)`计量；应工作区间已扣真实休息后不能再扣一次。多班分别求交再合并不重叠片段；`M/分钟每额度单位`仅在该方案明确的单位换算下使用。半天可定义上午/下午班段、标准日一半或排班工作时长一半，必须选择并展示，不能默认上午全是4小时。

虚构例：10:00–14:00及17:00–21:00，申请13:00–18:00，命中60+60=120分钟；仅在该企业额度日明确480分钟时才耗0.25天。跨夜22:00–次日02:00、次日03:00–07:00，申请23:00–次日04:00，命中180+60=240分钟；休息02:00–03:00不耗工作分钟。跨日/跨月保存同一事实及原工作日归属和各自然日片段，不在两月各扣全量。

按日历连续计算的病假/产假等另有期间资格和给薪规则，不能因为休息日无排班就缩短连续假期事件；是否消耗额度、计薪及证明资格分别交法域规则。没有排班时按已批准日历/无班规则核定或形成暂定影响；不得为接受依法应办的假期而伪造排班，后补班表也不能静默多扣已核额度。

## 12 申请限制、组合假和证明

表单包含真实关系/服务店、假种、一个或多个半开时间段、计算预览、期望使用批次、原因、证明附件/补交期限、紧急标识、交接及联系安排。本人身份从会话取得，代申请保存实际操作者及授权，不接受外部person_number替换本人。

配置最小申请量、步长、单次/周期上限、提前申请、补交期限及证明门槛。病假等连续事件按事件根累计检查，不能拆几张单绕过证明或周期限制。企业规则不能使适用法定假因漏过内部提前时限而永久丧失；紧急申请可按合法流程先受理、后补证，给明确责任人和期限。超过企业业务上限应引导例外申请，不能建议拆单规避法定/证明控制。

证明分未提供、已上传待核、获核、退回补交、豁免有据；文件名/proof_note不等于材料真实有效。附件权限、恶意文件处理、摘要、留存及受控副本引用统一文档管理。证明不齐影响的资格/计薪行须明确；不能一概拦全部工资。组合假一份申请下有多个假种子行，分别资格、额度、给薪和流程；全批或部分生效策略显式选择，不同假种不能把额度随意合池。

## 13 提交审批实际休假与销假

申请版本：draft→submitted/pending→approved_scheduled→partially_taken/taken；拒绝/撤回/取消另存结果。统一流程可配置单审、多步、会签、代理和抄送；流程实例完成不等于业务额度已生效，必须有领域执行回执。

提交事务锁权益范围和必要批次，重验权限、规则/资格/排班/证明、交叠、发生日可用量及修订，创建申请、预占、审批实例/任务和outbox；全部失败回滚。最终审批执行重验相同基线及当前余额，将待批占用转已批未休，生成带版本的排班/考勤影响，不直接改原始打卡。未来发生后按核定或明确规则转实际已休；追溯补录标真实来源和批准时间，不能伪造原时点审批。

撤回未批准释放对应预占；取消未发生已批假释放指定未消费范围并修订未来安排。已经发生或被工资采用的销假/缩短须核实际工作、休假证据、考勤封存及工资影响，走带原行的更正；已休回退必须同事务冲原批次用量，不能先释放额度再等考勤处理。部分销假按片段核量，原批次已过期时不自动变新长期余额，依原权益及合法修订处理。

同一真实时间段不能因两个假种/两份组合单重复解释同一缺勤；同人不同真实关系的休假分别核工作安排和权利，不能仅按person+date简单禁止所有并行假。跨关系日历重叠应提示真实时间安排及适用规则，数据范围不泄露另一品牌细节。

## 14 周期哺乳假及事件型假

周期授权保存开始/结束、每天或每周可用时窗、适用工作日、每天量、资格事件和中断条件。一次审批生成授权，不预造已实际休假；系统按每次工作安排生成可重算的发生候选，稳定键为周期根+发生日期/时窗+真实关系。补班、跨夜、调班、假日或资格变化产生新增/取消差异，不重建已消费历史。

哺乳安排与产假、育儿假、陪护等均有独立假种和资格；不用统一“子女未满某岁”常数套两地全部假。子女/医疗资料未核时进入资格待办。资格终止后的未来安排变更按政策办理，已经合法享受的历史不自动追回或扣工资。

## 15 加班现金调休分配和预支

加班先有V7已核事实及合法加班分类，`H_verified=H_cash_basis+H_comp_basis+H_pending`，基础分钟分配合计不超原可补偿量。加价、夜间额外待遇可另有独立附加项，但不得把同一基础小时既全额发费又全额转调休。是否允许现金/调休选择以及法定不能替代的项目，由实际制度和有效法定规则校验，不预置全日型一律可调休。

虚构企业增强规则：核准120分钟，其中现金60、调休60；调休倍数1.25时生成75分钟额度，消费120中的调休基础仍为60，不再把75当新的实际加班。原加班类型、比例及工资方案冻结。调休到期需转回现金时，生成同一补偿义务下剩余基础量的现金候选，不增加原始打卡或实际加班量；已经转现金的部分不可再休或再补发。

预支必须显式启用并有资格、上限、用途、到期、审批及合法处理方式。授予未取得不能伪造已取得加班。后续真实获得调休先按批准规则清偿预支债务，保留双方来源。离职预支未回补只形成核对事项，不能自动扣末期工资或变私人欠债；适用法律及合同依据另核。

## 16 结转、延期、过期和提醒

批次保存取得日、可用起点、原到期、延期后到期、权益年度、可结转性质及原父批次。结转创建同一权益的接续可用片段并冻结原转出，不复制为另一全额权益；累计净转入=净转出，原年度及工资补偿历史可追溯。法定与企业福利分别核范围，不能全局默认次年3月31日作废或只看今年余额。

延期由本人/主管/HR申请，保存原因、范围、新期限、合法依据、审批及影响；不能把已兑付/已用量延长再发。到期任务先检查当前规则、延期、待批/已批预约和已采用现金状态。对发生日在有效期内的获批预约保留其分配或按明确规则办理，不因审批跨到期夜间任务抢跑清掉。

到期处理可为提醒待办、依法关闭可用、允许结转、经核转换现金或回原加班补偿；每种需权威规则。到期不自动等于权利消灭；法律/事实未核或企业未依法安排的权益列待处理负债/风险，不以“清零”绿灯隐藏。权益减少追加有效记账及依据，不删授予。通知及已读不构成本人同意放弃权利。

提醒按权益根+到期修订+窗口+责任人去重，区分待处理、发送、已读、实际办理。延期后旧定时任务失效；责任人离职转派，过期未办持续升级。站内、钉钉、飞书、企微沿V10统一消息能力，未连接渠道显示未配置/待发送，不假送达。

## 17 入职离职调动复聘与多关系

首次入职先核实际资格与年度/周年基线，已在别单位取得的适用资格或已享权益有据登记。复聘复用永久人，但真实关系、法定连续性及集团承认年资分开核；不能固定“3个月内一律连续”，也不能复聘重新授全年后再扣已享。

同实际雇主换店且权利连续时继续原权益根，通过公司经历/成本片段展示，不释放再发全年。跨实际雇主须依法核旧关系结清及新资格，不能默认把旧债/余额移给新雇主。集团福利在同一共享范围内按政策可跨品牌用，但所有门店共用一份权益余额。临时支援不造入职或重置年资；两份真实独立雇佣各自合法权益保留。

离职先处理未来申请、实际已休、已批未休、预支、结转及法定应付补偿，生成逐项处置清单。合法应现金补偿的形成V8候选及稳定义务；不可转现金的依据和剩余处置留痕。不能把“其他假一律作废”当默认，也不能因还有权益争议删除真实离职或拖欠确定工资。解除/重开须核旧补偿/支付结果，未执行可撤对应意图，已锁/已付净补差。

内地法定年假终止折算出现已安排多于应折算量时，按本轮CN02基线不自动追回；不能由负差额直接生成工资扣项。合同/福利预支与该法定事实分开，不借企业“预支追还”配置规避此保护。

## 18 CN与HK日历及给薪分离

日历分别记录地区、时区、日型、法定假/公众假/企业假、调班工作日、休息日、年度规范及修订。香港公众假日与适用法定假日不能仅共用一个holiday布尔；内地特殊补班与门店实际排班也分开。公司可启用两薪酬体系，不表示同一人的假期权利自动取得两份或由品牌名决定法域。

法域基线按实际关系、工作地区和适用事实引用官方版本；CN年假、医疗期、产育等与HK年假、病假累积、产侍假、连续性及平均工资各有策略。假期模块输出资格、核定单位、日期和版本，V8计算对应给薪、税社保/MPF及最低保障。不能把香港全部有薪假固定80%，或把内地统一日薪分母套所有香港给薪；旧样表仅作结构参考。

已接收并定向核对本轮两地官方基线（本地参考资料），其CN01–CN10、HK01–HK12精确链接作为规则包依据，不能只做自由填数界面。必须至少实现以下独立分支：

- 内地连续工作资格与累计工作档位、365新进/终止折算、法定日及休息日排除、正常工资已含与额外未休报酬分解；当期多休不自动追扣。
- 内地病假给薪和医疗期保护分离；地区未知不套上海模板。法定加班日型不能全用调休抵掉；地方婚育护理等待地区核定而非默认0。
- 香港连续性按同一真实雇主、周和有效版本认定；2026新门槛与旧418分版本，依法/双方同意缺勤认定小时不直接等于打卡小时。
- 香港休息日、法定假日、另定及代替假日分别保留义务与履行日，不能付钱就销掉必须休的假日。
- 香港连续年假遇休息日/法定假日，按官方HK06输出年假消费和另补休息/假日义务；不能照内地“直接不计入”算法，也不能漏掉补休义务。
- 香港疾病日先/二类批次及使用次序分开，事件连续性、津贴资格、证明和适用排除分别核；不够给薪资格不直接改旷工。产/侍产的可休与给薪资格同样分开。
- 香港ADW按具体待遇指定日期确定工资窗口，排除日和对应工资成对剔除。分母≤0、缺工资或缺证明转人工核定/外部获核基线，不返回0；月薪已含假薪时只做合法替换/补差。
- 香港在职以款代年假、年终/终止结算及共同年度首期均调用各自条件与算法，不把“全部可折现”和统一取整开放为无守卫开关。

## 19 人工认定和调整

人工能力包括补录有效年资/资格、设企业增强政策、补发或冲回错误额度、批次延期、申请时间核定、销假、调休用途更正及导入期初。每次必须明确调整对象、观察日、前后值、单位、依据/附件、原因、发起/复核、有效日、影响、当前基线和修订；重大减额/追溯与自我受益配置禁止自审，职责可配但不能无痕直接改余额。

提供两类动作：`append_delta`（增减Δ），`target_available`（将某范围当前可用调至T）。后者在预演计算`Δ=T−可用基线`，提交时锁当前权益/批次及占用并复验基线；若有人新请假导致余额变化，拒绝旧预演重做。T是可用余额、授予总额或期初余额必须三选一，不允许一个“覆盖”按钮混用。

例：当前可用12，增量+3后15；目标可用15时差额+3。若授予12已用5，则可用7；目标可用15需增8，不是填15当新的授予总额后变10。减额不得吞没法定保护、已消费或执行未知量；转争议/更正而不把系统变负后自动追工资。补录诊断/签名必须如实标历史人工来源，不能伪造医生、本人确认或外部审批。

## 20 导入与迁移

模板分假种/方案、资格年资、期初分批额度、增量调整、目标可用、历史申请与已休、原加班调休、现金已结及来源映射。每行有集团/稳定人号、真实关系选择器、权益根/批次或外部行键、假种、单位、权益年及有效区间、来源状态；合法的无日明细历史基线可导入但标明粒度，不伪造原卡或逐日休假。

预检展示映射、单位转换、前后余额、重复、资格缺口、已用/已付、缺列和权限差异。缺列不清空；文件指令、公式、宏和PDF文字不执行。覆盖模式仅生成差额，原台账仍保存。相同外部真实权益的文件换名或行号变化需别名对账，不按新文件名重授。

提交按可原子办理的人员/权益依赖组执行，重验预检修订与余额；失败组不留半张申请，成功组不因重跑重复发放。导入成功/部分受阻/待核分别统计，附件或资格不足不显示全量完成。旧库迁移先核单位“天”、归属关系、已批/已休/冻结/折现、往年及已付，再锁旧写路径并对账，不把一张聚合余额强猜成各有效期明细。

## 21 薪酬采用和共同防重

向V16统一采用中心输出两类来源：一是休假/给薪计量及资格（由V7日月报采用），二是现金补偿/调休转费/手工获批差额（按稳定义务映射V8/V16预置项目）。同一假期事实的给薪解释可分多项目，但已含月薪与额外补足须明确，不能正常工资加全额假薪；未提供劳动依法减发是应发减发，不在净薪重复扣。

现金候选保存权益/加班父根、已核量、法定/合同依据、工资关系/法定组件责任、主体、币种、计价规则、工资项及所属/支付期。采用预演不造应付；审批与正式执行分开，执行锁父义务、源修订、目标工资基线及累计已采用/占用，创建唯一采用及输入/outbox。两体系/拆批/重导/转店不改变原经济事项身份。

额度转换先预占，只有权威采用/工资确认到达配置的确定阶段才完成不可再次使用的耗用；银行付款另有状态，失败不恢复同一假期再兑一次。撤回工资须依原回执原子冲回或受控更正；执行未知先对账，不能先还额度再改渠道。更正采用按`新获批累计应得−此前累计有效采用/更正`计算净差，已封存工资不随规则或请假更正静默变化。

老板成本只取V8正式工资/补偿及实际企业承担成本原子。假期天数、额度、现金义务余额、预占和转账资金不能全部各加一遍成本；跨店分摊不新增工资，香港非现金/平均工资基数不现金发放。

| leave.approval_effect | 权威审批实例、批准快照及当前源/余额/排班 | 待批转已批占用、未来考勤/排班影响；申请+批准修订+generation |

| leave.cancel_correct | 原分配、实际发生/工资状态、批准更正和逆向范围 | 精确释放或签名回退+新核勤/工资影响；原业务行+更正修订 |

| quota.carry_extend_expire | 原权益/批次、延期/预约/现金状态、适用规则 | 同根接续/合法减额及提醒，不重复出入；批次+处理种类+到期修订 |

服务端任何submit/effect/导入/脚本路径必须执行同一领域守卫；预检、界面隐藏按钮、备注文本不能替代。业务事务与outbox原子提交；消费者按业务版本/代次去重，失败/未知有核查与责任人。采用统一错误码：规则失效、资格待核、单位错误、证明待补、时间冲突、批次不足、基线变化、权益受保护、来源已采用及执行未知，错误不泄露他公司个人资料。

## 23 必须通过的具体边界

| 编号 | 场景及预期 |
|---|---|
| L01 | 同人两真实雇佣、同雇主跨店及集团共享福利各一例：权益范围不同，换店不重新发同份全年 |
| L02 | 日历年/周年、闰年、月中入职/离职及资格期中跨档：按适用分段与分母复现，不统一365或12 |
| L03 | 虚构10天累计0.5步长：1/2/3/4月累计0.5/1.5/2.5/3、年末10，重跑不删旧用量、不翻倍 |
| L04 | 原12→增量3=15；授予12用5时目标可用15→差额8；含预占且基线变动时拒旧批准 |
| L05 | 10–14、17–21请13–18=120分钟；跨夜22–02、03–07请23–04=240，不扣休息、不首尾相减 |
| L06 | 同一天半天窗口3小时与按排班一半4小时的方案分别预览，不能同名默认全按4小时 |
| L07 | 待批预占、已批未休、实际已休、现金预占分列；两并发申请合计不可超过有效范围余额 |
| L08 | 病假连续事件拆单仍核累计材料要求；紧急合法补交路径可受理，不把内部超时当永久失权 |
| L09 | API直接提交绕过前端check仍强制最大时长、资格、有效假种及证明守卫 |
| L10 | 跨年多个有效期，按发生日期及扣减顺序逐批次分配；过期批次不被任意转当前长期量 |
| L11 | 已批有效期内休假跨到期任务运行，处理既有预约；延期后旧过期任务不得冲掉新期限 |
| L12 | 取消未来2小时只释放对应批次2小时；实际已休或工资已封存走原行更正，不删单返全额 |
| L13 | 哺乳周期一次审批，多日发生根稳定；换班/节假日重算不复制已休且保留资格及修订 |
| L14 | 已核120分钟分现金60+调休基础60，虚构1.25转75分钟；总基础仍120，不再发完整现金120 |
| L15 | 调休预支、后续取得归还、离职未补三场景，不伪造加班、不自动扣末期工资 |
| L16 | 到期转现金使用原补偿来源及剩余量；已采用/未知时不能同时恢复额度或改渠道重兑 |
| L17 | CN/HK假日、给薪和假期日单位分别核；双体系公司不多发同一权益，假期事实与工资规则各可穿透 |
| L18 | 资格/年资待核与N/A/0分开；有权人工补依据并重算，不能人工把适用法定底线设0 |
| L19 | 复聘不默认三个月连续、不无依据重发全年；同人前次已享和旧现金结算保留 |
| L20 | 规则修改/手工减额影响已用或已付：保留原账、受保护及未知量，明确争议/净补差，不隐式造债 |
| L21 | 同一外部权益换文件/映射/导入批次仍同根；缺列不清空，失败组续跑不重做成功组 |
| L22 | 工资引用已含月薪假期不再全加一次；应发减发不在净薪再扣；银行失败不再扣同份额度 |
| L23 | 本人、主管、品牌HR、薪酬、admin分别搜索/看附件/导出/用旧链接，菜单字段数据期间同一权限 |
| L24 | 无人审批、规则缺失、附件失败、导入失败、外部平台断联及消息失败均有待办；不能假成功或无故停已确定工资 |
