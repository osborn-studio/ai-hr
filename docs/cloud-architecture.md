# 天意HR运行与数据架构

正式应用采用 React 构建产物、一个 Node HTTP 服务和一个部署数据库。Node 同源提供网页与领域 REST 接口，不需要生产 Vite 进程。PostgreSQL 为正式持久化基线；Broker 是需通过契约验证的替代接入方式。当前代码与验证状态见[开发进度](development-status.md)，安装步骤见[部署与初始化](deployment.md)。

## 部署边界

`code/app/cloud-server.mjs` 是标准入口。缺少明确数据模式或连接时启动失败；它核对数据库全部迁移文件及 SHA256，遇到缺失、未知迁移或哈希变化时停止。静态资源由同一进程托管，资源缺失与 API 错误不会返回成功的首页 HTML。

`TYHR_DATA_MODE=postgres` 使用 `DATABASE_URL`。`broker` 模式使用服务端能力、查询和命令端点，不同时连接本地数据库。`pglite_demo` 只用于显式隔离演示，生产模式禁止。旧 `CONTROL_URL` 物理分库模式不用于标准云端部署。

标准云端使用带版本的领域接口、当前用户会话及统一基础目录。个人账号、口令与会话操作有独立入口。旧独立页面和旧业务 URL 仅保留在明确的历史验证入口，标准云端关闭这些路径，原工资书签回到当前核算首页，不把旧记录号当作新记录号。

## 统一组织与永久人员

一个部署数据库可保存多个逻辑帐套。集团帐下建立品牌公司和门店，各层可有部门与岗位；门店是独立经营核算主体。实际法律雇主、发薪、税务、供款、工作地点和成本承担分开记录。

永久人员编号在同集团内贯通；雇佣、任职、借调和供应商派驻保留各自期间与历史。无关联客户之间保持隔离，不按姓名合并人员，不因外部通讯录同步自动建立雇佣。

## 领域命令与查询

浏览器调用 `/api/v2/query/<名称>` 和 `/api/v2/command/<名称>`。服务端从真实会话确定操作者，拒绝请求替换身份。命令使用稳定操作号；同号同参数可核对原结果，同号异参数冲突。浏览器不取得数据库密钥，也不提交任意 SQL。

每个命令在同一事务、同一连接核验功能、数据、字段、状态、版本、余额及来源，写入业务审计和待投递事件后提交。外部 HTTP 不在业务事务中发送。功能、数据范围和字段必须由同一完整授权满足，查询、统计、导出、附件和 AI 接口沿用该边界。

工资以真实关系、已核规则和来源版本建立经济义务、采用行及工资项目。新版本按累计目标与已确认金额计算净差；旧确认工资保留。币种分别汇总，工资确认、资金预占、银行受理、实际到账及申报状态分开。

## 后台任务与外部连接

学习期限、集成、公式预演、招聘等后台任务由同一 Node 进程管理。可恢复任务保存在数据库中，通过状态、租约及来源版本核对重试。进程退出时停止领取任务并释放资源；未知外部结果保留待核，不按失败重发。

集成配置、加密凭据、组织人员对照、来源预检、实际投递和回执分开保存。当前授权、永久人员映射和来源在网络前后重核。企业 SSO 使用明确允许的回跳源及已核平台身份，不自动授予业务权限。电子签外网任务默认关闭，显式启用后仍需完整配置与当前审批。

敏感附件和外部凭据使用服务端密钥加密。密钥与数据库备份一起规划保管；数据库恢复不代表密钥可以丢弃。标准演示使用编写场景，不生成外部签署、已读或真实付款事实。

## PostgreSQL与Broker适配

所需数据库语义包括 PL/pgSQL、`btree_gist`、排他约束、JSONB、精确数值、日期区间、临时表、锁和同连接事务。仅有 SQL 查询 REST 接口不足以证明兼容。

Broker 实现领域级 `queryView` 和 `executeCommand`，必须在服务端保持事务原子性、当前授权、幂等查询与未知结果核对。多个逐行 HTTP 请求不能替代工资或假期的业务事务。文件、回调和定时任务也需要各自明确的运行能力。

千问、钉钉或其他云端是否提供这些数据库语义、回调及后台运行能力，须在目标环境实际验证。仓库提供接入契约与隔离验证，不把本地通过等同于目标平台已经上线。初始只读架构审查保留在 Git 历史和本地归档，当前说明以本页为准。
