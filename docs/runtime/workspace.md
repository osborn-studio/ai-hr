# 天意人力资源系统：新版工作台与测试帐套

本版本面向餐饮多品牌、多门店的本地 B/S 部署。英文名称为 `ty-hr`。新版入口为 `/workspace`；已有业务功能继续保留。

测试组织使用用户指定的“天意集团”，旗下“香香鱼米”和“大富烤肉”各10家门店。大富烤肉10家门店全部配置为香港（HK、HKD）；香香鱼米采用内地（CN、CNY）测试配置。总部使用独立集团帐套。工资批次和考核周期按地区币种分别核算，不将港元与人民币直接相加。全部人员、编号、任职、考勤输入、工资和绩效金额独立虚构。来源材料只用于理解格式和业务关系，不自动导入客户真实记录。

## 组织与人员

门店是经营核算公司，公司内部设置部门。档口可以承接一个部门的职责，也可以是部门内的工作区域。集团标准岗位、职级和具体公司的岗位设置分别维护。

集团永久人员编号保持不变。入职、离职和重聘形成不同雇佣段，岗位及部门归属形成有起止日的任职记录。雇佣离职日包含当天；任职失效日是不再任职的第一天。跨品牌、跨帐套履历依账号授权展示。

新基础与原业务采用显式映射。业务接续页选择经营公司、旧业务适配节点及发薪/社保主体，先预览再接续。适配节点仅用于原代码运行，不会变成新公司内部的部门。并行雇佣不能无损映射到原来按人员管理的模块时，会明确阻断。基础资料授权不会自动扩大原工资或考勤权限。

## 进入测试

1. 启动本地服务，进入 `/workspace`，使用本地初始化生成的账号登录。
2. 管理员在工作台选择“建立完整测试帐套”，选择初始绩效算法。
3. 系统建立天意集团、双品牌20家门店及1家集团总部、62位虚构人员、三个帐套和内部组织。工资与绩效按CN/CNY、HK/HKD分组。重复点击会复用已建帐套，不覆盖修改过的记录。
4. 在集团选择器切换到天意集团。可以先查看人员跨品牌经历，再进入薪酬核算或绩效考核。

所有菜单采用分组展开；长表支持搜索和分页，业务页按任务分区。原系统36个业务页均有入口，培训页可选择获授权的发薪主体，包含题库、试卷、作答和结果；参训人员、场次与累计学时按业务日权限展示，组织页保留树形图、关系网、清单及岗位视图。

## 工资核算

工资批次区分历史金额快照与规则计算。历史快照保留收入、业务扣款、员工承担和企业承担，逐项对账；新月份从输入和选定规则版本计算，原始数据与修改后的输入分别保存。

可选择固定月薪、日历天折算、约定工作日折算或时薪方案，并配置适用项目。规则使用受限表达式：四则运算、比较、`IF`、`MIN`、`MAX`、`ROUND`、`AND`、`OR`，不执行任意程序。启用规则是系统内的版本操作，使用者可自行选择配置，不依赖外部客户确认。

源字段与修改字段可以逐项核验；仅对所选公式实际读取的必要字段检查。空值与零、资格未明确与资格为否分别保存。法定项目按地区和资格输入处理，不把香港工资套入内地个税算法。

操作顺序为：导入或粘贴输入 → 明确人员、门店与雇佣 → 选择规则 → 编辑和核验输入 → 接收已确认绩效 → 试算与对账 → 锁定结果 → 导出工资表或打印工资单。锁定不代表付款，系统不会据此生成银行付款事实。

重复来源文件会被识别，同期同公司同人重复过账由数据库阻止。当前更正或补发需要独立、明确的业务设计，不能通过重复导入普通工资批次完成。

## 绩效方案选择

绩效周期分别保存门店月度指标、员工月度考核归属/职级以及管理者责任范围。管理者责任范围不会扩大其工资查看权限。

同一个周期可以选择以下聚合策略：

| 策略 | 计算顺序 |
|---|---|
| 逐月奖金平均 | 每月按当月归属、职级和等级计算奖金，再平均取整 |
| 平均达成度与末月职级 | 先平均月度达成度，再使用末月职级/基准和等级计算 |

界面同时显示两种结果及差异。使用者选择启用策略后重新计算，结果版本随之变化；确认时锁定本版本。未选定、输入不完整或存在源错误的结果保留具体原因，不自动补零。其他品牌、月份和个人基准可以配置独立参数。

确认奖金按稳定来源键进入工资输入，重复操作不会重复加奖。系统检查人员、雇佣、公司、工资月、币种和结果版本。两套方案的对照结果不会同时自动进入工资。

## 香港工资工具

大富烤肉全部门店使用香港地区和港元。香港工资可配置月薪/时薪及MPF项目；MPF资格为明确输入，空值不能被当成不需供款。香港主体在原内地工资和个税入口会被阻止，进入新版工资规则页核算。

“香港工资工具”提供连续工时条件与平均日薪的独立试算。工时按同一雇主的连续七天周期输入，经核验后按适用日期检查每周17小时或连续四周68小时条件；历史规则单独区分。结果仅判断工时条件，不自动认定完整法律资格，缺少前序周数据时显示未能判断。

平均日薪以指定日期前12个完整日历月为期间；短于12个月的任职按已服务期间处理。工资与排除日的对应工资一起排除，工资取MPF扣除前金额。缺月、重复月或未核验输入不出正式平均数。工具同时显示计算分子、分母与来源；具体假期资格及天数仍需明确输入。

规则来源：香港劳工处的[连续性合约说明](https://www.labour.gov.hk/eng/labour/Continuous_Contract_EduTool.htm)、[平均工资计算工具](https://www.labour.gov.hk/eng/labour/avgMonthSalaryCalculator.htm)、[假日工资问答](https://www.labour.gov.hk/eng/faq/cap57g_whole.htm)及积金局的[雇员强制性供款说明](https://www.mpfa.org.hk/en/mpf-system/mandatory-contributions/employees)。当前默认MPF项目是普通月薪雇员例子，不替代饮食业临时雇员等不同计划配置。

## 花名册与数据导入

基础资料导入支持具名工作表“花名册”的预检、公司显式映射和提交。可下载纯虚构示例模板。来源编号以文本保存，保留前导零；姓名和报表序号不能自动充当跨文件人员主键。

来源岗位标签保留在来源记录中。缺少部门、岗位设置或历史日期时，不制造任职及既往雇佣。总部部门不会因列名为“部门”就被自动建立为经营公司。相同集团、相同文件哈希跨帐套也不会重复建人。

## 代码与部署

- `code/db/193`起为新版基础、治理、业务接续、薪酬、绩效及导入的增量迁移。
- `code/app/workspace.*`为外壳，`customer-workbench.mjs`为薪酬/绩效操作页。
- `foundation*.mjs`与`test-workspace.mjs`处理基础、映射和全虚构初始化。
- `customer-payroll*.mjs`、`customer-performance*.mjs`处理业务和来源预检。

新空库初始化会逐迁移记录文件及SHA256。已有库只提示缺失，不猜测或自动接纳历史。可信账本的数据库先备份，再用 `DATABASE_URL=... node tools/migrate-checked.mjs --only 200,201,202,203,204` 显式前滚；编号须与实际缺失迁移一致。已应用的迁移不可修改。

初始化管理员：明确指定 `DATABASE_URL` 或 `PGLITE_DATA_DIR`，运行 `node tools/init-workspace.mjs`。随机口令仅写入 `TYHR_RUNTIME_DIR/workspace-access.json`，不打印口令、不进入仓库。`--demo`仅用于旧开发小样本。干净测试库设置 `SEED_SKIP=1`，再运行 `node tools/init-test-workspace.mjs --confirm-synthetic`，或在工作台建立完整测试帐套。完整测试帐套只为其自身新建的虚构组织及主体建立旧业务授权范围，便于原排班、假期和培训模块使用；不会把其他组织加入范围。

验证以本次实际测试日志为准。完整虚构业务通过不等于真实客户制度已配置、真实工资已核验或生产验收完成。
